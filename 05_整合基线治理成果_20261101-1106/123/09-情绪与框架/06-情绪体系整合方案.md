# R3 情绪体系整合方案：状态机 × 记忆元数据

- 版本：Integration Proposal 1.0 — **待审批（Pending Approval）**
- 性质：架构整合决策提案。**不是**对既有两份文档任何一方的替代；批准后按 §六 清单落入 m0X 文档。
- 整合对象：
  - **A 方案** = `05-情绪系统设计提案.md`（元数据标注：affect_* 字段 + EmotionBoost 排序加权）
  - **B 方案** = `05-心理机制管线/PSYCH-PIPELINE.md`（状态机：P/A/D/E/L 五数值 + 检索七步 + 注意力 + 顶点记账）
- 判定事实：两者是**同一问题的时空互补**，不是竞争方案。B 的检索七步包含并超过 A 的 EmotionBoost；B 的分变量衰减优于 A 的单一 DecayPolicy；但 B 管的是"现在"（当前状态），**它自己的待办清单（§十三）写明"建表 + 回填 valence：需要你的真实数据"、"reinforce() 需要调用方写回"——恰好就是 A 方案定义的 M01 存储字段与 M04 反馈回路**。
- 整合原则：**B 管"现在"，A 管"过去"；状态机为大脑，记忆字段为沉淀；接口对齐，各自保留拔除路径。**

---

## 〇、结论摘要

1. **两者不是二选一**。B 方案缺的正是 A 方案设计的：记忆侧 valence 持久化（建表回填）、强化写回（reinforce 闭环）——这两项分别是 A 的 §2.1 与 §2.2。A 方案缺的正是 B 已实现的：状态机、七步检索、注意力容量。**互补面超过重叠面。**
2. **重叠面只有一处需要裁决**：检索加成。A 的 EmotionBoost（±10% 乘性）与 B 的情绪一致性评分（七步之三）是两个不同强度的机制，**不可叠加使用**（会双重计权）。本方案裁决：**用 B 的七步链替代 A 的 EmotionBoost**——因为 B 的链路经过压测且语义更丰富（同向加分/反向减分/侧抑制/容量选材），A 的 ±10% 设计降级为 B 链路里"情绪一致性"步骤的**护栏参数**。
3. **A 方案中被 B 取代的部分**：EmotionBoost（#16）不再作为独立决策点；A 的检索加权章节（§4.1/4.2/4.4）整体由 B 的七步链承接。**A 方案中依然成立且不可替代的部分**：M01 存储字段（含反馈回路三字段）、M03 写时标注（成为 B 的 valence 回填数据源）、全部红线（P1–P7）与权限边界。
4. **B 方案的落位**：作为一个**新的可插拔组件槽位**接入 R3（"心理状态机"槽位，插拔清单第 17 号），状态持久化在独立文件（`psy-state.json`，类比 social-v2 的会话态），**不进权威库、不进 R3 五模块的职责范围**——它是 M02 检索与 Bridge 组装层的协作组件，不是第六个模块。
5. **最大风险如实声明**：B 方案自认"所有测试都是构造的，没有真实对话语料"（§十三）。整合后必须先影子运行（只记录不生效），用真实 QQ 对话验证抽取器判准率，达标后才允许影响检索。

**分工一览**：

| 层 | 谁管 | 管什么 | 状态载体 |
|---|---|---|---|
| **现在**（本次对话） | B 状态机 | 当前情绪/心境/精力/负荷 → 注意力 → 本次检索的七步评分 → 表达修饰与温度 | `psy-state.json`（会话级，非权威） |
| **过去**（长期记忆） | A 方案字段 | 每条记忆沉淀的效价/强度/标签 → 七步链的情绪一致性与分变量衰减的数据源 | `memory.sqlite` affect_* 字段（权威） |
| **反馈**（越用越准） | A 方案记账 | last_retrieved/confirmed/reinforce → B 的 `reinforce()` 闭环 + 分变量衰减的刷新 | memory.sqlite 反馈字段（权威） |

**为什么"现在"不放权威库**：B 的状态是**会话级、高频写、可丢失可重置**的运行时状态（每分钟 tick），放 `memory.sqlite` 会造成写放大并污染权威数据的备份节奏。这与 R3 既有先例一致——SocialV2 会话态留在 Bridge（报告3 P6）、Recall Cache 独立为 `cache.sqlite`。心理状态是第三种"运行时态"，同理独立。

## 二、重叠裁决：检索加成归 B 七步链

### 2.1 为什么不能叠加

- A 的 EmotionBoost：`1 + 0.1·intensity·valence_sign`（±10% 乘性护栏）
- B 的情绪一致性：七步链中独立一步，同向加分、反向减分，且有侧抑制与容量选材配合
- 若叠加：同一情绪信号在检索链中被计权两次，且 A 的护栏（±10%）会被 B 的链路输出突破，护栏失效。

### 2.2 裁决

| 项 | 结果 |
|---|---|
| **检索排序机制** | **采用 B 的七步链**（§六），作为 M02 排序的**可插拔实现之一**（FusionStrategy/Reranker 的组合升级，插拔清单已有接口位） |
| **A 的 EmotionBoost** | **撤销**独立决策点资格；其 ±10% 护栏语义转为 B 链路"情绪一致性"步骤的**上限参数**（防止 B 的情绪权重失控压过相关性——与 A 原设计的保护意图一致） |
| **A 的 DecayPolicy** | 保留接口位（框架优化文档第 6 号），但第一实现改为 **B 的分变量衰减**（detail/affect/meaning 三半衰期）——A 提案 §4.4 的"三维 DecayPolicy"由 B 实现承接 |
| **A 的标签过滤** | **保留**（affect_labels 的结构化过滤与 B 七步链不重叠——过滤是"进不进候选池"，七步是"池内怎么排"） |
| **A 的 EmotionExtractor** | **保留且升级地位**：它产出写时标注（affect_*），正是 B 状态机"建表 + 回填 valence"待办的数据来源；V2 LLM 标注照旧可选 |

### 2.3 七步链与 R3 既有机制的对接点

| B 的步骤 | R3 对应机制 | 整合说明 |
|---|---|---|
| ① 分变量衰减 | M02 D23 `DecayPolicy` 接口 | 三半衰期实现作为 DecayPolicy 的第一实现；**历史查询调低时间因素**（D23 既有语义）保留 |
| ② 干扰（bigram 倒排） | M02 D13 去重、M01 D20 过滤元数据 | 干扰是**池内互压**，与 D13 的跨渠道去重不冲突；bigram 索引可复用 P4（人格管线）已实测的切分函数 |
| ③ 情绪一致性 | （替代 A 的 EmotionBoost） | 读取 memory 行 affect_valence 与状态机当前 P 的同向/反向；**±10% 护栏参数在此生效** |
| ④ 激活扩散（一轮不迭代） | M02 D5 关系扩展（L0/L1/L2）、M04 `listNeighbors` | B 的一轮扩散对应 M02 的 **L1 一跳**；多跳（L2）仍归 M02 遍历控制——**遍历与预算归属裁决（前轮 P1-1）不变** |
| ⑤ 侧抑制 | M02 D22 多样性控制 | 侧抑制是 D22"相同事件合并、避免重复占位"的计算化实现 |
| ⑥ 去重 | M02 D13 | 同 ② |
| ⑦ 按容量选 + 反向保底 | M02 D7 动态预算 | **容量 = mind 的注意力输出**（B §5.1），把 D7 的"根据当前问题复杂程度动态分配"升级为"根据此刻认知容量动态分配"；**反向保底槽位**（极端负面时强制一条正向记忆）作为新增规则进 M02 D22 |

**关键不变量（M02 主权不动摇）**：七步链是 M02 排序的**实现**，不是 M02 的替代。遍历控制、预算持有、权限判权时机（M05 §10.4）、去重语义归属全部维持既有裁决——B 组件无权越过 M02 直接改检索行为。

## 三、数据契约：两个方向的对齐

### 3.1 状态机 → 检索（读 R3 数据）

| B 需要读 | R3 提供方 | 契约 |
|---|---|---|
| 候选集 | M02 渠道检索产出 | 按 M02 既有接口，B 不自行访问 M01 |
| 每条候选的 valence/intensity | memory 行 `affect_valence` / `affect_intensity` | A 方案 §2.1 字段；B 的 memory.mjs valence 语义与 A 的 [-1,1] 定义一致（同一 PAD 源流），**直接映射，无需换算** |
| 每条候选的衰减输入 | `last_retrieved_at` 等反馈三字段 + `affect_updated_at` | A 方案 §2.1/2.2；B 分变量衰减据此计算 detail/affect/meaning 保真度 |
| 内容文本（bigram 干扰） | memory 正文（经 M01 读接口） | B 的倒排索引按候选集构建（每次检索现场），不持久化、不建旁路库——**避免与 P4 人格管线的 L1 FTS 重复建设** |
| 记忆 importance | M03 评分总分（M03 §6） | B 的 importance 语义与 M03 五维总分同源映射 |

### 3.2 检索/对话 → 状态机（写回状态）

| 事件 | 写回动作 | 对应 B 的待办 |
|---|---|---|
| 用户确认/延续/重复提及 | `mind.reinforce(memoryId)` → 状态机内该记忆激活度提升 | **B §十三"再巩固闭环已实现未接"——由 A 的反馈记账接通** |
| Recall 命中 | 异步记账 `last_retrieved_at`（A §2.2）+ 触发 B 内部记忆激活 | 同上 |
| 每条 QQ 消息 | `mind.say(text)` → 事件抽取（纯规则） | B 已实现（6.5μs） |
| 时间流逝 | `mind.tick(minutes)` | B 已实现 |

### 3.3 状态持久化契约

```text
psy-state.json（会话级，Bridge 侧或独立于权威库的运行时目录）
  { pad: {...}, energy: {...}, load: {...}, peak: {...},
    trait: {...}, trust: {...}, savedAt, schemaVersion }
```

- 快照/恢复语义沿用 B 的 backup.mjs（往返无漂移已压测）；
- **不参与 M01 备份**（非权威数据，同 Recall Cache 定位）；损坏时重置为中性初值，不阻塞聊天（降级路径见 §五）；
- 多会话：每 conversation_key 一份状态（与 SocialV2 同粒度），或按用户主体聚合——**列入裁决 J-3**。

## 五、B 方案的接入形态与护栏

### 5.1 槽位定义（插拔清单第 17 号）

```text
组件名   : PsyStateEngine（心理状态机）
级别     : L2 可整体拆除（状态文件可丢弃重置，权威数据零依赖）
接口     : mind.say / mind.tick / mind.hint / mind.temperature / mind.reinforce
状态载体 : psy-state.json（会话级，非权威）
读 R3    : 仅经 M02 检索接口与 M01 读接口（禁止直连 SQLite——与 M02 不直连存储的同一纪律）
写 R3    : 无（状态机不回写任何权威字段；reinforce 只改自身内部激活度）
降级路径 : 状态文件缺失/损坏 → 重置中性 → 检索退化为"衰减+去重"六步（无情绪一致性）→ 聊天不受影响
关闭路径 : 配置关闭 → M02 回退 A 方案的 EmotionBoost 简易加权（作为 fallback 保留实现）或纯 RRF
```

### 5.2 三条硬护栏（沿用 A 方案红线，扩展到状态机）

| # | 护栏 | 说明 |
|---|---|---|
| G1 | **情绪只修饰表达与排序，不覆盖人格与事实** | B §八"输出修饰语不输出身份语"直接继承；R3 侧补充：mind.hint() 输出**禁止**进入 system 层人格段（人格管线方案已裁定框架归 preset） |
| G2 | **状态机不产生记忆** | B 的顶点/未接住记账（trait/trust 演化）只改状态机自身参数；**不得**据此向 M03/M04 提交任何候选——"关系变差了"是状态，不是事实记忆。若未来要记录，必须走 M03 候选通道 + 用户可见 |
| G3 | **状态机不参与删除/权限** | 心理状态恶化**绝不**触发记忆删除、隐藏或降权到权限层面（A 红线 P5/P6 的延伸）；"暂时不提难过的事"只能走显式用户指令 |

### 5.3 影子运行（上线前强制阶段）

B 自己承认最大缺口是"没有真实语料"。因此接入分两档：

| 档 | 行为 | 退出条件 |
|---|---|---|
| **影子模式**（强制首档） | 状态机照常运转并记录（日志），但 `mind.hint()` **不注入 prompt**、七步链**不影响排序**；同时 A 方案的写时标注照常落库 | 真实对话跑 ≥2 周：① 事件抽取在真实语料上的情绪判向与主人观感一致率 ≥75%（抽样人工复核）；② 无状态漂移/崩溃记录 |
| **生效模式** | hint 注入 + 七步链参与排序，α 类参数从保守值起步 | 影子达标后手动切换；随时可回影子 |

这一档把 B 的"唯一无法靠代码解决的缺口"转化为**有退出条件的可控风险**。
