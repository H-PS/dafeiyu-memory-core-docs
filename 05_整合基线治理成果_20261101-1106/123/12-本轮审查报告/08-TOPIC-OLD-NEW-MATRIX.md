# 08 — 知识主题 × 新/旧语料 对照矩阵

**问题**：是不是"新旧都有事"？
**结论**：**是，但不是同一类事，也不对等。**
- **新（canonical + work 14/15）**的问题集中在**契约与执行层**：没有 DDL、写入闭环断、tier 无转换、Persona 无管线、权威未裁。
- **旧（时间流）**的问题集中在**档案与证据层**：缺 canonical、174/133 哈希缺口、日期标签失真、39% 重复、凭据暴露；内容本身反而保存了大量**机制与教训**。
- 按主题看：**新强在"对象与接口"，旧强在"机制与踩坑"**；有 **5 个主题两边都缺**。

## 3. 一张图说清"新旧各有什么事"

```
                  内容/机制完整度            契约/可执行度
新 canonical  ████████████████░░░░  高        ███░░░░░░░░░░░░░░░░░  低（0 DDL / 写入断）
新 work 14·15 ██████████████░░░░░░  中高      ████░░░░░░░░░░░░░░░░  低（授权矛盾 / 三套参数）
旧 时间流     ██████████████████░░  高（素材） ██░░░░░░░░░░░░░░░░░░  很低（非正式 / 副本 / 缺 canonical）
```

- **新**：知道"要建成什么样"，但**没有一张能开工的图纸**（对象全、接口全、DDL 空）。
- **旧**：有大量"别人踩过的坑与可复用机制"，但**很多是未批准的候选稿**，且档案本身不完整。
- **所以不是"新旧都有事"这么对称**：新是"设计超前、执行未落地"；旧是"经验丰富、身份不明"。

---

## 4. 使用建议（按主题）

1. **对象/接口/枚举** → 只用新（canonical），旧的不作依据。
2. **并发/删除/启停/Embedding 迁移/人格注入/心理分层/验收方法** → 取旧的**机制与不变量**，重写成 R4.1 契约，不搬实现。
3. **tier/关系/Persona/DDL/权限表** → 两边都没有，必须新设计（见主报告 N-01…N-13、M0-1…M0-6）。
4. 任何来自旧文档的结论，一律标 `NEW PROPOSAL` 或"可直接继承（附裁决出处）"，**不得写成已批准**。
