## 0. 四个不等号（本文件的最高纪律）

> 这四条不是修辞。它们各自对应本项目已经发生过或即将发生的**具体误判**，因此逐条展开：左边能证明什么、不能证明什么、右边需要什么证据。

### 0.1 `Mock 通过 ≠ 真实数据验证通过`

| | 内容 |
|---|---|
| **左边（已成立）** | 66 条测试全绿（`README.md:103-129`）、demo 计数稳定、幂等复跑 `evidence_written=0`、故障注入 11 条全过 |
| **左边证明了** | 七步链路在**受控夹具**上自洽；状态机、幂等键、错误分类的**代码逻辑**正确 |
| **左边不能证明** | ①真实库能否被打开（`bc-source.ts:30` 的 `readOnly` **从未运行**，`RISK-REGISTER.md:42` R-01）；②6 条 SQL 是否与真实 schema 匹配（`bc-source.ts:75-84` 依赖 `ts`/`retired_at` 两列，即隐含 `user_version≥10`，见实验计划 F-01）；③真实数据的 `payload_json` 键名是否如假设（`bc-source.ts:141-146`）；④真实比例（孤儿率、`-1` 哨兵率、reasoning 占比）是否让规则失效 |
| **右边需要什么** | `E-1` 的结构一致率 = 100%、`E-2` 的哈希一致率 = 100%、`E-9` 的 payload 解析成功率 = 100%；且**实验对象版本号已知**（实验计划 A-6） |
| **典型误判** | "66 条测试全绿，所以可以接入" —— `INTEGRATION-READINESS.md:290` 已把这条列为"明确不建议的做法" |
| **本路线图的落点** | v0.1 的验收**只**包含 Mock 范围；v0.2 的准入**只**看真实数据实验结论 |

### 0.2 `真实数据读取成功 ≠ Evidence 契约通过`

| | 内容 |
|---|---|
| **左边可能达到的状态** | v0.2 结束时：能打开真实库、能恢复原话、能算出 `content_hash`、能构造出 15 字段的 `EvidenceDTO` |
| **左边证明了** | 数据侧可行（"原话可恢复"这个项目命题成立） |
| **左边不能证明** | 这个 DTO 能被 Memory Core **接受**。`evidence.schema.json` 是 `additionalProperties:false`（`contracts/schemas/evidence.schema.json:7`），且**没有** `original_text`/`speaker_id` 字段、`source_type` 枚举里**没有** `"chat"`（同文件 `:13`）、`required` 里有 `scope` 与 `recorded_at`（同文件 `:8`）而 DTO 里没有这两个名字的字段（`domain.ts:116-134`）、`evidence_id` 要求 `format:uuid`（同文件 `:10`）而原型是 `"<session>:<seq>"`（`evidence-adapter.ts:53`）。→ **至少 8 类硬违规**（实验计划 E-8 的预期清单） |
| **右边需要什么** | ①`E-8` 的违规清单（不是"大概不兼容"，是逐字段、带 schema 行号）；②`D-9` 的裁决（升版 schema / 桥接侧投影）；③裁决后重新生成 Evidence 并**零违规**（或在裁决文书中逐条豁免） |
| **典型误判** | "我们已经把原话取出来了，写进 Evidence 就行了" —— 写进去的每一条都会因 `additionalProperties:false` 被拒；若绕过校验器硬写，就是**不可撤销的脏数据**（`RB-1`/`RN-9`） |
| **本路线图的落点** | v0.2 只做"读"；"写契约"是 v0.3 的开工前置，**v0.2 的通过不能当作 v0.3 的开工许可** |

### 0.3 `Evidence 写入成功 ≠ Memory Core 候选与确认流程通过`

| | 内容 |
|---|---|
| **左边可能达到的状态** | v0.3 结束时：Evidence 成功写进一个**一次性记忆库**并能回读 |
| **左边证明了** | 写入通道打通（schema 合规、幂等、可撤销） |
| **左边不能证明** | 记忆**生效**。Memory Core 的生命周期是 `candidate → pending_review → active`（`contracts/state-machines/state-machines.md:10-16`），其中 `pending_review → active` **只能由 M04 审核通道写入**（同文件 `:15`，台账 D-AP-05），且 `candidate.evidence_refs` **必须非空**才可进 `pending_review`（`contracts/schemas/candidate.schema.json:18`）。也就是说：**Evidence 只是候选的输入，不是记忆本身**。桥接层的六不原则已把这一点写死：`internal_to_memory_unit = "FORBIDDEN_IN_BRIDGE"`（`evidence-adapter.ts:23`） |
| **右边需要什么** | ①候选生成（M03）——**不是 CMB 的职责**；②质量检查（十项 `quality_flags`，`candidate.schema.json:24-28`）；③M04 审核通道的 `confirmed` 写入；④`SM-2 validation_state` 的 `unverified → confirmed`（`state-machines.md:37-49`）。四项缺一，记忆就停在 `candidate`，永远不会 `active` |
| **典型误判** | "Evidence 已经写进去了，所以记忆库已经有记忆了" —— 事实是：它最多变成一条 `candidate`，且若 `evidence_refs` 为空连 `pending_review` 都进不去 |
| **本路线图的落点** | v0.3 的验收**只**包含"Evidence 侧"；"候选与确认流程"属于 Memory Core 项目，CMB 在 v0.5 灰度时**只能承诺"提供了合格输入"**，不能承诺"记忆已生效" |

### 0.4 `沙盒端到端通过 ≠ 生产安全`

| | 内容 |
|---|---|
| **左边可能达到的状态** | v0.3/v0.4 结束时：沙盒里跑通"读真实数据 → 写一次性记忆库 → 撤销 → 重建台账 → 再对账"，全部一致 |
| **左边证明了** | 功能正确、幂等、可恢复、可回滚 |
| **左边不能证明** | ①**性能不伤热路径**（沙盒没有真实写负载；`E-10` 才是唯一证据）；②**权限边界正确**（沙盒里我们有权读一切；生产里权限是收缩过的）；③**数据治理合规**（沙盒里可以随意存副本；生产里副本是敏感资产）；④**故障不致灾**（沙盒崩溃无所谓；生产里磁盘满/多实例/误配路径都是新的失败模式）；⑤**人的流程**（谁批准、谁回滚、多久发现） |
| **右边需要什么** | ①`E-10` 的量化结论（p95 增幅、WAL 峰值、零 BUSY）；②最小权限运行（路线 D 的"只读备份目录"，见架构方案 §1.4）；③v0.4 的 7×24 影子运行 2 周零事故；④v0.5 的灰度 30 天 + 回滚演练通过 |
| **典型误判** | "沙盒里端到端跑通了，可以上生产了" —— `INTEGRATION-READINESS.md:290` 已警告；本路线图把它变成**阶段门禁**：v0.4 与 v0.5 存在的**唯一理由**就是补上这一条不等号 |
| **本路线图的落点** | v0.4 = 影子（不生效）、v0.5 = 灰度（生效但极小）；两者都不是"可选步骤" |

### 0.5 三条补充不等号（同等纪律，但非任务书原列）

| 不等号 | 说明 |
|---|---|
| `只读副本通过 ≠ 活库可用` | 副本没有 `-wal` 争用、没有 `-shm` 共享问题。R-18 只有在活库上才能被回答（实验计划 E-3 T3） |

### 3.2 v0.2 的准入条件（**= 进入 v0.3 的门禁，三条**）

> 这三条也是本文件向总控回复的"v0.2 准入条件"，刻意压到三条以内。

1. **材料合法且版本可考**：拿到一份用户授权的一致性只读副本（`A-1`）+ 该库对应的 `bili` 版本号（`A-6`）+ 宿主身份导出物（`A-2`，若 E-6 要做）。三者缺一，v0.2 的结论不可采信。
2. **三张地基卡有量化结论且无"以假设填空白"**：`E-1`（结构一致率、`user_version`、CAS 孤儿率）、`E-2`（`algo` 值域、`byte_len` 一致率、抽样哈希一致率）、`E-8`（契约违规清单 ≥8 条且逐条可定位）。结论必须能回答"yes/no + 数字"，不能停留在"基本一致"。
3. **只读与隔离被证明而非被承诺**：每张卡的 RO-5 审计产物齐备（`total_changes=0`、源文件指纹不变、`query_only=1`）；产物中零正文；`_exp` 与 `evidence` 的落盘位置与保留期已登记（`A-5`）；且**未向任何真实 Memory Core 写入任何一条记录**（可用 Memory Core 侧的空表快照反证）。

## 5. v0.4 · 影子运行（7×24 双轨观察，不对外生效）

| **风险** | ①**误开写开关**：影子期若配置错误，可能写到真实库 → 必须"写开关默认关闭 + 启动自检打印目标库身份（并断言不是生产库）"；②**磁盘满**：副本堆积 → 保留策略 + 配额告警；③**副本泄漏**：副本含全员明文 → 权限收缩到专用账户 + 加密盘 + 30 天保留；④**长期运行暴露低频 bug**（块消失/重建/clock skew）；⑤**运维疲劳**：告警太多会被忽略 → 只对"会导致数据错误"的事件告警 |
| **测试** | ①**7×24 连续 2 周**；②每周一份"对账一致性报告"（本次 run 与上次 run 的差集必须可解释）；③**故障演练清单全部通过**（见下方 5.1）；④影子结果与"人工抽查"对比（抽 N 个块，人工核对恢复的原句与源一致） |
| **验收标准** | ①连续 2 周零 P0 数据事故；②`E-10` 结论为"可长期开启"（p95 增幅 <10%、零 BUSY），或形态已改为纯副本；③每周对账差集 100% 可解释（无"原因不明的丢失"）；④故障演练 6/6 通过；⑤ledger 增长曲线与预测偏差 <30%；⑥撤销延迟 P95 ≤ 1 h |

| **是否需要用户裁决** | **是**：①影子范围（哪些会话/群）；②时间窗（是否允许低峰扫描）；③是否接受"纯副本形态"（若 E-10 判定禁直连）；④告警接收人与响应 SLA |
| **是否允许进入下一阶段** | **允许进入 v0.5（生产灰度）**，前提：2 周零事故 + 6 项故障演练全过 + 用户明确批准灰度名单。**若 E-10 结论为"禁止活库任何交互"，则 v0.5 只能在纯副本形态下进行**（此时撤销延迟受快照周期约束，需用户书面接受） |

## 6. v0.5 · 生产灰度（单租户 / 单群，可写 + 可撤销）

| 字段 | 内容 |
|---|---|
| **目标** | 在**最小范围**内真实生效：Evidence 写入真实记忆库（仅灰度名单内的会话），撤销生效，用户可见。用最小爆炸半径验证"生产安全" |

| **风险** | ①**脏数据进入生产**（契约/身份错）→ 只能靠 v0.3 的验收 + 灰度期逐条审计；②**撤销延迟**导致"已删内容仍在"（治理事故）；③**范围蔓延**（从 1 个群涨到全量）→ 必须"扩范围走审批"；④**多实例误启**（同一台账被两个进程写）；⑤**记忆库侧不受 CMB 控制**（若 Memory Core 侧拒绝或行为不同，CMB 无法兜底） |
| **测试** | ①灰度群端到端（新增 → 撤销 → 复活 → 重建）；②**回滚演练**：把灰度群全部 Evidence 标 revoked，验证记忆库不再检索到它们；③压测（灰度范围的最大消息速率 × 3）；④混沌（同 v0.4 六项 + 多实例并发写入必须被锁挡住）；⑤**对账一致性周报** |
| **验收标准** | ①灰度 30 天零 P0 数据事故；②撤销 SLA：P95 ≤ 1 h、100% 的撤销在 24 h 内完成；③回滚演练成功且恢复时间 ≤ 30 min；④对账一致性：每周差集 100% 可解释；⑤ledger 与副本磁盘增长在预算内；⑥**人工抽查**：随机 50 条 Evidence 与源逐字一致（人工核对，不是脚本）；⑦用户书面确认"可以扩范围" |
| **禁止事项** | ①**绝不**把范围从名单外自动扩大（扩范围必须重新审批）；②**绝不**关闭逐条审计；③**绝不**跳过人工抽查；④**绝不**在撤销失败时"重试到成功"而不告警（要有上界）；⑤**绝不**把 `revoked` 当删除（它是布尔标记，`evidence-sink.ts:71-79`）；⑥**绝不**承诺"记忆已生效"——只能承诺"已提供合格 Evidence 输入"（见 §0.3） |
| **是否需要用户裁决** | **是**：①灰度名单与扩范围审批；②`D-14` 的对外承诺口径（撤销多久生效、复活怎么表达）；③是否接受"CMB 不保证记忆生效、只保证证据合格"的责任边界 |
| **是否允许进入下一阶段** | **允许进入 v1.0**，前提：灰度 30 天零事故 + 回滚演练通过 + 用户明确批准扩范围。**禁止自动进入**（v1.0 意味着多实例/多租户，风险面性质变化） |
