## 2. 核心设计原则（不可违背）

1. **单一写路径**：任何 A 层写只能经 `MemoryService` 写队列；B 层永不由外部直接修改（B 是投影）。
2. **A 层是事实源**：memoryId/revision/lifecycle 只在 A 层定义；B 层派生。
3. **写前重读**：写队列内每次操作从最新 store 状态定位目标，绝不复用请求进入时的数组/索引。
4. **旧 revision 不得覆盖新 revision**：恢复、重试、并发一律以 `expectedRev` 校验。
5. **恢复不得绕过 tombstone**；备份恢复默认跳过已删记录。
6. **A/B 不得相互递归触发写入**：B 投影更新只作为 A 层同一操作的 effect，不产生新的 A 写。
7. **正文持久化与向量可用性解耦**：embedding 失败不等于记忆写入失败。
8. **分级审计**：不可逆操作（删除/授权/恢复）审计必须成功才允许提交；其余走补偿。
9. **第一版不引入新存储引擎**：保持 JSONL + 文件锁，SQLite 列为后续扩展。
10. **保留已定的 12 项设计决策**（见 §5），冲突项列入 08 待决策。

## 3. 目标架构

```
入口：bridge.js HTTP 端点 / MCP 5 工具（接口签名不变，内部转发）
  │
  ▼
src/memory-service.js  ←—— V2.4.2 唯一新增模块
  ├─ Normalizer     边界规范化（canonicalKey + token 脱敏 + 截断 + subjectId）
  ├─ Embedder       六态状态机；在【写队列外】执行，不持锁
  ├─ WriteQueue     进程内 FIFO 串行；WAL 先行 → 重读 → rev 校验 → Tier1 审计 → 原子提交 → WAL committed
  ├─ ReadAPI        list/get/search；过滤 lifecycle/tombstone/visibility/embedding 就绪
  ├─ Reconciler     A→B 投影修复（只重建 B，不写 A）
  ├─ Recovery       启动扫描 WAL 未提交项
  ├─ Auditor        两级审计 + 轮转 + 补偿队列
  └─ Backup         envelope 备份 + dry-run 恢复

存储（全部在 state/，原子写规范统一：随机 tmp + fsync + renameWithRetry + 0600）：
  memory-store.jsonl          活动记录（原子重写）
  memory-tombstones.jsonl     墓碑（只追加，永久）
  memory-wal.jsonl            WAL（追加 + checkpoint 截断）
  memory-share-requests.jsonl 分享申请（原子重写）
  memory-audit.log            审计（capped 10MB×10）
  memory-audit-pending.jsonl  审计补偿队列
  writer.lock                 跨进程写互斥
  bridge.lock                 进程实例锁（升级为状态文件：pid+instanceId+state+heartbeat）
  social-v2.json              B 层投影（结构升级，文件名不变）
backups/memory-backup-*.json  结构化备份 envelope
```

## 4. A 层记录 Schema（V2）

```json
{
  "id": "mem_01J8Z…",            // ULID，全局唯一，永不回收
  "rev": 3,                       // 每次成功变更 +1，初始 1
  "key": "group:123456",          // canonical（写入前统一规范化）
  "category": "activeTopic",      // activeTopic|pendingThought|memberImpression（+future）
  "subjectId": "某群友",           // memberImpression 必填；其余 null
  "factKey": "preference:group:123456:food",  // 可空，见决策 1/2
  "text": "…（脱敏后全文，≤1000 字）",
  "owner": "group:123456",
  "visibility": "owner_private",  // owner_private | group_shared
  "lifecycle": "active",          // active|pending_delete|expired|evicted|suppressed
  "vec": [ …1024 floats ],
  "vecModel": "bge-m3",
  "vecDim": 1024,
  "embedding": { "status": "ready", "attempts": 0, "nextRetryAt": null, "lastError": null },
  "origin": null,                 // 分享副本：{ "id": "mem_原件", "rev": 2 }
  "expiresAt": null,              // pendingThought 专用
  "shareCopies": [ { "targetKey": "group:999", "status": "approved", "requestId": "req_…", "copyId": "mem_…" } ],
  "suppression": null,            // { "scope": "text|vec|all", "at": …, "by": …, "reason": "…" }
  "createdAt": 1730…, "updatedAt": 1730…,
  "migratedFrom": null,           // "v1" 迁移标记
  "_crc": "sha256:…"              // 记录级校验（规范字段序列化后哈希）
}
```

## 7. 八个最终问题的回答

**Q1 V2.4.2 vs V2.4.1 新增什么** → §1 表（10 项）。

**Q2 哪些 V1 缺陷能被彻底解决**（结构性消除，无残余路径）：
F-01（写队列+重读+rev）、F-03（响应统一报 `aRemoved`/各层计数）、F-04（B 投影化+A 层同步 lifecycle）、F-06/F-15（统一原子写）、F-09（memoryId 审批）、F-23（写入前 canonical）、F-18/F-19（顺带清理）、F-26（备份带时间戳命名）。

**Q3 哪些只能降低概率或提供补偿**：
| 缺陷 | 残余风险 |
|---|---|
| F-07 | 双进程抢锁的理论窗口缩窄到「锁年龄>grace 且状态未推进且端口空闲」并全链路留痕；无法证明 100% 消除 |
| F-10 | opId 幂等 + contentHash 去重消除重试/超时重复；**模型语义性重复调用**（不同措辞）仍可能产生近似条目 |
| F-12/F-13 | 坏行隔离 + 告警 + `_crc`；磁盘级损坏仍可能丢行（可检测、不可恢复） |
| F-14 | 维度/数值校验 + vecModel 隔离；模型切换后历史向量需重算窗口期，期间降级检索 |
| F-16 | 缓存改 `storeVersion` 计数器；同毫秒并发读写仍有理论竞态（写队列已消除写写竞态） |
| F-20 | 端点鉴权改无条件三重校验；依赖全局兜底仍是纵深防御 |
| F-22 | 查询失败分层返回（B 成功 + A 降级标志）；Ollama 不可用时仍无法语义检索 |

**Q4 影响现有数据**：`memory-vectors.jsonl` → 新 `memory-store.jsonl`（旧文件保留为 `.v1.bak`）；`social-v2.json` 结构升级（B 三字段加 `memoryId/rev`）；`bridge.lock` 格式升级；新增 6 个 state 文件；`backups/` 格式换 envelope。`memory-admin.log` 旧格式停用（保留归档）。

**Q5~Q7 旧记忆迁移**（详见 03 §7、08 D-08~D-11）：离线迁移工具（需 writer.lock + 服务停止）→ 全量备份 → dry-run 报告 → 确认 → 逐行赋 id/rev=1/lifecycle=active → 同 key+category+text 去重合并 → 原子写新 store → 旧文件只读保留。**防丢失**：迁移前后条数对账 + 每行 `_crc` + 失败即整体回退（迁移在临时副本上完成后才 rename）。**防复活**：迁移只读**当前** store 文件，不触碰任何历史备份；tombstone 初始化为空。V1 是物理删除，"已删但存在于备份"的记录在 V1 数据中不可识别 → 列入 08 D-12（是否接受此边界）。

**Q8 第一版最小可交付** = M0（见 §6）。

**Q9 必须留到后续**：ShareSuggestion（决策 8）、factKey 完整模板与七种关系型、副本批量重嵌入、SQLite、WAL 压缩、审计检索界面。
