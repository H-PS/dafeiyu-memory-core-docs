# 第一章 · 项目是什么

为 **DSH（DeepSeek Harness）QQ 机器人**构建一套 **Memory Core 记忆库系统**（R3 设计 / R4 集成 / R4.1 定点修订），当前卡在 **"CR-08A 域内答复"** 这一环——即 L3 证据链（记忆是否真的进入了最终 Prompt）的技术设计收口阶段。

## 1.2 系统结构

```
QQ 用户
  ↓
DSH（DeepSeek Harness 运行时，宿主）
  ↓
qq-bridge（本地桥接进程，代码在 D:\qq-bridge，约 12,482 行 bridge.js）
  ↓
Memory Core（五模块设计，尚未实现）
  ├─ M01 存储与数据管理（SQLite 权威存储）
  ├─ M02 检索与上下文构建
  ├─ M03 提取与候选生成
  ├─ M04 整合、反思与视图维护
  └─ M05 权限与访问控制
```

**关键事实**：`qq-bridge` 当前**未接入**记忆库与心理层（事实 F6）。Memory Core 全部为设计文档，零实现。所以本项目是**纯设计阶段**，任何"已定义"都只指设计文本，不指代码存在。

# 第四章 · 技术设计核心（v4.6 候选内容）

> 以下为需要新对话理解的技术骨架。完整条文见 `04_LATEST_V46_CANDIDATE/v4.6-latest-design-candidate.md`。

## 4.1 L1–L5 五级确认链（理解整个项目的基础）

| 级别 | 含义 | 可否验证 |
|---|---|---|
| L1 | 检索到了该记忆 | 可 |
| L2 | 准备注入 Prompt | 可 |
| **L3** | **记忆版本确实进入了最终 Prompt** | **本项目核心** |
| L4 | 模型实际使用了该记忆 | **无可靠通用信号** |
| L5 | reinforce 写入（强化） | **禁写中** |

**关键区分**：L3 只证明"进入"，不证明"使用"；L3 不得替代 L4；**不得仅凭 L3 触发 reinforce**。

## 4.2 两条独立证据链

1. **请求关联链**：InjectionRecord → correlationId → DSH turn
2. **内容映射链**：memoryId + memoryVersion → 组装追踪 → PromptAssemblyEvidence

两条链**独立成立、均通过才认定 L3**，不得互相替代。所有集合比较以 `(memoryId, memoryVersion)` 为单位。

## 4.3 两阶段事件模型（v4.6 核心创新，解决循环依赖）

**问题**：整体有效性 passed 需要检查 ③ 通过 → ③ 需要事件 → 事件需有效性通过 → **成环**。

**解法**：
```
第一阶段：实际组装观察记录（prompt/assembled）
  ├─ 组装完成后立即产生
  ├─ 是 Bridge 核验的【输入】
  ├─ 不代表证据有效 / 不代表 L3
  └─ 即使后续证据 invalid 也必须保留

        ↓ Bridge 执行检查 I / II / III

第二阶段：有效 L3 确认记录
  ├─ 仅当整体有效性=passed 且版本满足 complete 时产生
  ├─ 由 Bridge 产生（E-2 接口扩展）
  └─ 仅覆盖明确列出的版本
```

- 检查 ③ 重定义：比对**第一阶段观察记录声明集合** ≡ 证据 complete 集合；
- 两阶段经同一 `correlationId` / `assemblyId` 关联。

## 4.4 A1–A8 结构错误分类（证据级 invalid）

| 编号 | 定义 |
|---|---|
| A1 | 外层结构损坏或核心关联结构缺失（evidenceId/injectionId/correlationId/sessionId/turn/assemblyId/versions/fragments）。**明文排除** mappingEvidenceRef、removalBasis（归 B1/B2） |
| A2 | 注入快照与 versions 不一致（缺项/多项/重复/集合不完整） |
| A3 | memoryId/memoryVersion 错配 |
| A4 | 引用绑定**明确错位**（对象可取得但绑定错误 memoryId/version/component/assemblyId） |
| A5 | 同一 component 重复声明 |
| A6 | 无效 fragmentId 引用（指向不存在的片段） |
| A7 | fragmentDigest 校验失败（摘要与实际内容不符） |
| A8 | 其他可确认的结构性/完整性错误（**兜底，援引须给出六要素**） |

## 4.5 B1–B4 证据不足分类（版本级 unknown）

| 编号 | 定义 |
|---|---|
| B1 | mappingEvidenceRef 缺失 / 对象不可取得 / 无法核验语义映射 |
| B2 | removalBasis 缺失或其 ref 缺失/不可得/不可核验（→ 不得判 removed） |
| B3 | 证据对象部分内容暂时不可读、无法确认是否保留 |
| B4 | 无法确认来源/版本/语义映射，但无篡改证据 |

**v4.6 关键修订**：B1/B2 **收窄**——"引用字段存在但对象不可取得"**不再**作普通 unknown，改由 **not_executable** 处理。

## 4.6 聚合规则 1–6（固定顺序，首个命中生效）

| 序 | 条件 | result |
|---|---|---|
| 规则 1 | 出现 A 清单任一情形 | `invalid` |
| 规则 2 | 否则，任一版本 unknown | `unknown` |
| 规则 3 | 否则，任一版本 partial | `partial` |
| 规则 4 | 否则，全部版本均为 removed | `removed` |
| 规则 5 | 否则，全部版本均为 complete | `complete` |
| 规则 6 | 否则（complete 与 removed 并存） | `partial`（定义式汇总） |

**规则 6 语义声明**：`partial` 有两种来源（规则 3 / 规则 6），均仅用于审计汇总，**不参与 L3 判定**。

## 4.7 §2.3.13 检查模型（三类检查 × 四态）

**三类检查**：
- **检查 I**：证据有效性（A1–A8、字段、引用绑定、fragmentDigest）
- **检查 II**：请求关联与集合一致性（Bridge 专属 ①②③）
- **检查 III**：版本内容完整性（requiredComponents、mappings、B1–B4）

**四态**：`not_started` / `not_executable` / `passed` / `failed`
- not_started ≠ not_executable ≠ failed ≠ passed
- **单项 passed ≠ 整体 passed**

**整体聚合优先级**：
```
任一 failed        → 整体 failed（invalid）
否则 任一 not_executable → 整体 not_executable（不得 passed）
否则 任一 not_started    → 整体 not_started
否则                     → 整体 passed
```

**unknown 三分**（§2.3.13 13.5）：
- a. **合法缺失型**：字段合法缺失 → unknown，整体**可以** passed
- b. **语义不足型**：对象可取得但语义不可证 → unknown，整体**可以** passed
- c. **必需检查无法执行型**：字段存在但对象不可取得 → **not_executable**，整体**不得** passed

## 4.8 L3 版本级确认的四个合取条件

```
L3 确认 = 检查 I 整体 passed
        ∧ 检查 II passed
        ∧ 该版本检查 III 判定 complete
        ∧ 第一阶段/第二阶段记录关联一致
```

**四条件缺一不可**。请求级状态、一致性检查完成标记、DSH 组装事实、模型实际使用，均不得替代其中任何一项。

# 第九章 · 经验教训（避免重复踩坑）

## 9.1 已犯过的错误

| 错误 | 教训 |
|---|---|
| 曾声称"v4.5 只有转录摘录" | **v4.5 完整原文存在于对话导出 L125544–L125966**，只是未落盘 |
| A 包 v4.5 摘录首版有实质错误（聚合规则 2/3/6 错位、B3 收窄、分类原则整段缺失） | 摘录必须逐字核对原文，**不能用语义概括代替** |
| 曾把 v4.6 的 A8 括注混入 v4.5 定义表 | 不同版本的内容不得混入 |
| 首次重建 ZIP 时漏掉 SHA256SUMS.txt | 清单三件套必须全部入包 |

## 9.2 技术坑（PowerShell/Python）

| 坑 | 解法 |
|---|---|
| PowerShell here-string 用单引号 `@'...'@` → 变量不插值 | 用双引号 `@"..."@` |
| `.Add("x" -f a, b)` 被解析成多参数 | 先赋值再 Add |
| Python 脚本里路径写成 `\\\\` → 变成双反斜杠 | 用 raw string `r"C:\Users"` 单反斜杠 |
| 文件带 UTF-8 BOM | Python 读用 `encoding="utf-8-sig"` |
| 控制台 GBK 无法输出 `↔` 等字符 | 写入 UTF-8 文件再读，不要直接 print |
| `edit` 工具报"file has not been read" | 改用 pwsh/Python 直接替换 |

## 9.3 工作方式要点

- 用户**逐项授权**，不接受"顺便做了"；
- 每次修改必须报告 **SHA256 + 校验结果**；
- 完成后**必须停止等待**，不得自行进入下一步；
- 报告要**如实标注**哪些是原文、哪些是推导、哪些无法确认。
