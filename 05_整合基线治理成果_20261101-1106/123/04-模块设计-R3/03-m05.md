# M05：权限与访问控制模块（Permission & Access Control）

**版本：** Draft 1.0  
**状态：** Design Frozen  
**适用项目：** QQ Bridge 独立 Memory Core  
**设计范围：** 本地单实例 QQ 机器人  
**原则：** 轻量权限、明确边界、低延迟、可扩展

> **基线归属声明**
> 本文档属于**新一代 Memory Core 设计基线（暂称 R3）**。
> `R2架构-最新-20261101/` 中的同编号模块属于**历史基线**，内容不具有当前设计优先级。
> 引用时必须明确区分版本，不得混合引用。

---

## 一、模块目标

M05 是 Memory Core 内部唯一的权限判定权威。

负责：
1. 识别请求主体及其可信身份上下文。
2. 判定记忆读取、写入、修改、删除、分享和撤销权限。
3. 管理 `private`、`group`、`shared` 三种记忆范围。
4. 维护 Memory Share 授权关系。
5. 处理权限撤销及相关访问失效。
6. 为其他模块提供统一权限判定接口。
7. 记录必要的权限操作审计信息。

M05 不负责：
- QQ 消息接收和身份解析。
- 记忆内容提取和评分。
- 记忆整合与 Observation 构建。
- 记忆持久化的底层事务执行。
- LLM 人格安全和聊天行为规范。
- Diary、Dream 的业务工作流。

核心原则：

**行为安全由人格和 System Prompt 负责，数据访问权限由 M05 强制执行。**

## 二、总体架构与职责

### 2.1 模块职责

| 模块 | 权责 |
|---|---|
| Bridge | 接收 QQ 消息、提供可信身份上下文、调用 Core、向用户反馈结果 |
| M01 | 权限记录和记忆数据的事务性持久化 |
| M02 | Recall 检索、权限过滤、结果组织和预算控制 |
| M03 | 记忆提取和候选生成 |
| M04 | 记忆整合、Observation、关系及派生数据维护 |
| M05 | 最终权限判定、授权生命周期和访问控制 |
| DSH / LLM | 消费授权后的 Memory Context，不直接访问权限数据库 |

### 2.2 信任边界

Bridge 是 Core 接收 QQ 身份信息的可信入口。

Bridge 提供：
- `user_id`
- `chat_type`
- `chat_id`
- `group_id`
- 当前成员资格信息（适用时）
- `request_id`

Core 接收请求后建立统一 Trusted Context。

约束：
- 普通业务参数不得覆盖可信身份字段。
- 各模块不得自行解析 QQ 身份。
- 身份缺失、格式错误或无法验证时，默认拒绝受保护操作。
- 内部模块传递时保留原始请求 ID 和调用链信息。
- M05 统一判定权限，不允许其他模块自行推断授权。

### 2.3 身份字段区分

| 字段 | 含义 |
|---|---|
| `actor_id` | 当前执行操作的人 |
| `author_id` | 原始消息或记忆的贡献者 |
| `subject_id` | 记忆描述的对象 |
| `owner_id` | 记忆所有者 |
| `group_id` | 群组范围标识 |

这些字段不能互相替代。

## 三、记忆权限范围

第一版只实现三种业务范围。

### 3.1 Private

个人私人记忆。

- 绑定稳定的 `owner_id`。
- 默认只有所有者可以访问。
- 不因群聊提及自动共享。
- 不因所有者是消息贡献者就自动产生私人记忆。
- Bot 所有者拥有全局管理权限，包括读取私人记忆。

### 3.2 Group

群组记忆。

- 群聊产生的记忆默认归属于对应 `group_id`。
- 不自动归入发言者的私人记忆。
- 当前有权访问该群的成员可以读取。
- 不同群组之间相互隔离。
- 保留 `author_id`，用于来源追溯、纠错和删除申请。

成员退出或被移出群后，立即失去该群记忆的读取权限。

群解散后，该群记忆整体停止对外访问，后续按生命周期策略处理。

### 3.3 Shared

私人记忆经所有者明确授权后，允许指定群组读取。

采用引用授权，不复制私人记忆。

- 原始记忆仍然只有一份。
- 所有权保持不变。
- 每个目标群独立建立授权记录。
- 撤销群 A 的授权不影响群 B。
- Shared 默认长期有效，直到主动撤销或触发失效条件。
- 检索表现跟随原始记忆的生命周期和衰减机制。

Shared 不是新的记忆所有权，而是对指定目标群开放的访问授权。

第一版不实现复杂的 `system` 等业务范围，但保留扩展空间。

## 四、Bot 所有者权限

### 4.1 所有者身份

Bot 所有者通过本地可信配置中的固定 `owner_id` 认定。

约束：
- Bridge 传递可信身份上下文。
- Core 根据可信上下文统一识别所有者。
- QQ 昵称、群名片和用户自我声明不能获得所有者权限。
- 修改 `owner_id` 必须通过本地管理操作。
- 所有者身份变更必须留下审计记录。

### 4.2 所有者权限

Bot 所有者拥有全局记忆管理权限，包括：
- 读取私人记忆。
- 读取群组记忆。
- 管理 Shared 授权。
- 执行必要的记忆维护、修改和删除。
- 查询本地权限审计记录。

所有者权限不允许被普通插件或普通群聊业务流程调用。

敏感操作必须留痕，高影响操作必须进行本地二次确认。

### 4.3 QQ 群管理员

QQ 群管理员身份不自动获得额外记忆管理权限。

不将平台管理员身份等同于 Memory Core 数据所有权。

## 五、操作权限

| 操作 | 默认权限 |
|---|---|
| Recall / 读取 | 当前范围内的授权成员 |
| Retain / 新增 | 允许向当前个人或群组范围贡献候选 |
| Update / 修改 | 记忆所有者或授权管理者 |
| Correct / 纠正 | 允许提交纠正，由 Core 校验 |
| Delete / 删除 | 所有者或授权管理者 |
| Share / 分享 | 私人记忆所有者主动授权 |
| Revoke / 撤销 | 授权所有者或有权管理者 |

补充规则：

1. 提交纠正不等于直接覆盖原记忆。
2. 提交删除请求不等于直接执行删除。
3. M05 负责授权判定，M01 执行正式持久化变更。
4. 普通群成员可以贡献群聊记忆，但不能随意修改或删除其他成员的私人记忆。
5. Bot 所有者可以执行全局维护操作，但仍需审计。

## 六、Memory Share

### 6.1 复用既有机制

现有系统已经有 `qq_memory_share_request` 和 approve/reject 审批流程。

M05 不另建平行审批系统，而是在现有机制上扩展：

- Private → 指定 Group 的授权能力。
- 授权范围。
- 授权撤销。
- 派生记忆权限继承。
- 必要审计。

拒绝或撤销时，应同步更新可见性状态，避免仅改变审批状态而遗留旧的可见性。

### 6.2 授权规则

- 必须由私人记忆所有者主动发起。
- 明确指定目标群组。
- 默认只分享明确选择的记忆，不分享整个私人记忆库。
- 原始私人记忆不改变所有权。
- 群组通过授权记录读取原始记忆。
- 不默认复制私人记忆。
- 不允许模型自行授权。

### 6.3 授权数据

建议字段：

| 字段 | 含义 |
|---|---|
| `share_id` | 授权记录 ID |
| `memory_id` | 原始私人记忆 ID |
| `target_group_id` | 授权目标群 |
| `granted_by` | 授权所有者 |
| `status` | pending / approved / rejected / revoked |
| `created_at` | 创建时间 |
| `revoked_at` | 撤销时间 |

每个目标群独立建立授权记录。

### 6.4 多来源与整合

私人记忆参与 M04 整合时：

- Observation 保留全部来源引用。
- 不自动转成普通 Group 记忆。
- 群组读取时确认相关 Shared 授权有效。
- 授权撤销后，相关 Observation 停止向该群提供。
- 原始私人记忆不受影响。

派生记忆不得扩大来源授权范围。

## 七、权限撤销

### 7.1 即时性

权限撤销采用：

**立即阻断访问，异步完成物理清理。**

具体规则：
1. 撤销成功后，立即阻断新的读取。
2. 相关缓存立即失效或标记不可用。
3. 旧快照不能绕过撤销结果。
4. 派生数据、索引和 Cue Anchors 按依赖关系重新评估或清理。
5. 撤销状态持久化，服务重启后仍然有效。
6. 清理任务失败允许重试，但不能恢复已撤销的访问权限。

### 7.2 并发处理

- 权限变更后递增权限版本。
- 在途操作提交结果前检查权限版本。
- 版本不一致时重新判定。
- 撤销优先于旧授权。
- 不影响无关群组和私人记忆。

## 八、群成员资格

Bridge 是群成员资格信息的可信来源。

Core 不自行连接 QQ 平台查询成员列表。

成员资格信息应携带：
- 来源。
- 有效时间。
- 用户 ID。
- 群组 ID。

过期、缺失或无法验证时：
- 拒绝群记忆读取。
- 不允许使用过期缓存继续授权。
- 普通聊天仍可继续，只是不注入无法确认权限的群记忆。

## 九、派生数据与轻量权限策略

### 9.1 基本原则

派生记忆不得扩大来源授权。

但第一版不建设企业级全链路权限系统。

采用轻量方式：

| 数据层 | 处理方式 |
|---|---|
| 正式记忆 | 存储时记录权限范围，Recall 时过滤 |
| Observation 等派生记忆 | 创建时继承来源权限 |
| Cue Anchors | 跟随原记忆权限 |
| 搜索索引 | 采用已有权限范围过滤 |
| Recall 缓存 | 权限变更时主动失效 |

### 9.2 性能约束

- 不在每次聊天时扫描全部向量。
- 不为每种派生数据建立独立权限规则。
- 不进行递归式全量权限检查。
- 不使用 LLM 判断权限。
- 不增加普通聊天的审批流程。
- 普通 Recall 使用索引和规则过滤。
- 敏感操作才执行额外校验。
- **同一请求内对相同 `(actor, memory_id, action)` 的判定结果可有限复用**（见 §10.4），避免单次请求内的重复计算。

核心原则：

**检查前置、规则简单、变更时失效；判定结果在单请求内有界复用，跨请求一律重新验证。**

> 说明：本原则要求的是"避免**无意义**的重复计算"，**不是**取消权限检查。每次进入新的请求、每个新增对象、每次权限状态变化，仍必须执行 M05 判定。

## 十、统一权限判定接口

M05 为 Core 内部模块提供统一接口。

### 10.1 请求结构

```json
{
  "request_id": "req_xxx",
  "actor_id": "user_xxx",
  "action": "read",
  "resource_id": "memory_xxx",
  "scope": "group",
  "trusted_context": {
    "user_id": "qq_user_xxx",
    "chat_type": "group",
    "group_id": "qq_group_xxx"
  }
}
```

### 10.2 返回结构

```json
{
  "decision": "allow",
  "reason_code": "authorized_group_member",
  "policy_version": "1",
  "permission_version": 12
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `decision` | allow / deny |
| `reason_code` | 判定原因 |
| `policy_version` | 权限策略版本 |
| `permission_version` | 当前权限数据版本 |

权限判定结果绑定单次具体操作：

- `request_id`
- `actor_id`
- `target_id`
- `action`
- `scope`
- `policy_version`

不允许跨请求、跨对象、跨操作复用授权结果。

### 10.3 模块调用边界

- M01–M04 通过统一接口请求 M05 判定。
- 其他模块不得直接修改权限记录。
- 其他模块不得自行推断权限。
- M05 是权限决策权威。
- M01 是权限记录持久化权威。

### 10.4 同一请求内的判定结果复用

**原则：同一请求内有限复用，跨请求重新验证。**

一次 Recall 以 `request_id` 为边界。同一请求中，对相同的 `(actor, memory_id, action)` 三元组，**如果授权依据及权限状态没有变化**，可以复用已经完成的判定结果，避免对同一条记忆在单次请求内无限重复计算。

**可以复用的条件（必须同时满足）：**

1. 同一个 `request_id`；
2. 相同的 `(actor_id, target_id, action, scope)`；
3. `policy_version` 与 `permission_version` 未变化；
4. 该对象未发生删除、状态变化或授权撤销。

**以下情况必须重新判权：**

1. 新的 `memory_id` 首次进入结果集合。
2. 新增关系扩展对象。
3. 新的 `request_id`。
4. 权限版本（`permission_version`）变化。
5. 共享授权撤销或失效。
6. 记忆删除、状态变化或其他使原授权依据失效的事件。
7. 涉及新的 `actor` 或 `action`。

**约束：**

- 复用只发生在**单个请求内**，请求结束即失效。
- **不得将授权结果跨请求复用**，包括同一会话的后续轮次、主动检索的后续调用。
- 缓存命中不等于授权；缓存对象仍须按本节规则判断是否需要重新判权。
- 复用不改变 M05 是唯一权限判定权威这一地位，也不构成对 M05 检查的替代。
- 本节不表示"不在每次读取时进行权限检查"，而是明确检查结果的**有效范围**。

> 本规则与 M01 D20 的两阶段过滤、M02 D8 的缓存策略、M02 D5 的扩展判权要求一致。

## 十一、LLM 记忆接口

权限接口面向 Core 内部模块，聊天 LLM 不直接访问权限数据库。

### 11.1 当前读取流程

```text
QQ 用户
   ↓
Bridge
   ↓
Memory Core
   ↓
M02 Recall
   ↓
M05 权限检查
   ↓
授权后的 Memory Context
   ↓
Bridge
   ↓
DSH / Chat LLM
   ↓
生成回复
```

LLM 只消费经过授权的记忆内容。

### 11.2 未来扩展方向

Memory Core 的对外记忆交互能力不应被限制为单一语义搜索。

未来可以扩展：
- 语义检索。
- 时间线回顾。
- 关联记忆探索。
- 随机记忆抽取。
- 近期记忆读取。
- 记忆候选提交。

第一版只实现聊天所需的 Recall 和 Retain。

> **澄清**：本句界定的是**对外记忆交互能力的范围**，不构成对 DSH 受控主动 Recall 的禁止。DSH 主动调用 `memory_search` 属于 Recall 的一种受控形式（见 M02 D1 / D16、M04 §10.1），M05 对其每一次调用同样执行权限判定，且每次调用均须使用 Bridge 提供的可信身份。上述"未来可以扩展"的能力（时间线回顾、随机抽取、候选提交等）仍不属于第一版范围。

Diary、Dream 的具体工作流不属于 M05，不在本次冻结实现范围内。未来可以独立设计和实现。

## 十二、权限失败与用户反馈

统一采用 Fail Closed：

- 身份缺失：拒绝受保护操作。
- 权限服务异常：拒绝受保护操作。
- 权限数据不一致：暂时拒绝。
- 普通聊天仍可继续，但不注入无法确认权限的记忆。

Bridge 根据 Core 返回的 `reason_code` 生成简短提示。

不得：
- 暴露内部权限规则。
- 暴露其他用户私人内容。
- 通过拒绝消息泄露无权访问的记忆是否存在。
- 在拒绝后继续执行被拒绝的修改操作。

高影响操作被拒绝时，明确告知操作未执行。

## 十三、持久化与备份恢复

### 13.1 职责

- M05 管理授权状态和权限决策。
- M01 负责权限记录的事务性持久化。
- 其他模块不得直接修改权限记录。

### 13.2 恢复规则

- 备份包含权限记录和版本信息。
- **恢复顺序以 M01 D8 为准**（跨模块统一权威流程）。M05 不重复定义完整恢复步骤。
- M05 侧要求：与最新撤销记录核对。
- 无法确认的授权默认拒绝。
- 派生记忆、索引和缓存恢复后重新校验。
- 不允许旧备份恢复已经撤销的授权。
- 权限状态不明确时默认拒绝访问。

## 十四、审计与高影响操作

### 14.1 审计范围

当前为本地单实例运行，不建设多角色审计系统。

审计日志仅供本地 Bot 所有者维护和排查。

建议记录：

- `request_id`
- `actor_id`
- `subject_id`
- `memory_id`
- `scope`
- `action`
- `decision`
- `reason_code`
- `policy_version`
- `timestamp`

权限变更额外记录必要状态摘要。

不记录完整记忆正文、密码或 Token。

日志采用追加式记录，普通插件不得修改或删除。

未来云端或多用户部署时，再扩展审计访问控制。

### 14.2 二次确认

| 操作 | 要求 |
|---|---|
| 普通读取、查看状态 | 正常授权 |
| 敏感读取、修改共享范围 | 留下审计记录 |
| 批量删除 | 本地二次确认 |
| 清空记忆库 | 本地二次确认 |
| 重置全部共享授权 | 本地二次确认 |

QQ 群聊普通消息不能直接触发高影响操作。

## 十五、策略配置

权限策略支持版本化配置。

- 安全硬约束不能由模型修改。
- 普通策略参数可以配置。
- 每次变更生成新策略版本。
- 记录操作者、时间、内容和原因。
- 支持配置校验、灰度应用和回滚。
- 回滚不能恢复已经撤销的授权。

第一版不建设复杂策略管理平台。

## 十六、错误与恢复原则

| 场景 | 处理 |
|---|---|
| Trusted Context 缺失 | 拒绝受保护操作 |
| 成员资格过期 | 拒绝群记忆读取 |
| 权限服务异常 | Fail Closed |
| 权限数据冲突 | 暂时拒绝并记录 |
| Share 授权失败 | 不开放群读取 |
| Revoke 清理失败 | 保持访问阻断，允许重试 |
| 缓存失效失败 | 禁止使用无法确认权限的缓存 |
| 备份恢复无法确认授权 | 默认拒绝 |
| Bridge 返回拒绝 | 不进入后续修改流程 |

普通聊天与记忆访问分离：权限失败不应无故中断普通聊天。

## 十七、测试要求

第一版优先轻量、可追踪的关键路径测试，不建设大型安全压测平台。

### 身份测试
- 正确用户身份。
- 身份缺失。
- 伪造业务参数。
- 所有者身份识别。
- 所有者身份变更。

### Scope 测试
- Private 所有者读取。
- 非所有者读取拒绝。
- Group 成员读取。
- 非成员读取拒绝。
- A 群不能读取 B 群记忆。
- Shared 有效授权读取。
- Shared 撤销后拒绝。

### 操作测试
- 普通成员贡献群记忆。
- 普通成员提交纠正。
- 未授权修改拒绝。
- 未授权删除拒绝。
- 所有者维护操作。
- 高影响操作二次确认。

### 生命周期测试
- 成员退群。
- 群解散。
- Shared 多群授权。
- 单群撤销不影响其他群。
- 撤销与在途 Recall 并发。
- 旧缓存失效。
- 备份恢复不复活旧授权。

### 性能测试
- 普通 Recall 不触发额外 LLM 权限判断。
- 权限过滤使用索引和规则。
- 不对全部记忆进行递归扫描。
- 权限异常不影响普通聊天继续运行。

## 十八、未来扩展边界

以下仅预留扩展方向，不属于第一版实现范围：

- 完整 RBAC。
- 多角色继承。
- 企业组织架构。
- 云端多租户权限。
- 复杂审批工作流。
- Diary / Dream 业务工作流。
- 更丰富的 LLM 主动记忆探索接口。

未来扩展不得破坏当前 `private / group / shared` 的基本语义。
