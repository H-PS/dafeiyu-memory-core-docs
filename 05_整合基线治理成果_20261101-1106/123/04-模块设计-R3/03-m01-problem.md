## P1：必须在相关实现阶段处理

### M01-RT01：版本历史持久化结构

**问题：** D7 生命周期管理与 D24 版本持久化已经明确业务原则，但最终 SQL Schema 尚未确定历史版本的实际保存结构。

**后续任务：**
- 明确当前版本与历史版本的存储方式。
- 明确版本递增和历史追溯规则。
- 确保旧版本不会被普通 Recall 当作当前事实。
- 确保删除和权限撤销不会被历史版本机制绕过。

**完成标准：** Schema 设计通过审查，版本更新、纠正、历史查询和删除测试通过。

### M01-RT02：检索元数据与权限复核

**问题：** D20 已明确 LanceDB 元数据只能用于检索优化，最终权限必须由 M05 判定。

**后续任务：**
- 明确 LanceDB 与 SQLite 的权限元数据字段。
- 明确元数据更新与失效策略。
- 确保检索结果必须经过 SQLite 最新状态和 M05 权限复核。
- 验证旧元数据、过期缓存和撤销授权不能造成越权访问。

**完成标准：** 权限过滤与最终复核链路通过测试，索引元数据不能成为授权依据。

### M01-RT03：删除状态与索引清理顺序

**问题：** D23 已明确删除优先，但需要在实现中确保旧索引清理期间不会重新暴露已删除内容。

**后续任务：**
- 明确 SQLite 删除状态的事务提交顺序。
- 明确 Recall 对删除状态的实时检查。
- 明确 LanceDB、FTS5、缓存和派生索引的清理流程。
- 验证清理失败、重试、重启和索引重建均不会恢复已删除内容。

**完成标准：** 删除状态提交后立即阻断访问；异步清理失败不影响阻断；恢复和重建不会复活已删除记忆。
