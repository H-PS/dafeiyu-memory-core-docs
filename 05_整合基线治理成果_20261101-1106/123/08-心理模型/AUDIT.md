## 三、发现的那个真问题

### 参数失配：emoCap 改了，peakThreshold 没跟着改

**现象**：25 分钟间隔 × 8 次攻击，触发了 **3 次**顶点。但设计上慢节奏不该触发。

**原因链**：

```
emoCap = 0.65（后加的）
  → 单层最大强度 ≈ 0.65 × 0.85 = 0.55
  → 加上 mood 溢出 + A/D 贡献
  → 两次连击就到 0.616
  → 而 peakThreshold 还是 0.60
  → 等于"两次就冲顶"
```

**这是两轮改动叠加造成的**：`emoCap` 是压力测试时加的，`peakThreshold` 是更早定的，没人回头检查两者的关系。

**修复**：`peakThreshold` 从 0.60 → **0.66**。

**验证**：

| 间隔 | 到顶点 |
|---|---|
| 3 分钟 | 第 **3** 次 |
| 10 分钟 | 第 **4** 次 |
| 25 分钟 | **不触发** |
| 60 分钟 | **不触发** |

这正是想要的语义：**密集攻击才崩溃，慢节奏不崩溃。**

### 为什么不是 0.72

试过 0.72，结果 3 分钟间隔要 **6 次**才触发，太钝了。

| 阈值 | 3 分钟间隔 | 25 分钟间隔 |
|---:|---|---|
| 0.60 | 2 次（太敏感） | 触发（错） |
| **0.66** | **3 次** | **不触发** ✓ |
| 0.72 | 6 次（太钝） | 不触发 |

## 四、这次审查的方法论

### 为什么需要它

模型改了十几轮，早期的判断有三种命运：

1. **仍然成立** —— 大部分
2. **已被推翻** —— 当初错了，或后来改坏了
3. **条件变了** —— 当时成立，现在参数改了

**只靠记忆是查不出来的。** 必须写成可执行的断言。

### 怎么写的

每条审查都是 `check(id, claim, fn)`：

```js
check("A5", "负荷 L 会扭曲评估", () => {
  const m1 = createMind(); m1.state.L = 0.1;
  const m2 = createMind(); m2.state.L = 0.9;
  m1.say(weakEvent); m2.say(weakEvent);
  const d1 = Math.abs(readout(m1.state).P);
  const d2 = Math.abs(readout(m2.state).P);
  return {
    verdict: d2 > d1 * 1.5 ? "PASS" : "FAIL",
    detail: `L=0.1 时 ${d1}，L=0.9 时 ${d2}`,
  };
});
```

**关键：`detail` 要带数字。** 否则 FAIL 了也不知道差多少。

### 三态而不是两态

```
PASS   结论仍成立
FAIL   结论被推翻
STALE  条件变了，需重新判断
```

**STALE 这一档很重要**：它区分"错了"和"过时了"。

## 五、已知的不可行项（确认仍不可行）

这些是明确**不该做**的，审查也确认了：

| 项 | 为什么不可行 |
|---|---|
| 让聊天 LLM 标 valence | 循环：情绪影响标注，标注影响召回 |
| 抄 19 个激素变量 | 变量多 ≠ 模型好，只等于难调 |
| 抄小凌的 sigmoid 权重 | 演示值，作者自承"其余是手填的" |
| 用离散标签当状态 | 同一件事会命中 3 个标签，没有裁决依据 |
| 顶点在慢节奏触发 | 崩溃需要密集攻击，慢节奏不崩溃是对的 |

## 六、还没验证的（真实缺口）

审查只覆盖了**代码层面的一致性**，没覆盖：

| 缺口 | 严重度 |
|---|---|
| **没有真实对话语料** | 高——所有测试都是构造的 |
| **没有人类评分** | 高——"像不像人"没人判断过 |
| **LanceDB 未实测** | 中——接口抽象了但没接真库 |
| **embedding 未实测** | 中——用 mock 跑的 |
| **长跑稳定性** | 中——最多跑过 1000 次事件 |
| **多实例并发** | 低——单用户场景够用 |

**这些不是"审查通过"能解决的，需要真实数据。**


2. 某个早期判断不再成立（要更新文档）
