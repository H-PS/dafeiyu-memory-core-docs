# 完整算法：情绪 → 注意力 → 记忆

> 三层一体。情绪算状态，注意力把状态变成「看什么」，记忆按注意力给东西。

---

## 0. 为什么注意力是情绪的一部分

这不是隐喻。**情绪在进化上的首要功能就是分配注意力。**

它不是「心情」，是一套优先级信号系统：什么值得看、什么值得记、什么可以忽略。

三个已被验证的耦合：

| 现象 | 机制 | 出处 |
|---|---|---|
| **隧道视野** | 高唤醒 → 注意范围收窄 | Easterbrook (1959) |
| **情绪一致性** | 负面情绪 → 负面记忆更易激活 | Bower (1981) 联想网络 |
| **唤醒增强固化** | 高唤醒 → 记忆更难遗忘 | McGaugh |

所以架构上：

```
情绪（状态）  ──►  注意力（分配）  ──►  记忆（检索）
   算 P/A/D         算 容量/广度/抑制      按容量给东西
```

**注意力不是检索的优化层，是情绪的输出。**

## 1. 四个注意力量

从 P/A/D/E/L 算出：

### 1.1 容量 capacity —— 倒 U 型

```
capacity = 2 + 3 × exp(−(A − 0.45)² / 0.12)
```

| 唤醒 | 容量 | 状态 |
|---:|---:|---|
| 0.00 | 2.55 | 困倦，装不下 |
| 0.30 | 4.49 | |
| **0.45** | **5.00** | **峰值** |
| 0.75 | 3.42 | |
| 0.90 | 2.55 | 隧道视野 |
| 1.00 | 2.24 | 只看得到威胁 |

**峰值在 0.45 而不是 0.5，是刻意的**：人最专注时不是最兴奋时，是略微平静的时候。

**两端都收窄，但原因不同**：
- 低唤醒：困，装不下
- 高唤醒：只看得到威胁

### 1.2 广度 breadth —— 情绪越强，扩散越远

```
breadth = 0.25 + 0.55 × |P|
```

平静时只想到直接相关的（0.25）；情绪强时「什么都往那上面想」（0.80）。

### 1.3 抑制 inhibition —— 唤醒越高，侧抑制越强

```
inhibition = 0.15 + 0.55 × A
```

高唤醒下注意力集中，不相干的被压掉。

### 1.4 隧道 tunnel —— 高唤醒 + 高负荷

```
tunnel = clamp((A − 0.6) × 2, 0, 1) × clamp(L, 0, 1)
```

**两个条件都要满足**：光是紧张还不够，得同时背着东西。

| 唤醒 | 负荷 | 隧道 |
|---:|---:|---:|
| 0.40 | 0.2 | 0.00 |
| 0.40 | 0.9 | 0.00 |
| 0.85 | 0.2 | 0.10 |
| 0.85 | 0.9 | **0.45** |

隧道 > 0.5 时，只保留最高分的一条。

## 2. 记忆检索：五个步骤

```
候选池
  │
  ▼ ① 情绪一致性加权   ← 必须在选种子之前
  │
  ▼ ② 选种子（前 N 个）
  │
  ▼ ③ 激活扩散（一轮）
  │
  ▼ ④ 侧抑制
  │
  ▼ ⑤ 按容量选
  │
最终结果
```

### ① 情绪一致性加权

```js
同向：score × (1 + 0.7 × |P| × |v|)
反向：score × (1 − 0.45 × |P| × |v|)
中性：不变
```

**必须在选种子之前做。** 这是实际踩过的坑：

> 第一版把情绪一致性放在扩散阶段。但种子是按原始分选的，
> 已经包含了反向记忆，后面怎么修正都来不及。
> 结果：开心时选出的记忆平均效价还是 −0.05。

**为什么反向只减不加，不完全排除？**

难过时偶尔也会想起好事——这叫自我安抚。完全排除会让角色失去复杂性。

### ② 选种子

取加权后分最高的 `capacity / 2` 条。

### ③ 激活扩散（只做一轮）

```js
gain = Σ sim(seed, item) × seed.score × emoFactor
newScore = score + gain × breadth
```

**为什么只做一轮？**

迭代到收敛在心理学上是「联想链」，但工程上会炸：两轮之后几乎所有记忆都被点亮，等于没有注意力。

**一轮 = 「顺带想起一件事」，这正是要的。**

`emoFactor` 同向加成、反向减成——因为文字相似不等于该被想起：

> 「他说明天一定来」和「他上次也这么说结果没来」字面极像，但情绪相反。
> 开心时不该立刻想起那次失约——那叫反刍，不叫联想。

### ④ 侧抑制

```js
final_i = score_i × (1 − inhibition × max_{j≠i}(score_j × overlap_ij))
```

**用 max 不用 sum**：最像的那条才真正抢走注意力，十条都不太像不该累加惩罚。

实测（三条说同一件事）：

| 记忆 | 原始 | 抑制后 |
|---|---:|---:|
| 「他答应陪我看电影后来没去」 | 0.70 | **0.498** |
| 「他答应陪我看电影，后来没去」 | 0.68 | **0.478** |
| 「看电影那次他放我鸽子了」 | 0.65 | 0.630 |
| 「他记得我不吃香菜」 | 0.50 | 0.500 |

### ⑤ 按容量选

```js
cap = round(capacity)
if (tunnel > 0.5) cap = 1        // 隧道
picked = top(cap) 且 score >= minScore
if (picked 为空) 至少给最高分那条  // 不能空手
```

## 3. 完整链路实测

同一批 8 条记忆，不同情绪下的「看见」：

### 开心（P+0.6 A0.6）

```
容量=4  广度=0.58  隧道=0.00
平均效价 +0.60
  [+0.6] 他说他明天一定来
  [+0.7] 我们聊到凌晨三点
  [+0.6] 他帮我修了电脑
  [+0.5] 我们一起吃了火锅
```

**全是正面。** 开心的记不住不开心的事。

### 难过（P−0.7 A0.3）

```
容量=4  广度=0.64  隧道=0.00
平均效价 −0.38
  [-0.7] 他上次也说一定来，结果没来
  [-0.8] 他说我太敏感了
  [-0.6] 他说他很忙，让我别烦他
  [+0.6] 他说他明天一定来        ← 留着一条好的
```

**3 负 1 正。** 难过时也会想起好事，但权重低。

### 焦虑（P−0.6 A0.85 L0.8）

```
容量=3  广度=0.58  隧道=0.40
平均效价 −0.70
  [-0.7] 他上次也说一定来，结果没来
  [-0.8] 他说我太敏感了
  [-0.6] 他说他很忙，让我别烦他
```

**全负面，容量最小。** 焦虑时只剩威胁。

### 平静（P0 A0.45）

```
容量=5  广度=0.25  隧道=0.00
平均效价 −0.16
  好坏混杂，按重要度排
```

## 4. 三层怎么接

```
┌──────────────────────────────────────────┐
│ mind.mjs       情绪状态机                │
│   P/A/D/E/L、needs、trust、peak          │
└────────────────┬─────────────────────────┘
                 │ readout()
                 ▼
┌──────────────────────────────────────────┐
│ attention.mjs  注意力分配                │
│   capacity / breadth / inhibition / tunnel│
└────────────────┬─────────────────────────┘
                 │ 四个量
                 ▼
┌──────────────────────────────────────────┐
│ memory         记忆检索（待实现）        │
│   情绪一致 → 扩散 → 抑制 → 容量          │
└────────────────┬─────────────────────────┘
                 │ 选中的记忆
                 ▼
┌──────────────────────────────────────────┐
│ pipeline.mjs   管线组装                  │
│   compose({ persona, memory, ... })      │
└──────────────────────────────────────────┘
```

### 接入点

`pipeline.mjs` 的第 5 站（compose）之前：

```js
// 站 3 之后，站 5 之前
const att = allocateAttention(pipe.state)
const recalled = focus(memoryPool, pipe.state)
const ctx = pipe.receive(text)
ctx.assemble({
  persona,
  memory: formatMemories(recalled.picked),
})
```

**关键：`focus()` 和 `compose()` 必须用同一个 state。** 否则会出现「心情说低落，但召回的是开心记忆」。

## 5. 参数表

| 参数 | 默认 | 作用 |
|---|---:|---|
| capacity 基数 | 2 | 最低容量 |
| capacity 峰值 | 5 | 最高容量 |
| capacity 峰位 | 0.45 | 倒 U 的顶点 |
| breadth 基数 | 0.25 | 平静时的扩散 |
| breadth 增益 | 0.55 | 情绪强度的放大 |
| inhibition 基数 | 0.15 | 最低抑制 |
| inhibition 增益 | 0.55 | 唤醒的放大 |
| tunnel 阈值 | 0.6 | 开始收窄的唤醒 |
| 情绪一致 同向 | +0.7 | |
| 情绪一致 反向 | −0.45 | |
| 扩散 同向 | +0.6 | |
| 扩散 反向 | −0.5 | |
| 侧抑制 max | — | 用 max 不用 sum |

## 6. 已知限制

| 限制 | 影响 | 补救 |
|---|---|---|
| 相似度是字符二元组 | 同义词匹配不上 | 接受，或加同义词表 |
| 容量是连续值 | 实际得取整 | 已处理 |
| 扩散只做一轮 | 联想链短 | 刻意设计，避免全点亮 |
| 隧道是硬阈值 | 0.5 处突变 | 可改成渐变压条数 |

## 7. 和 Letta 的差异

| | Letta (MemGPT) | 本方案 |
|---|---|---|
| 记忆 | 分层 + 模型自我编辑 | 衰减 + 召回竞争 |
| 情绪 | 记忆的标签 | **独立运行时状态** |
| 注意力 | 模型的上下文管理 | **从情绪算出来的量** |
| 遗忘 | 模型主动决定 | 半衰期自动 |
| 谁改状态 | 模型可以改写 | **模型不能改** |

**核心差异：Letta 把情绪当内容，我们把情绪当状态。**

前者模型能改写，后者不能。这决定了注意力必须是**从状态算出来的**，不是模型自己决定的。
