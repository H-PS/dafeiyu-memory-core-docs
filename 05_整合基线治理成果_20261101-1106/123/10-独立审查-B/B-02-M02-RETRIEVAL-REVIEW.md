## 0. 阶段结论

1. **M02 框架方向正确，但存在 3 处结构性缺口**，使若干算法决策在框架层无法被正确做出。〔推导〕
2. **B-023（P1）**：D4 五因素中「记忆重要性」「证据可靠性」**在 M01 无字段承载**；importance 在 PSYCH 有实现，reliability 确认无。〔事实〕
3. **B-011 M02 部分（P1）**：M02 全文不提 embedding/维度/索引空间（grep 零命中），**查询侧模型路由跨模块无人拥有**。〔事实〕
4. **B-012（P1）**：M02 不假设有摘要（`摘要`/`cue` 零命中）；但投影差异影响无规则。**RRF 归因已按原文更正**（见 §5.3）。〔事实〕
5. **B-004（P1）**：M02 全文无 RRF 公式、无 k、无 depth、无权重（`k=60` 零命中）；k=60 仅在**寄存器 D-OK-19**，不在 M02、不在台账。〔事实〕
6. **B-013（P1）**：三处衰减**非同一算法、非冲突算法**，是不同职责；但 **PSYCH 保真度折扣直接乘检索分数（×0.25–1.00），与 `F(t)` 同属排序影响 → 双重打折风险**。〔推导〕
7. **B-027（P1，新增）**：**RRF 与 `F(t)` 不存在必然的数学互斥，但当前设计没有定义两者的组合位置、权重语义和排序保证，存在尺度不一致及重复衰减风险**；D3 与 D4 职责边界亦未定义。〔推导〕
8. **B-028（P1，新增）**：`focus()` 的代码形态**具有完整候选处理与最终选择能力**〔事实〕；与 X-1 的 delta-only 约束**存在接口职责冲突风险**〔推导〕——**须区分"函数本身有最终选择能力"（事实）与"系统集成时是否让它接管最终排序权"（尚未发生、且 X-1 已禁止）**。
9. **本阶段未发现"应当立即替换"的组件**。RRF、四渠道、四项预算、分层扩展均为合理选择。〔推导〕
10. **未引用任何性能数字**；外部证据全部为原始论文/官方文档。

## 3. 十类算法逐项审查

> 每项给出：机制与依据 → 局限/失败模式 → 替代方案 → 结论。完整成本表见 §4.8。

### 3.1 关键词检索

- **机制**〔事实〕：D3 L88 仅一句「SQLite FTS5｜精确关键词、名称、数字、型号」。无分词器、无排序函数、无权重。
- **局限**〔设计缺口〕：① **中文分词是前置条件**——FTS5 分词器为**建表选项**，更换需重建表；默认 `unicode61` 对无空格中文切分不当（官方核实）。M01 已识别（§十 开放项 3），**M02 未识别**。② **无 BM25 参数声明**（B-024）。③ 无同义词扩展。
- **替代**：BM25（**实际已内建**，§4.1）、trigram 分词器、外部分词器。
- **结论**：维持 FTS5；须补分词器选型登记 + BM25 参数登记。

### 3.2 向量检索

- **机制**〔事实〕：D3 L87 仅一句「LanceDB 向量检索｜语义相似度和模糊关联」。无模型、无维度、无度量、无阈值。
- **局限**〔设计缺口〕：① **模型依赖强**——换模型即换语义空间（阶段 1 B-010/B-011）；② 对数字/型号/人名不敏感（FTS5 强项，二者互补）；③ **D21 四档置信度无相似度→档位的映射规则**（L670–673）；④ **无查询向量生成规则**（B-011）。
- **替代**：不同 embedding 模型族（**本审查不推荐任何具体模型**，§4.2）。
- **结论**：维持向量为主力；**须先补 B-011 查询侧路由**，否则换模型无安全路径。

### 3.3 混合检索

- **机制**〔事实〕：D3 四渠道互补 + RRF（L92）；D1 两阶段共用检索服务（L61）；L94「保留各渠道原始分数、排名和来源」。
- **优点**〔推导〕：四渠道正交合理（向量管语义、FTS 管精确、结构化管条件、关系管联想）；**保留原始分数为后续评估留了数据**，是良好实践。
- **局限**〔设计缺口〕：① 融合层未设计（无公式/k/权重，B-004）；② **渠道失效时融合是否退化为单路未定义**（D9 说"向量失败→用 FTS+结构化"，但未说融合形态；Matrix C26 F4 说"退单路"，M02 未写）；③ 候选集不同时的偏差（§5.3）。
- **结论**：**采用，且不应简化掉任何一路**（关系扩展可延后）。

### 3.4 重排序

- **机制**〔事实〕：D4 L108「第一版以规则排序为主，**暂不引入 Cross-Encoder 或额外 LLM 重排序**，但保留后续升级空间」。
- **局限**〔推导〕：引入即增加推理延迟与成本，与宗旨"节省 Token"需权衡；需模型托管，触及 D-AP-09 隐私边界；**当前无评估基线**。
- **替代**：Cross-Encoder（§4.4）；LLM 重排（M02 明确暂不引入）。
- **结论**：**不采用，本审查明确支持该决定**。理由：无自有测试集证明基线不足（D-AP-06）；Matrix C28 已设计为"失败跳过"可选项，**架构已留位，延后无损失**。

### 3.5 时间衰减

- **机制**〔事实〕：D23 L688–721。`S_final = S_vector × F(t)`（L702）；**明确标注"该公式仅为初步研究方向，不是最终算法"**（L711）；五项暂不冻结（L713–719）。
- **★ 结构问题**〔推导〕：`S_vector × F(t)` 是**分数级**运算，而 D3 用 RRF（按名次融合）。**`F(t)` 的作用位置（RRF 之前/之后/作为独立一路）m02 未定义**：若在 RRF 之前但排序已完成，则对名次无影响；若在之前且重新排序，则会改变名次；若在之后相乘，则定义良好但量纲不同、时间因子可能主导。**三种顺序结果不同，而设计未指定**。→ 详见 **B-027**。
- **三处定义**：见 §5.5（B-013）。
- **结论**：应延后（D23 自述"不是最终算法"），但**须先定义 `F(t)` 与 RRF 的组合位置与语义**。

### 3.6 重要性权重

- **机制**〔事实〕：D4 L104「记忆重要性：记忆本身的重要程度」。**无定义、无来源、无取值、无算法**。
- **★ 核心问题**〔事实〕：`m01.md` 全文 `importance|重要性|score|评分` **仅 1 处命中**（L1092，且是"M03 负责评分与路由"的职责声明）；M01 D19 向量记录（L449–460）**无 importance 字段**。M03 的 R/P/E/T/U（§6.2 L158 `S = 0.25R+0.20P+0.25E+0.15T+0.15U`）是**提取期候选价值**（"值不值得存"，一次性），**非检索期记忆属性**（"排序时有多重"，需持续维护）——语义与生命周期均不同。
- **PSYCH 侧**〔事实〕：`memory.mjs` 有完整实现（`initialImportance` L171–188 + `effectiveImportance` L206–215，后者用 `recallCount` 做边际递减），**但 M01 无字段承载**。
- **替代**：① 复用 M03 的 `S`（**语义不匹配，不推荐**）；② M04 整合期赋值 + M01 持久化（**跨模块新增字段**）；③ "重复提及"代理（D25 L744 提及，但**判定口径归 M03 §8**，语义弱）。
- **结论**：见 **B-023**。**reliability 确认无任何实现**（`memory.mjs` 无 confidence 字段；`m02.md` D12（L527–530）的 `Explicit/Inferred/Uncertain/Corrected` 是**类别标签**非连续分数）。

### 3.7 相关性评分

- **机制**〔事实〕：D4 L102「相关性：与当前聊天内容的匹配程度」，无定义；D21 L664–666 保留"匹配强度和置信度"，四档（L670–673）。
- **局限**〔设计缺口〕：① **四渠道无统一量纲**（余弦 0–1、BM25 无界、结构化布尔、关系跳数），**不可直接比较**——这正是 RRF 存在的理由；② **但 RRF 之后如何再叠加"相关性"未定义**，若已融合排名则 D4 的"相关性"与 RRF **重复计分**；③ 置信度四档**无映射规则**。
- **结论**：见 **B-027**（D3/D4 职责边界）。

### 3.8 上下文预算

- **机制**〔事实〕：D7 L413–430 四项预算（候选数量/最终返回/Token/关联扩展）；L424「必须有硬性上限」；L426「先去重、排序，再选择」；L430 数值待实测。
- **优点**〔推导〕：**本模块相对最完整的一节**。四项正交、各有明确对象；"不为了填满 Token 预算而继续搜索"（L658）与宗旨完全一致。
- **局限**〔设计缺口〕：① **"根据问题复杂程度动态分配"无度量规则**；② 四项预算相互关系未定义；③ **无降级优先级**（预算不足时先砍哪项）。
- **结论**：**采用，且应列为 V1 必做**（缺此则上下文成本失控）。

### 3.9 多路召回融合

- **机制**〔事实〕：D3 L92「通过 RRF 融合」；L96「具体权重、候选数量和关联深度**暂不固定**」。依据链：Matrix C26（FusionStrategy L1）、M04 D15 L1128、Pluggable §三 L68 示例、**寄存器 D-OK-19**。
- **优点**〔推导〕：RRF 只用排名，**正好解决四渠道量纲不可比**——技术选择正确。
- **★ 五处缺口**〔设计缺口〕：① **无公式**；② **无 k 值**（全文零命中，仅在寄存器）；③ **无候选深度 depth**（直接决定 k 的相对影响）；④ **无权重**（四路是否等权）；⑤ **无"候选集不同"的处理规则**。
- **结论**：**采用 RRF 方向**（正确），但须补齐五缺口；**k=60 不得默认视为已批准**（B-004）。

### 3.10 去重与冲突处理

- **机制**〔事实〕：**D13**（L540–546）同 `memory_id` 多渠道命中需去重并保留各渠道排名分数；语义相似可在上下文构建阶段减少重复但**不能删除正式记忆**；**时间不同/状态变化不能简单视为重复**。**D17**（L605–613）优先当前有效；冲突保留差异、结合时间与来源；**检索不改变正式记忆**，只能形成反馈交 M03/M04。
- **优点**〔推导〕：**设计清醒**——明确区分"去重（上下文层）"与"删除（权威层）"（L544），明确"时间不同≠重复"（L546），避免了记忆系统最常见错误（把状态变化误判为重复而丢历史）。
- **局限**〔设计缺口〕：① **"语义相似"如何判定未定义**（用何相似度、何阈值？若用向量则回到 B-011）；② **去重与 PSYCH 侧抑制/去重的关系未定义**（§6.2）；③ **冲突检测无算法**（D17 只说"保留差异"，未说如何发现）；④ **去重相对融合的位置未定义**（m02 未写去重在融合前还是后）〔推导〕，故**去重后排名如何处理亦未定**。
- **替代**：MMR（§4.6，**不建议**）；`memory_id` 确定性去重（**建议作 V1 基线**）。
- **结论**：**确定性去重应立即采用**；语义去重**延后**（依赖 B-011）。

## 4. 替代方案比较

> 证据等级：**A** 原始论文/官方文档可核实｜**B** 权威二手｜**C** 工程实践｜**D** 证据不足。**本表不含任何性能数字。**

### 4.1 BM25

| 项目 | 内容 |
|---|---|
| **结论** | **不是"是否采用"的问题——它已经在用。** FTS5 内建 `bm25()`，`rank` 列默认映射到它；D3 的"FTS5 精确关键词"实际返回的就是 BM25 排名 |
| **依据** | SQLite FTS5 官方文档 §5.1.1（核实 2026-11-03）：`bm25()` 为内建辅助函数；`rank` 默认 = `bm25()`；**k1=1.2、b=0.75 硬编码不可配置**；支持列权重 `bm25(ft, 10.0, 5.0)` |
| **收益** | 零额外收益（已内建）；零计算/存储代价 |

### 4.5 RRF

| 项目 | 内容 |
|---|---|
| **结论** | **采用，且是当前最优选择**；但须补齐 M02 的五处缺口（§3.9） |
| **依据** | **Cormack, Clarke, Buettcher. SIGIR '09, pp.758–759.** DOI [10.1145/1571941.1572114](https://dx.doi.org/10.1145/1571941.1572114)。**本阶段已下载全文 PDF（66,196 B）并抽取文本逐字核对**，摘录归档于 `_B-REVIEW-BACKUPS\RRF-PAPER-EXCERPT-20261103.txt` |
| **收益** | 只用排名，绕开归一化——正好匹配四渠道量纲不可比 |
| **代价** | 可忽略（每路每候选一次加法） |
| **限制** | 见下"原文核对"三条 |
| **影响** | 无接口影响、无迁移成本 |
| **证据等级** | **A** |

**原文逐字核对（本阶段最重要取证）**

> Given a set D of documents to be ranked and a set of rankings R, **each a permutation on 1..|D|**, we compute RRFscore(d ∈ D) = Σ_{r ∈ R} 1/(k + r(d)); **where k = 60 was fixed during a pilot investigation and not altered during subsequent validation.**

- 〔事实〕**原文设定为 `each a permutation on 1..|D|`**——每个 ranking 都是对**同一文档集 D** 的完整排列。**论文未定义"文档缺失于某列表"的处理规则**，因为其设定中不存在缺失。
- 〔事实〕原文 k 的作用：「The constant k **mitigates the impact of high rankings by outlier systems**」。
- 〔事实〕原文 k 敏感性：「The results of the first… indicated that **k = 60 was near-optimal, but that the choice was not critical**」。
- 〔事实〕原文实验材料：「the individual rankings in these experiments were exactly those submitted by TREC participants」——**各系统对同一语料库的完整排序**，故 permutation 假设成立。

**k 的作用**〔推导〕：k 越小 → `1/(k+rank)` 衰减越快 → 头部更集中；k 越大 → 越平滑。k=60 时 rank=1 与 rank=10 贡献比为 `61:70`（约 1.15 倍，**本审查自行计算**）。

**k 的结论**〔推导〕：k=60 **有原始论文依据**（先导实验 near-optimal + 不敏感），可作**合理默认起点**；但**不得称"最优"或"已批准"**（B-004）；更**不得**把论文的"not critical"外推到本系统——**M02 的 depth 未定义，而 k 的相对影响与 depth 强相关**（depth 越小 k 影响越大）。

### 5.5 B-013：时间衰减三处定义

**逐字核对结果：三处是不同层次，非同一算法不同描述，也非三个冲突算法。**〔事实〕

| 出处 | 原文要点 | 作用对象 | 输出 | 状态 |
|---|---|---|---|---|
| **M02 D23**（L688–721） | `S_final = S_vector × F(t)`；「**仅为初步研究方向，不是最终算法**」；五项暂不冻结 | **检索排序权重** | 排序分数 | **未冻结** |
| **PSYCH §6.2**（L216–233） | detail 12 / affect 60 / meaning 900 天；输出保真度 full/gist/trace/faded；§6.3 保真度决定措辞 | **记忆保真度**（"还能记起多少细节"） | 保真度档位 + **措辞** | 设计完整，**验证全为构造数据**（B-014） |
| **Roadmap Phase C**（L112） | 「衰减 v2（分变量）」列为**可选升级**，独立开关，A/B 达标才保留 | 同 PSYCH 分变量思路 | — | **未裁决、未排期** |

**性质判定**：
1. **M02 D23 与 PSYCH §六 的语义不同**〔推导〕：前者答"该排多前"（基于记忆年龄的排序权重），后者答"还记得多清楚"（基于三侧面的保真度，并驱动措辞）。**二者概念上可以并存。**
2. **但两者都能影响检索排序（B-013 实质）**〔事实〕：`RETRIEVAL.md` §五 L119–126 与 `attention.mjs` L542–550 明确——保真度折扣**直接乘在 `score` 上**：`detail≥0.5→×1.00`、`≥0.18→×0.85`、`affect≥0.25||meaning≥0.35→×0.60`、`否则→×0.25`。**即 PSYCH 衰减既影响措辞、也影响排序。**
3. **准确表述**：**PSYCH 保真度折扣与 M02 `F(t)` 均能影响检索排序。两者语义不必然相同，但若同时启用，需要明确作用对象、计算顺序和权重，避免同一衰减效应被重复计算。** 〔推导〕——**不得**未经分析将两者认定为同一变量（前者是保真度、后者是时间权重），**也不得**提前替用户二选一。
4. **Roadmap Phase C 的「衰减 v2」**〔事实〕：是升级项，与 PSYCH §六 同源。**若未来采纳，需明确它替换 `F(t)`、替换 PSYCH 保真度、还是二者都替换——当前无任何文档说明。**

**本审查不选择任何一处作为权威定义**（任务明确禁止）。**B-013 保留，性质从"权威归属不明"精确化为"组合规则缺失 + 未来升级项归属未定"。**

**另注（与 D-AP-05）**〔事实〕：台账 D-AP-05 明确「last_retrieved **不得**作为衰减 v2 的正向权重输入」。M02 D23 当前未违反（未提该字段），但**未来实现衰减 v2 时必须遵守**（避免"被检索过→衰减更慢"的自我强化循环）。

## 6. 与 PSYCH 七步链的关系

### 6.1 七步链原文（PSYCH §六 L188–199）

`① 时间衰减（细节没了→打折；faded→过滤）→ ② 干扰 → ③ 情绪一致性 → ④ 激活扩散（一轮）→ ⑤ 侧抑制 → ⑥ 去重 → ⑦ 按容量选（+反向保底槽位）`

**PSYCH 明确的操作顺序理由**（L201–214）：衰减必须在情绪一致之前；去重必须在侧抑制之后（"两条相似度 0.533 的记忆，侧抑制后都是 0.811——分不出胜负"）。

### 6.2 与 M02 的职责对照

| 七步 | M02 对应 | 关系 | 标签 |
|---|---|---|---|
| ① 时间衰减 | **D23**（`S_vector×F(t)`，未冻结） | **★ 功能重叠**（PSYCH 还额外做 faded 过滤，M02 无） | 〔推导〕 |
| ② 干扰 | 无 | PSYCH 独有 | 〔事实〕 |
| ③ 情绪一致性 | 无（`心理`/`情绪` 零命中） | PSYCH 独有 | 〔事实〕 |
| ④ 激活扩散 | 无 | PSYCH 独有 | 〔事实〕 |
| ⑤ 侧抑制 | 无 | PSYCH 独有 | 〔事实〕 |
| ⑥ 去重 | **D13** | **★ 功能重叠** | 〔推导〕 |

### 6.4 重复排序/加权/隐式改变路径

#### B-027｜M02｜P1｜RRF 与 `F(t)` 的组合位置、权重语义与排序保证未定义

| 项目 | 内容 |
|---|---|
| **问题描述** | **不存在必然的数学互斥，但当前设计没有定义两者的组合位置、权重语义和排序保证，存在尺度不一致及重复衰减风险。** 具体：**①** D23 的 `S_final = S_vector × F(t)` 是**分数级**运算，而 D3 规定融合用 RRF（按名次融合）。`F(t)` 究竟作用于「进入 RRF 之前的分渠道排序」还是「RRF 之后的融合分」，m02 **未规定**。**②** 若在 RRF 之前乘 `F(t)` 但排序已在乘法之前完成，则 `F(t)` 对名次无影响；若在乘法之后重新排序，则 `F(t)` 会改变名次——**两种执行顺序产生不同结果，而 m02 未指定是哪种**。**③** 若在 RRF 之后乘 `F(t)`，数学上定义良好（乘积仍可比较），但 RRF 分数量级（k=60 时每路约 0.01–0.03，多路求和后仍为小量）与 `F(t)`（通常 0–1）**量纲不同**，直接相乘会使时间因子主导排序。**④** D3（RRF 融合）与 D4（五因素排序）的**先后与职责未定义**：若 RRF 已产出融合排名，D4 的「相关性」因素即可能重复计分 |

| **技术影响** | 时间衰减能否生效、五因素排序能否生效，取决于组合位置的选定；若未定义即实现，**同一设计意图可能因执行顺序不同而得到不同排序结果，且差异不易察觉** |
| **限制** | **未实测**；上述为基于 RRF 定义与 m02 原文的推导。**`F(t)` 的具体形式本就未冻结（D23 五项暂不冻结）**，故无法进一步量化影响。**效果层面完全未验证**（M02 §十 开放项 6） |

| **建议方向** | 以下为**可选路线，本审查不选定**：<br>**a) 分数级融合**：放弃 RRF 改加权分数融合（需先解决四渠道归一化）<br>**b) RRF 之后作后置重排因子**：对融合排名而非融合分做调整<br>**c) RRF 之前分渠道乘 `F(t)` 并重排**：需明确「重排发生在乘法之后」<br>**d) 时间作为独立一路排名**：把时间新鲜度名次化后并入 RRF（数学上与其他路同构，但需定义新鲜度的排名规则）<br>**e) V1 不做连续衰减**，仅硬过滤<br>**审查倾向**：**b 或 e** 代价最低、语义最清晰；但**最终取决于用户对 V1 衰减范围的决定** |

## 10. 技术建议

### 10.1 阶段重点问题回答

**Q1：当前检索设计是否存在明显性能或质量瓶颈？**

**质量瓶颈三处（均为设计缺口，非性能问题）**〔推导〕：① **融合层未设计**（§3.9 五缺口）——四路召回缺少明确的合并规则，**当前最主要的质量缺口**；② **五因素中两项无数据源**（B-023）——排序实际只有三因素；③ **`F(t)` 与 RRF 的组合位置未定义**（B-027）——时间因素能否生效取决于尚未选定的组合方式，**效果未验证**。

**性能瓶颈**：**当前无法评估**〔无法核实〕。M02 §十 开放项 6 明确"真实聊天场景下的召回准确率与上下文成本"未测。**本审查不提供任何性能数字。**

**Q2：是否有算法可以低成本替换？**

**有一处，方向是"简化"而非"替换"**〔建议〕：把 D4 五因素中的 importance/reliability **显式标注为 V1 不参与排序**（B-023 方案 a），V1 排序用三因素。**文档调整成本低，但后续实现、字段调整和测试仍有成本**——具体包括：① 需在 M02/M01 文档中显式声明"不参与"，避免实现者自行发明字段；② 若未来启用 importance，仍需 M01 字段设计与 M04 更新责任定义；③ D10 的三因素排序效果**仍需测试验证**。其余无需替换——RRF、四渠道、四项预算、分层扩展都是合理选择。

**Q3：哪些算法需要组合而非互相替代？**

| 组合 | 为什么不能互相替代 |
|---|---|
| **向量 + FTS5** | 正交：向量管语义（换说法），FTS 管精确（型号/数字/人名）。M01 D21 L518–524 与 D3 L87–88 已明确分工 |
| **结构化 + 语义** | 结构化管"什么时候"（时间条件），语义管"是什么"。D14 L552 已明确 |
| **预算 + 排序** | 排序决定"谁优先"，预算决定"要几个"。D20 L658"信息足够即停"须靠预算实现 |
| **RRF + 去重** | 二者功能不同（融合合并多路视角、去重消除同对象重复），但**执行顺序在 m02 中并未完整定义**——见下 |

**执行顺序的准确定位（依 m02 原文，区分已定义与未定义）**：

| 步骤 | m02 是否定义 | 原文依据 |
|---|---|---|
| **跨渠道归并**（同一 `memory_id` 多路命中合并为一条） | ✅ **已定义**（去重时保留各渠道排名与分数） | D13 L540–546 |
| **融合（RRF）** | ✅ 已定义为"多渠道结果通过 RRF 融合" | D3 L92 |
| **融合与去重的先后** | ❌ **未定义** | D3 L92 与 D13 L540–546 **均未说明二者先后**；D7 L426 只说"先去重、排序，再选择"，**未提及融合在去重之前还是之后** |
| **去重与排序的先后** | ✅ **已定义**：先去重、再排序 | D7 L426「先去重、排序，再选择最终结果」 |
| **预算裁减** | ✅ 已定义为最后一步 | D7 L426「再选择最终结果」；四项预算见 L417–422 |

**→ 结论**：**"去重→排序→预算"三步顺序已定义；"RRF 融合与去重"的先后未定义**。这会影响去重的判定基准（对原始多路候选去重，还是对融合后列表去重），属 **B-004 五缺口之一（候选集规则）的具体表现**。

**Q4：如何避免上下文注入过多？**

M02 已有**四层防线**〔事实〕：① D2 触发范围；② D7 四项预算（含硬性上限）；③ D20 少而准（"准确性优先于相关性，相关性优先于完整性，完整性优先于数量"，L651–653）；④ D21 置信度四档（低置信度不进普通上下文）。

**但"预算动态分配"和"实际效果"尚未验证**〔设计缺口〕：D7 L424 只写"根据当前问题复杂程度动态分配"，**无度量规则**；D7 L430 明确"具体数值通过实际聊天测试确定"，**即数值与效果均未验证**。建议补：**问题复杂度→预算档位**的简单映射（如按查询长度/触发类型分 2–3 档），**不需要复杂模型**；并在 D10 评估中记录各档位的实际注入量与召回率。

**Q5：如何保持检索结果的可解释性？**

**已具备良好基础**〔事实〕：D3 L94「保留各渠道的原始分数、排名和来源信息」；D19 明确 Core 内部保留来源/时间/权限/版本（L643）。

export function initialImportance(ev, opts = {}) {

### 13.4 B-013 修正：衰减有**两套实现**，且已实测分离

**§5.5 曾判"三处衰减是不同职责"。代码核验后需进一步精确化。**

`decay.mjs` 实际实现：

| 侧面 | 半衰期 | 初值来源（`buildMemory` L329–331） |
|---|---|---|
| `detail` | 12 天 | 固定 `1.0` |
| `affect` | 60 天 | `Math.abs(valence)` |
| `meaning` | 900 天 | `initialImportance()` |

且**按 `kind` 有调制系数**（`KIND_MODIFIER` L56–63）：promise 的 meaning 半衰期 ×8，chat 的 ×0.5。

**关键发现（`RETRIEVAL.md` §五 L119–126）**：保真度**不仅影响措辞，还直接乘在检索分数上**：

```js
detail >= 0.5                      → ×1.00
detail >= 0.18                     → ×0.85
affect >= 0.25 || meaning >= 0.35  → ×0.60
否则                                → ×0.25
```

**→ 这直接回答了 §5.5 的疑问**〔事实〕：PSYCH 衰减**既影响措辞、也影响排序分数**。因此：

- **二者同属"时间/遗忘相关的分数衰减"这一功能类别，都能影响排序，但不是同一变量的两种实现**：`F(t)` 乘在 `S_vector`（向量语义相似度）上、属 M02 融合排序层；PSYCH 折扣乘在候选池分数上、属 `focus()` 内部管线，且其值是经 `kind` 调制半衰期后的 detail/affect/meaning 三变量分档（`decay.mjs` L56–63），**不是时间的单调函数**。**若同时作用于同一分数流，衰减效应将叠加**。
- **B-013 性质升级**：不是"组合规则缺失"，而是**"存在两套都会影响排序的衰减实现，若同时接入将双重打折"**。
- **修正后建议**：**V1 只允许一套衰减作用于排序**。二选一（**本审查不选定**）：
  - **选 PSYCH**：有代码、有 `kind` 调制、有保真度档位（可驱动措辞），比 `F(t)` 抽象更完整；
  - **选 M02 的 `F(t)`**：更简单，但需自行实现，且 PSYCH 保真度仍会通过措辞影响输出。
