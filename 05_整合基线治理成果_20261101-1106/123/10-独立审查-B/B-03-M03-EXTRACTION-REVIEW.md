## 3. 十类算法审查结果

### 3.1 提取方式

- **现状**〔事实〕：L23「模型负责理解和提出候选」、L24「Core 负责确定性校验、评分计算和候选分流」——职责分工明确。但**候选如何从对话中生成**（触发条件、抽取规范/提示词结构、单批次候选上限）全文无定义；L65 只说"异步批量处理，不对每条消息单独调用模型"。〔设计缺口→B-030〕
- **同一信息重复提取**〔事实〕：§8 规则 1/5 要求批内合并、关联同一候选；跨批次由 M04 去重（L305）。方向明确，但**合并算法与批间信号承载缺失**（→B-032）。
- **规则与 LLM 边界**：L394 Schema 校验＋确定性检查、L338 Core 重算——**校验侧规则明确**；**提取侧全靠模型**，无规则预筛。外部证据：规则+语义混合分工有领域先例（Chiticariu EMNLP 2013；Sarawagi 2008 综述，均 A 级）。〔事实〕

### 3.2 候选生成

- **范围**：仅当前批次（L67）；跨轮次信息不加载，历史比较归 M04（L69）。〔事实〕
- **上下文不足/指代不明**：claim_type=uncertain 可表达（L113）；但**指代消解无设计**（→B-036）。〔设计缺口〕
- **数量上限与成本控制**：无单批次候选上限、无成本参数（§11 配置表 L348–360 只有权重/阈值/暂存项）。〔设计缺口→B-030〕
- **生成失败**：§12 L380–382 任务可恢复/失败不视为成功/重试幂等——**故障处理完整**；但"模型输出无效（Schema 不过）"的重试上限与丢弃策略未定义（L390"有限重试"无数值，§14 L434 列为待定参数）。〔依赖实现〕

### 3.3 事实与事件区分

- **类型体系**〔事实〕：7 种 kind（L86–94）+ 3 种 claim_type（L109–113）+ §6.5 类型化评价重点（L230–238）——分类框架存在。
- **可执行性**〔设计缺口〕：无判定树/关键词映射/推理链。例："我下周可能去北京"归 plan/goal/state/event 无规则可循（子代理 A 案例）。且 **M03 7 类 → M04 memory_type(fact/event 两类) 的映射未定义**（m04 L101），preference/plan/goal/relationship/state 落库形态悬空（→B-037）。
- **短期事件误提取为长期事实**：L96「记忆类型…不直接决定永久保存期限」+ state 类"需要考虑时效"（L102）——**有意识**；但判定靠模型，无规则护栏。〔推导〕
- **假设误记为事实**：claim_type=inferred/uncertain 约束（L117–118）针对此；但判定者是模型（→B-034）。

### 3.4 实体识别

- **全文唯一相关条目**是 L122 否定性约束「不允许仅凭语义相似度把不同主体、不同人物或不同关系合并」——**无识别、别名、指代消解、合并的任何能力设计**。〔事实〕
- 责任归属：M02 D15 L556–562「优先使用已有实体和 Relation 数据」「M02 不负责创建或修改实体」——只消费不创建；M04 无实体层（其 Relation L309–328 是记忆间关系，非人物实体）。→ **实体识别全链路无 owner**（→B-036）。外部证据：同名实体消歧是实体链接领域公认核心问题（Shen/Wang/Han, IEEE TKDE 2015, A 级）——L122 的谨慎有文献依据，但"不合并"不等于"能识别"。〔事实〕

### 3.5 时间信息处理

- **输入有 event_time（L43），候选结构无任何时间字段**（L316–333）。〔事实〕
- §8 规则 6 要求"证据累计必须保留来源引用和时间信息"（L292）——**要求存在、载体不存在**。M04 侧 Fact/Event 有 valid_from/valid_to/recorded_at（m04 L104–106），但 **valid_from 的取值来源未定义**；m04 全文 grep 相对时间/模糊时间 = 0 命中；m02 D14（L548–552）只覆盖查询侧。→ **写入侧时间链路三文档均未定义**：相对时间解析、时间缺失保守策略、持续状态 vs 一次性事件均无归属（→B-035）。〔设计缺口〕
- 外部证据：相对时间标准化有成熟方案（dateparser 活跃维护、Duckling 未归档但低频、HeidelTime 约 3 年半未更新——维护风险，均 A 级核实）。〔事实〕

### 3.6 重要性判断

- **M03 的"重要性"= 五维加权和 S**（L158），用于**准入分流**（L246–252）；评分主体是模型（L337），Core 只重算。〔事实〕
- **三重同名异义**〔事实+推导〕：① M03 S（准入分，0–5，Core 重算）；② M02 D4"记忆重要性"（**检索排序**因素，m02 L104，无维度分解、无数据来源）；③ PSYCH importance（0.05–1，情绪驱动，函数级实现但**未被检索链调用**）。三者语义、时机、消费方均不同，**不能混用**；M02 引用的字段全链路无 owner（→B-023 更新）。
- **高频提及≠高重要性**：L130 明文「评估不能只依赖重复次数」；§6.1 与 §8 L294 一致。〔事实〕**设计态度正确**；但**重复次数根本没有字段承载**（→B-032），所以该原则当前无从违规也无从执行。
- **可解释性**：五维各有 0–5 语义锚（L164–209）＋ scoring.version 可追溯（L360）——**评分可解释性设计良好**。〔事实〕

### 3.7 信息置信度

- **claim_type 三值枚举是类别标签，非连续置信度分数**——M03 不产出数值型 reliability/confidence。〔事实〕M04 侧 Fact/Event 有 confidence 字段（m04 L108），但其**推导规则（claim_type×E 维×证据累计→数值）无任何文档定义**。〔设计缺口〕
- **低置信度处理**：§7.2 暂存观察保留 inferred/uncertain 属性（L260）、L118 uncertain 不得直接写入——**有明确约束**。〔事实〕
- **推测写成事实的防线**：见 §3.10 与 B-034——**防线存在缺口**。

### 3.8 重复候选识别

- **概念区分**〔事实〕：§8 规则 1（批内合并证据）vs 规则 5（关联同一候选）vs M04 去重（L305）——三个层次存在；但**规则 5 未限定"同一批次"**，而 M03 不加载历史（L67），文字上越界到 M04 职责（→B-032）。
- **判定阶段**：批内合并在 M03（L287）；跨批次在 M04（L305）。〔事实〕
- **错误合并不同时间的相似事件**：L122 禁止语义相似度合并主体；时间维度因无字段而**无法参与合并判断**（→B-035 关联）。〔设计缺口〕
- **保留原始证据**：source_refs 必留（L120）、L341 可追溯——**设计明确**。〔事实〕

### 3.9 矛盾检测

- **M03 无矛盾检测设计**：全文无"矛盾"；"冲突"仅指移交 M04（L306）。〔事实〕
- **M04 检测范围**：候选 vs **已有**记忆（m04 §4.2 L259–266），五种冲突类型含 contradiction（L273）；processCandidates 输入**不含原始对话批次**（L756–758）。〔事实〕
- **→ 批内矛盾（用户同批次先 A 后 B）无人负责**：M03 不检测；M04 看不到批内语境、且同批候选互查在 m04 全文无定义（grep 同批/批内/候选之间 = 0）。〔设计缺口→B-033〕
- **区分矛盾/演变/补充/纠正**：M04 §4.2 五类型＋§4.4 纠正机制（L289–303，保留原始记录+版本化）——**候选 vs 旧记忆的冲突区分设计完整**（M04 侧，Frozen）。〔事实〕
- **覆盖丢失历史**：m04 L112「Fact/Event 保留历史信息，不因新信息到来就直接覆盖旧记录」——**有明确保障**。〔事实〕
- **无法判断时**：m04 L284「冲突未解决时进入 uncertain 或 pending」、L447 待审核——**有保守策略**。〔事实〕

### 3.10 误提取与遗漏风险

- **幻觉防线现状**：Schema 校验（L394）只保证**结构**；content 幻觉、source_refs 指向不存在的消息均可通过校验。**claim_type=explicit 由模型自证**（L322 示例即模型输出；§6.4 硬约束清单 L215–222 不含"核对 claim_type 与 source_refs 原文一致性"；L117/L119 是对模型的规约，**无 Core 侧独立判定机制**）→ L117 在当前设计下是无执行者的愿望条款（→B-034）。〔事实+推导〕
- **外部反证（A 级）**：Graphiti 官方 README 明文承认结构化输出失效会导致 ingestion failure 并给降级机制；OpenAI 官方承认输出默认非确定性（seed 仅 best-effort 缓解）。→ **Schema 校验必须配合重试/降级，且"确定性检查"的具体内容需要设计**。〔事实〕

- **评估方法**：m02 D10 有 8 题测试集；**m03 无任何测试用例或评估方法设计**——§14 L432"中文语义提取的准确率"待验证但无抓手（→B-041）。〔设计缺口〕
