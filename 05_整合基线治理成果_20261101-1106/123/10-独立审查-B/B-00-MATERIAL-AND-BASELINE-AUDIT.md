## 4. Dream 与心理管线

### 4.1 Dream（`dream.md`）

- 自述 **Concept Baseline Draft 1.0 / 状态：概念收尾 / 实现状态：未实施**。
- §八明确：Dream 是 Memory Core 的**未来能力**，不在 M03/M04/M05 当前设计范围内；依赖 M05（判权）、M02（检索）、M04（关系候选，**接口未冻结**）、M01 D2（Dream Report 持久化）。

- **结论**：Dream **没有算法设计**，只有目标、边界和概念验收标准（§九，10 条）。**无法做算法替代性评估**；只能评估"它对 M01/M02/M04/M05 提出了哪些接口前提"。阶段 6 处理。

### 4.2 心理管线（`PSYCH-PIPELINE.md`）

## 5. 架构演进与可插拔设计要点

> 来源：`R3-Architecture-Evolution.md`、`R3-Pluggable-Capability-Design.md`、`R3-Capability-Ownership-Matrix.md`、`R3-Distributed-Evolution-Roadmap.md`、`R3-Architecture-Decision-Register.md`。均已通读。

### 5.1 架构演进（Evolution）

- 结论：五模块基线"基本对齐"能力边界，不需要推翻，需要在模块之上增加"横切能力宿主分组"（P0 平台层）——对应台账 D-AP-03（**接受概念，不授权实施，不新增第六模块/进程**）。
- 能力分解：38 项核心能力 + 3 项跨模块协作面（含 C50 DSH 主动通道、C51 反馈记账），共 41。
- 重申的不变量：权限唯一权威（M05/C40）、LLM 唯一入口（M04 §6.2）、Embedding Provider 归 M01。

### 5.2 可插拔设计（Pluggable）

- **能力契约八要素**（manifest）；**五级分类**（各级定义阶段 6 逐级核对；Ownership Matrix 另有替换级别 L0–L3 与失效行为 F1–F5）；**回退链**（如 `deepseek → ollama → 任务排队`，"绝不假装成功"）；**影子/蓝绿注册**；**拔除测试 T13**（最少 7 条外部依赖）。
- 已裁决：D-AP-07"接受五级可插拔分类、C40 不可插拔"；优化-4"首版拔除测试从 7 条外部依赖起步，保留后续扩展"。
- **契约是文档设计，不是已实现的接口**。凡涉及"如何实际运行"，一律"实施待核实"。

### 5.3 所有权与失效行为（Ownership Matrix）

- 检索相关 11 项全部归 M02（编排权威）；横切 9 项；失效行为 F1–F5；替换级别 L0–L3。
- 对本审查的含义：**"换掉某一路召回不应改动 M01/M03/M04"在所有权层面成立**，但是否在**接口契约层面**成立，需在阶段 2 核对 M02 如何读 M01 的数据。

### 5.4 Roadmap

- Stage 1/2/3，触发器为 T-2x/T-3x；D-AP-08 已接受"用可判定触发器驱动演进，不用预定时间表"，且"**触发后仍需重新评估并单独授权**"。
- Phase C 列有"重排器（bge-reranker-v2-m3）"等**可选升级**，各自独立开关——**属未裁决的未来选项**。
