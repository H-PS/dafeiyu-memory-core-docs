## §2.3.6.1 四态映射要求

**〔原文级〕** 版本级 `completeness` 为严格四态：`complete` / `partial` / `removed` / `unknown`。`invalid` **不是**第五种版本级状态——它是证据级 `result` 取值（见 §2.3.6.5）。

**〔归纳〕** 四种状态各自要求的映射事实与证据字段，对话中的表述为：complete 要求 requiredComponents 全部具备唯一、有效、可核验的映射；partial 要求可枚举缺失/截断/未映射项；removed 要求给出 removalBasis 与 removalBasis.ref；unknown 要求给出不可判定原因。**（具体表格措辞未能逐字复核。）**

**〔原文级〕补充规则 A —— 结构可选性**：`mappingEvidenceRef`、`removalBasis`（含 ref）属**结构可选**字段；其合法缺失**不构成结构错误**，后果由 §2.3.6.5-B 分类规则处理（归 B1/B2 → 版本级 unknown），不得升级为 invalid。

**〔原文级〕补充规则 B —— 版本级/片段级不一致**：§2.3.6.3 第 7 条：版本级结果与片段级证据不一致时**必须拒绝 L3，不能选择较有利的一方**。

**〔未能取得〕** §2.3.6.1 的完整"补充规则 1–8"逐条清单：对话记录中仅保留了其中与结构可选性、版本级一致性、unknown/partial 区分相关的部分要点，**其余条目无法可靠复现**，本包不填补。

## §2.3.6.2 必要组成部分与映射

**〔原文级〕**
- `requiredComponents` 是版本级完整性判定的依据；`componentMappings` 为每个 requiredComponent 提供**至多一条**映射声明（重复即 A5）。
- `fragmentRefs` 必须指向当前 `assemblyId` 下 `fragments[]` 中真实存在的片段（否则触发 A4/A6）。
- 映射声明的**语义充分性**（片段内容是否真正表达该组成部分）属语义判定，不要求结构校验方完成；不可核验时该版本判 unknown（B1）。

**〔未能取得〕** §2.3.6.2 的完整原文（表格/示例/边界说明）。

## §2.3.6.3 版本级与片段级一致性

**〔原文级〕** 第 7 条（核心）：版本级结果与片段级证据不一致 → 必须拒绝 L3；可确认的结构性不一致 → invalid（A8 兜底）；不可确认 → unknown。

**〔归纳〕** 其余条目（片段证据缺失不得保留 complete、片段显示截断/替换不得 complete、整体移除须 removalBasis、digest 不匹配不得 complete、assemblyId 不一致按 A4 处理）——语义在对话中出现过，**逐字措辞未复核**。

## §2.3.6.4 责任声明

**〔原文级〕** DSH 产生证据（字段、映射声明、片段摘要、removalBasis）；Bridge 只核验，不代填证据字段；任何一方判定不得替代另一方责任。

## §2.3.6.5 A 类清单（A1–A8）

**〔原文级〕** —— 以下定义在 v4.5 与后续 v4.6 定点修正中**两次以上逐条复述**，措辞可信度高（A1 明文排除项亦一致）：

| 编号 | 定义 |
|---|---|
| **A1** | 证据外层结构损坏，或核心关联结构缺失（evidenceId、injectionId、correlationId、sessionId、turn、assemblyId、versions、fragments 缺失或不可解析，致证据对象不成立）。**明文排除** mappingEvidenceRef、removalBasis 及其 ref（归 B1/B2 处理，不归 A1） |
| **A2** | 注入快照与 versions 不一致（缺项、多项、重复项、集合不完整） |
| **A3** | memoryId / memoryVersion 错配（versions 或引用指向非注入快照中的版本） |
| **A4** | 引用绑定明确错位——引用对象**可取得**，但绑定的 memoryId / memoryVersion / component / assemblyId 与当前上下文明确不符（含 fragmentRefs、mappingEvidenceRef、removalBasis.ref）；或跨版本、跨 assemblyId 引用 |
| **A5** | 同一 component 重复声明（componentMappings 内一个 component 出现多条声明） |
| **A6** | 无效 fragmentId 引用（指向 fragments[] 中不存在的片段） |
| **A7** | fragmentDigest 等完整性校验失败（摘要与片段实际内容不符——可确认的损坏或篡改信号） |
| **A8** | 其他能够确认的结构性或完整性错误 |

> **A8 来源归属说明（2026-11-03 第二轮定向纠错）**：原摘录在 A8 后附有"（兜底条款；援引须给出具体、可复核依据，不得作主观归类）"，经核对**该括注不属于 v4.5 原始定义**（v4.5 原文 A8 仅一句，见导出 L125746），实际来源为 **v4.6 §2.3.12 12.4（A8 援引规则）**。本次移除属**来源归属纠错**，不删除该规则本身、不迁移至其他正式文件、**不代表否决 A8 设计**——v4.6 的 A8 援引六要素仍完整保留在 `01_EVENT_L3_REVIEW/v4.6-latest-design-candidate.md` 替换文本 B 的 12.4 中。

## §2.3.6.5 B 类清单（B1–B4）

**〔原文级·B1/B2 为本轮修订重点〕**

| 编号 | 定义 |
|---|---|
| **B1** | mappingEvidenceRef 缺失（合法缺失）、引用对象不可取得，或无法核验其语义映射，导致该版本无法判定 |
| **B2** | removalBasis（含 ref）缺失、不可取得或无法核验，导致 removed 判定不成立 |
| **B3** | 证据对象部分内容暂时不可读、无法确认内容是否保留（证据整体不可读或缺失时不构成可核验证据——按 §2.3.5 视为证据缺失、不认定 L3，不进入 completeness 判定） |
| **B4** | 其他证据不足情形（须说明不足性质） |

> **重要（v4.6 修订点）**：v4.6 §2.3.6.5 第 12 条已**收窄** B1/B2——"引用字段存在但对象不可取得"**不再**作普通 B1/B2 unknown，改由 not_executable 处理（见 `v4.6-latest-design-candidate.md` 替换文本 D 第 12 条）。审查时须以 v4.6 收窄后的边界为准，B1/B2 原文仅作历史对照。

## §2.3.6.5 分类原则（三分法 · 逐字补录）

> **补录说明（2026-11-03 第二轮定向纠错，O-5）**：本段在原摘录中**完全缺失**，现按 v4.5 原文逐字补录。

> **历史对话行号**：**L125754–L125763**（提取件 `ORIGINAL-v4.5-section-2.3.6.5-L125735-125791.md` 第 20–29 行）。

**〔原文级·逐字〕分类原则：**

三分法（本版明确，消除 A/B 重叠）：
- "核心结构字段缺失/损坏"（证据对象不成立）→ A1；
- "版本级语义证据字段缺失，或引用对象不可取得/不可核验" → B1/B2；
- "引用对象可取得但绑定明确错位" → A4；
- 同一情形不得同时命中 A、B；判定顺序：先查结构成立性（A1/A2/A3），再查对象可取得性（缺失/不可得 → B），最后查绑定一致性（可取得但错位 → A4）；
- B 类情形不因聚合规则 1 的概括措辞被归入 invalid——规则 1 仅适用 A 清单；
- 无法确认的情况一律 fail-closed：不得支持 complete 或 L3；
- 若某一情形无法唯一归类（既非明确 A 也非明确 B）：该版本先按 unknown fail-closed，并将该情形列入实施前待定义清单（附录 F），不得自行创造隐含规则。

## §2.3.6.5 聚合规则 1–6

**〔原文级·已按 v4.5 原文 L125775–L125790 逐字校正（2026-11-03 定向纠错）〕**

> C. 聚合规则（固定顺序，首个命中生效；本版未改动）：

| 序 | 条件 | result | 保真度 |
|---|---|---|---|
| 规则 1 | 出现 A 清单任一情形 | `invalid` | 原文级 |
| 规则 2 | 否则，任一版本为 unknown | `unknown` | 原文级 |
| 规则 3 | 否则，任一版本为 partial | `partial` | 原文级 |
| 规则 4 | 否则，全部版本均为 removed | `removed` | 原文级 |
| 规则 5 | 否则，全部版本均为 complete | `complete` | 原文级 |
| 规则 6 | 否则（complete 与 removed 并存） | `partial`（定义式汇总约定） | 原文级 |

**〔原文级〕互斥性与覆盖性**：规则 1 先排除 A 类结构损伤；此后每个版本恰处四态之一（unknown 的成因含 B 清单）；规则 2/3 为存在量化、规则 4/5 为全称量化；唯一剩余组合（complete+removed）由规则 6 显式规定——不存在无规则可适用或双规则同时适用的版本集合。

**〔原文级〕规则 6 语义声明**：`result=partial` 有两种来源（规则 3 / 规则 6），均仅用于审计汇总，不改变版本级 completeness 值，不参与 Bridge 的 L3 判定。

## 空集处理与职责声明

**〔原文级〕**
- A 类无命中是"通过"的**必要条件，不是充分条件**；
- `evidence.result` 只记录证据核验结果，**不代表请求状态、不代表 L3、不代表模型实际使用**（§2.3.10 第 1 条）；
- A 类=可确认错误，B 类=无法判定；两者互斥，同一情形不得同时给出 A4 与 B1 分类。
