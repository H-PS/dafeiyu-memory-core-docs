## 一、L3 主链的接口依赖（先确定范围）

### 1.1 什么接口是 L3 主链必需的

A5 结论：L3 = 检查 I passed ∧ 检查 II passed ∧ 该版本检查 III complete ∧ 两阶段记录关联一致（v4.6 L90）。

由此推出 L3 主链的接口需求：

| 需求 | 对应接口项 | 现状 |
|---|---|---|
| 证据对象承载（含 A1–A8 所需字段） | 证据对象结构（非 X 系） | **设计文本有**，无代码证据 |
| 请求级关联（correlationId/assemblyId） | **F4 = 否** | **不存在** |
| 第一阶段观察记录（E-1） | **F3 = 否**（无 prompt/assembled 事件） | **不存在** |
| 第二阶段确认记录（E-2） | v4.6 L27 明示「v4.5 无对应结构」 | **不存在** |
| 不落盘摘要比对 | F-CK-4 未核查 | **未验证** |
| 跨对象引用可得 | F-CK-2/3 未核查 | **未验证** |
| 请求级状态落点 | 10 态缺 not_executable/not_started | **设计缺口** |

## **〇、登记完整性缺口（v1.1 新增，重大发现）**

**主审实测**：`06-interface-map.md` 全文检索以下六个关键概念——**全部 0 命中**：

| 概念 | 命中数 |
|---|---:|
| `E-1` | **0** |
| `E-2` | **0** |
| `correlationId` | **0** |
| `assemblyId` | **0** |
| `请求级` | **0** |
| `终态` | **0** |

**判定**：**接口图完全没有登记 L3 证据链本身**——证据对象、两阶段记录（E-1/E-2）、证据无效记录、请求级终态**均为 0 条**。

**后果**：
- 06-interface-map 的 14 条接口中，**与 L3 直接相关的仅 X-6 一条**（投递面），且其可观测性受 F3/F8 限制；
- **L3 主链的核心接口（E-1/E-2）不在登记表内** → 这解释为何 A6 无法从接口图直接评估 L3 可行性；
- **A5 的 S5-03（请求级无落点）在接口层同样无登记**——不是「X-13 与之相关」，而是**根本没有对应登记项**（X-13 属心理层 L4/L5）。

> **给用户的提示**：06-interface-map 需**补登记** L3 主链接口（E-1/E-2/请求级终态）与 E-3 候选（请求级终态落点、l3_revoked、接口级失效行为字段）。此项**属文档治理，本报告不擅自修改**。

## 四、接口职责重叠与边界

| # | 疑点 | 判定 |

## 六、接口职责与「失效行为」缺口

`06-interface-map.md` L65 自述：「每条接口的『失效行为』字段大多未定义——这是设计文档的系统性空白，建议进入裁决材料（**不阻塞架构裁决，但阻塞实现**）」。

**主审判定**：该自述**准确**。14 条接口中仅 X-4（有降级链）与 X-5（可丢失不阻塞）有部分失效行为描述，其余 **12 条未定义**。

**对 V1 的影响**：按宪章 §3.5「失败可处理」原则，**失效行为未定义即不满足 V1 就绪条件**。
