# 10-ERROR-DEGRADATION-RECOVERY · 异常处理、降级与恢复

> 依据：m01 D29/D35（存储降级/错误分类）、M02 D9（检索降级六类）、m04 §十七（M04 异常表）、m05 §十六（权限失败）、M04 §6.4（模型降级）、Pluggable §四（降级链）、Pluggable 不变量 6（降级不越权）、A5 异常路径审查、Agent E 发现（反复活闭环缺口、写入预算缺失）。
> 总原则：**普通聊天尽量不中断，记忆功能按故障范围降级；权威数据或权限不可靠时拒绝访问。** 降级只能"变少变慢"，不得"变宽"。

---

## 一、失效行为分类（F1–F5，全系统统一语义）

| 码 | 语义 | 典型场景 |
|---|---|---|
| **F1 安全关键** | 失败即拒绝/阻断，绝不静默降级 | 判权失败、删除状态提交、reinforce 违规写入、提取"失败不伪装成功" |
| **F2 渠道降级** | 该路失效→其他路继续 | 向量/FTS 不可用 |
| **F3 事务语义** | 失败=操作未发生 | 权威写入、版本冲突拒绝覆盖 |
| **F4 性能降级** | 失效→跳过该步/换默认，正确性不变 | 重排跳过、缓存丢弃、心理层重置中性、观测失效 |
| **F5 受控恢复** | 需人工/受控流程介入 | 备份恢复失败、质量事故、视图校验失败保留旧版 |

## 三、恢复流程（M01 D8 八步，唯一权威，跨模块统一）

```
1. 恢复权威数据库 memory.sqlite
2. 完整性与 Schema 检查
3. 恢复删除状态
4. 恢复权限与撤销状态
5. 恢复或重建 LanceDB
6. 恢复 Outbox 和任务状态
7. 检查关联及派生数据（重建 cache.sqlite）
8. 确认安全后开放 Recall
```

**防复活约束**：不能恢复已撤销授权/已删除记忆；已删内容不得经索引重建、缓存恢复、历史版本复活；权限不明确默认拒绝；**旧备份的授权不得覆盖更新的撤销结果**；cache.sqlite 不参与恢复（一律重建）。
**在途 Retain 复活路径（红队 RT-12 补）**：删除发生时，已在 M03→M04 管道中的候选可能引用已删记忆——M04 终审**必须回查候选 source_refs 指向记忆的当前删除状态**，已删则候选拒绝入库（与 B-018 索引写入回查同向，扩展至候选审核层）；时序上不依赖"删除先于提取"的假设。

**〔审查发现·Agent E〕反复活闭环不闭合**：D8 要求恢复"以最新有效删除状态为准"，但恢复对象即承载删除状态的同一库——从旧备份恢复时删除记录同样回退，"最新"无处可取；备份周期/保留数量为开放项（m01 §10-11）；已删内容可长期存活于备份与 evidence 原文。**修订提案（待裁）**：①删除/撤销写**独立追加式墓碑账本**（单调版本、单独备份不回滚、恢复时以账本重放）；②为 evidence 定保留期与"要求忘记"物理清理路径；③明确"备份窗口内被删内容随窗口过期消失"。此提案与 D8 现文不冲突（属细化），但因涉及删除语义，列 14 号待用户确认。

## 四、Event-L3 链路异常（候选设计）

| 异常 | 处理 |
|---|---|
| 证据整体 failed（A 类） | 请求终态 l3_rejected；无确认记录；第一阶段观察记录+无效记录保留 |
| 整体 not_executable/not_started | **无确认记录**；〔修订提案 S5-03〕落 l3_unevaluable 终态（待裁） |
| evidence_timeout 后迟到证据 | 不进入任何检查；原请求保持终态；重试须新 correlationId（T-10） |
| 权限撤销发生在两阶段之间 | 撤销优先；确认不产生（权限状态实时生效于 L3 条件） |
| 观察记录与证据不一致 | 检查 III 判 unknown/failed；按 13.5 三分与规则 1–6 聚合 |
| invalid 下版本级 complete 值 | 仅诊断保留，不产生确认效力（§2.3.6.5 第 10 条效力推广） |

## 五、降级链声明（Pluggable §四继承）

```
rerank:   失败 → 跳过用原序（V1 重排器默认 noop）
vector:   不可用 → 禁用向量路（FTS+结构化继续）
fusion:   学习型失败 → rrf（V1 仅 rrf）
llm:      deepseek 失败 → ollama 失败 → 任务排队（绝不假装成功）
cache:    损坏 → 丢库重建（直查权威）
psy:      损坏 → 重置中性 + 跳过情绪一致性步（Core 功能完整）
```

**不变量**：降级后的路径不得放宽任何权限/生命周期检查（不变量 6）；每能力降级行为必须是其 F 码之一，不得"报错退出"。

## 六、写入侧预算与背压〔审查发现·Agent E，新增提案待裁〕

**缺口**：活跃群 500–1000 条/天 → 25–50 个提取批次，无日预算/背压/积压降级——成本随活跃度线性上涨不可预期。
**修订提案**（登记待裁，14 号）：Retain 日 Token 预算 + 显式"记住"指令优先插队 + 积压时增大批次/降低频率；预算耗尽时不丢弃数据而延迟处理（与"失败≠成功"一致）。

## 七、第三方断言污染防护〔审查发现·Agent E，新增提案待裁〕

**缺口**：claim_type 描述证据性质而非"谁对谁断言"。群成员说"A 其实很有钱"会以 explicit 进 group 记忆，之后在 A 在场时注入——M05 只有 scope 维度，无"关于第三人的陈述"规则，构成"不乱说"的正面漏洞。
**修订提案**（登记待裁，14 号）：候选增加 `assertion_source ∈ {self, other, bot_inferred}`；硬规则：关于在场第三人的 other 断言不入 fact 层（只能 uncertain 或带"据 X 说"表达）；对同一 (author→subject) 的重复矛盾断言节流。与 B-034（explicit 由模型自证）同源，合并呈报。
