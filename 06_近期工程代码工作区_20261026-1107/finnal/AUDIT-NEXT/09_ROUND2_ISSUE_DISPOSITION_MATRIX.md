## 三、A08-10 回源结果（P1 详证）

### 3.1 本轮找到的成因

**结论：正文时间戳是脚本内硬编码的固定字符串，与脚本实际运行时刻无关。**

证据：

```
v12_finalize.py       → "# 时间：2026-11-03 22:40（Asia/Shanghai）",
v12_fix_closure_s7.py → block = """## 七、v1.2 受控修订记录（2026-11-03 22:15）
```

- `22:40` 与 `22:15` 两处均在**脚本源码**中作为字符串常量写死；
- 脚本 mtime 分别为 20:07:26 / 20:05:32，即**脚本在 20:05–20:07 写入了标注 22:15 与 22:40 的文本**；
- `22:05`（CONSISTENCY L5）与 `22:35`（VERIFICATION L3）在全部 41 个 `.py` 中**未找到写入源**（grep 0 次），可能由未保留的临时脚本或手工编辑产生。

### 3.2 判定

| 层 | 结论 |
|---|---|
| 现象 | ✅ **确认**：正文时间 22:05/22:15/22:35/22:40 与 mtime 20:07 相差约 2 小时 |
| 原因 | ✅ **已定位 2/4 处**（22:15、22:40 为脚本硬编码）；2/4 处（22:05、22:35）**未找到生成源** |
| 是否人为伪造 | ❌ **不判定**。证据只支持「时间是事先写定的计划时点」，**不支持也不排除**其他解释 |
| 是否影响验证过程 | ⚠ **不影响验证内容**——`_v12_verify.txt` 的 23 项 UNCHANGED 我已在 ROUND1 独立复算成立 |
| 是否影响 F-08 | ⚠ **加强 F-08 的解释力**。F-08 说「VERIFICATION 验的是中间态」，本轮发现其时间戳也不可自证，二者指向同一现象：**A-04 v1.2 的生成过程缺少可执行的时间/对象绑定** |

### 3.3 为何仍是 A 类

关键不在「历史时间错了」，而在「**产生这些文件的脚本仍会把时间写死**」：
若 A/B 修改沿用 `v12_finalize.py` 这类脚本新建 v1.3，则 v1.3 的修订时间同样不可验证，**F-08 这类问题会在新版本上重演**。

**最低解决条件**（任一即可）：
1. 确认「正文时间 = 计划时点」并在新版本中显式标注；或
2. 修改生成脚本改用运行时时间（`datetime.now()`）并留存完整日志。

**不需要**回改 A-04 v1.2 历史文件。
