# Outbox / recovery verification harness (Agent G)

Isolated verification code for the Memory Core R4.1 area **transactional outbox + backup/restore +
startup/shutdown ordering**. It is a probe, not a product module:
`PRODUCT_IMPLEMENTATION_AUTHORIZATION` remains **NOT_AUTHORIZED**. Nothing here is part of the
product build, and no product file was modified.

## Run it

```powershell
cd E:\[PROJECT]\r41-baseline\03-verification\outbox
node run-all.cjs
```

No install, no build step, no package manager. Node 24.21.0 / SQLite 3.53.4, `node:sqlite` only.

`run-all.cjs` runs the four suites in order in child processes, prints per-script exit codes and
the evidence records each run appended, writes
`06-evidence/raw/outbox/run-all.summary.json`, and exits `0` only when every script exited `0` and
every appended record is `PASS` (`1` = failures present, `2` = harness error).

Every run **appends** to `06-evidence/outbox.jsonl`; it never rewrites it. A fresh `evidence_id`
block is assigned by append order. Delete the file first if you want a single coherent block.

## Environment constraints that shaped the code

These were measured here, not assumed, and they explain some unusual-looking choices:

1. **`node:sqlite`'s `backup()` returns a Promise.** `db.backup` does not exist. Because the
   surrounding code is synchronous, backups run in a child process (`lib/backup-child.cjs`) — which
   is also a more honest model of an operator's backup process (a real second connection).
   `VACUUM INTO` works and is used only as an independent cross-check.
2. **Piped stdio is denied in this sandbox** (`spawn`/`spawnSync` with `stdio:'pipe'` →
   `EPERM`). Child workers therefore report by appending to a JSONL file with `fs.writeSync`
   (`--evlog`), and the parent reads that file. `stdio:'ignore'` is used throughout; `run-all.cjs`
   redirects stdout to real file descriptors, with an `ignore` fallback.
3. **A busy-wait starves the event loop**, so `'exit'` callbacks never fire in a spinning parent.
   `lib/proc.cjs` waits by polling `process.kill(pid, 0)` instead of relying on events.
4. **A self-inflicted `SIGKILL` on Windows** yields child `status: 1, signal: null` — not a signal
   name. The kill tests assert `signal === null` explicitly so "killed" is not confused with
   "exited 1 on its own"; the evidence log written before the kill survives.
5. **LanceDB is not present** in this environment (`:memory:` unsupported, package only in the
   canonical tree). The vector channel is modelled by a **second SQLite file** (`index.sqlite`),
   which has the one property that matters: no shared commit with the authority. Every claim about
   "the external store" is a claim about that stand-in — see the duplicate windows in
   `04-contracts/OUTBOX-CONTRACT.md` §6.3.

## What the numbers mean (and do not)

- Concurrency checks use **genuinely separate OS processes** (two `node` children on one database
  file) with a barrier, and assert on the *overlap* of their claim windows, not on wall-clock
  ordering. A sequential "concurrent" test would not be accepted.
- Backoff, lease and drain timings are **measured** and asserted as bounds, never as exact values.
- Every numeric default in the prototype is labelled **`EXPERIMENTAL / VALIDATION_PENDING`**
  (MC-AUD-008 open). No backup retention value exists anywhere in this area — MC-AUD-009 is an open
  decision, and `backup.retention_policy_is_unspecified` fails the moment someone adds one.
