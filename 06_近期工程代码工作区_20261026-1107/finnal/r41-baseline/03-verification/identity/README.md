# 03-verification/identity — TECH-IDENTITY-01

Identity, permission-context and final-retrieval authorization verification for the Memory Core
R4.1 baseline.

> **SYNTHETIC_IDENTITY_VERIFIED != REAL_HOST_MAPPING_VERIFIED**
> All identities are generated by `lib/synthetic-identity-provider.cjs`. No QQ Bridge is contacted,
> no DSH identity data is read. Real-host validation is **not permitted** in this session.

## Run it

```bat
cd 03-verification\identity
node run-all.cjs
```

* `222` executed assertions, one JSON evidence record each.
* **Exit `1` is correct on this baseline.** Six checks fail on purpose: they are the negative
  controls that prove the hardening requirements are load-bearing. See `TASK-RESULT.md` §0.
* Exit `0` would mean those six attacks stopped leaking, i.e. the deliberately weak reference
  profile changed — investigate before trusting it.
* Exit `2` = harness error (a module threw).

No npm, no pnpm, no child processes, no network. Plain CommonJS, Node ≥ 18 (developed on v24.21.0).

Partial run of a single module (writes `partial-<n>-*` artifacts and leaves the main evidence file
untouched):

```bat
node run-all.cjs --only=05
```
