### 六·A V-8 门禁理由（Correction 5 + 假设化修正）

V-8 是**事实测量核查门**，不是技术依赖。它阻塞 M0/M1 的程度仅以"测量有效性所需的已证实事实"为限。需区分五层（层次 4–5 为 `CONFIRMED`，层次 1–3 为**待核查事实/假设**）：

| 层 | 命题 | 状态 |
|---|---|---|
| 1 | token 在请求间会变化 | `CONFIRMED`（轮换即变） |
| 2 | token 位于 DSH 缓存相关前缀内 | **假设（未证实）** |
| 3 | DSH 缓存实现把该变化判为前缀失配 | **假设（未证实）** |
| 4 | 所装 DSH 版本是否上报缓存 usage 字段 | **待核查（V-8 目标）** |
| 5 | 字段是否到达并被 token-ledger 正确存储 | **待核查（V-8 目标）** |

只读核查四项（不变）：
1. 真实 DSH usage 事件是否含 `cacheMiss`/`cacheHit`/`cacheWrite`；
2. token-ledger 是否收到并正确存储这些字段；
3. 字段缺失是否表示为 `N/A`（**绝不静默当 0**）；
4. 计划中的 prompt/凭据变更是否影响缓存测量基线的有效性。

**结论口径**：①缓存影响目前是**合理假设，未证实**，不得描述为已证明；②若 DSH 不含缓存字段，`cacheHitRate` 报 `N/A`（不是 0），**不阻塞 M0/M1**；③若 prompt/凭据变更可能影响基线，必须在**对比变更前后缓存指标之前**先验证该影响；④V-8 只阻塞到事实被确认为止。

### 六·B 双损覆盖验证门 V-8b（可验证化 + 独立可信基线）

- **V-8b 校验不变式（三 key 集显式比较，比较 key 身份非计数）**：
  - `K_pre` = 恢复前存在的全部凭据 key 集（**必须来自独立于被恢复损坏对象的可信来源**，见下）；
  - `K_enum` = 恢复流程枚举出的 key 集；
  - `K_reg` = 恢复后实际重生成的凭据 key 集。
- **独立可信基线要求（本轮新增）**：`K_pre` 不得**仅**从被恢复的损坏 credential 文件派生；不得假设"枚举 social-v2 conversations 覆盖全部凭据记录"。可信来源选项：① 实施期维护的**独立凭据清单文件**（credential manifest，与 credential 文件分离落盘）② 审计日志回放 ③ 人工核对。**若无法建立独立可信基线，V-8b 标 `UNCONFIRMED`**。
- **PASS**：`K_enum ⊇ K_pre` 且 `K_reg == K_enum`（无缺、无多余），且每个重生成凭据的归属/关联校验通过——**仅凭计数匹配不得判 PASS**。
- **FAIL**：缺 key、多 key、归属不符、或 `K_pre` 仅源自损坏对象。
- **PASS 前**：双损恢复保持受控/人工，**不得描述为确定性**。PASS 后才可称认证恢复确定性。

### 六·C 共享 token-ledger 的并发与持久性边界（Correction A + 细化）

**事实**：`token-ledger` 是**单一共享文件** `state/token-usage.jsonl`（`token-ledger.js:22`），写入 `appendLine`（`:258-268`，`appendFileSync` 单行、吞错返回 bool）+ `compact`（`:273-304`，`writeFileSync(tmp)`+`renameSync` 原子替换）。

**不变式（Correctness）**：任何"已接受的账本更新"不得被静默丢弃；提交序 = 样本进入单写者队列/串行提交的顺序；重试不重复记账（幂等折叠 `:464-466`）；append 与 compact 互斥。

**持久性边界（明确区分，不得混淆）**：
- **同步 append 原子性**（单线程事件循环内 `appendFileSync` 不交错）= 可保证。
- **崩溃持久性**（append 后、ack 前崩溃是否已落盘）= **不可仅凭 `appendFileSync` 推断**，需实施期测试确认（fsync 语义/OS 缓冲）。

**崩溃点行为（设计 vs 实施期验证）**：

| 崩溃点 | 设计预期 | 保证等级 |
|---|---|---|
| enqueue 前 | 样本随进程丢失，无账本残留 | 设计意图 |
| enqueue 后、append 前 | 样本丢失（未落盘） | 设计意图（尚未接受） |
| append 后、ack 前 | 可能已落盘（无 ack 语义，账本无回执） | **实施期验证** |
| compact 中 | tmp+rename 原子，不会写坏；旧文件完整 | 设计保证（原子替换） |

**机制**（实施期择一，不预设）：①单写者队列 ②账本本地串行提交。**不变式权威，机制实施期定**。

**reset 生命周期边界（Correction C）**：账本记录由 DSH 会话事件驱动（`bridge.js:11763/11769`），**与 reset 事务解耦**——reset 成功不要求账本成功；账本失败不逆转 reset、不触发再次轮换；账本重试经幂等折叠不翻倍；账本结果不入 reset `overallResult`（D-8）。
