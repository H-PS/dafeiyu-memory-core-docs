## 二、逐项 before / after

### 细化 A · C-7 账本顺序与持久性边界

| 项 | 内容 |
|---|---|
| 原 | C-7 补了 L4 共享账本 + 不变式 + 机制实施期定，但未定义提交序、崩溃点行为、append 原子性 vs 持久性 |
| 改 | ①提交序 = 样本进入单写者队列/串行提交顺序；②重试不重复记账（幂等折叠 `:464-466`）；③明确"同步 append 原子性 ≠ 崩溃持久性"（`appendFileSync` 不等价已持久化）；④五个崩溃点行为表（enqueue 前 / enqueue 后 append 前 / append 后 ack 前 / compact 中）；⑤append 与 compact 互斥 |
| 证据 | `token-ledger.js:258-268`（appendLine 吞错）、`:273-304`（compact 原子替换）、`:464-466`（幂等折叠） |
| 类型 | 细化（正确性） |
| 遗留 | 机制（队列 vs 锁）实施期定；append 后崩溃的持久性需实施期测试（LEDG-06） |

### 细化 B · V-8b 独立可信基线

| 项 | 内容 |
|---|---|
| 原 | V-8b 三 key 集比较，但 `K_pre` 来源未约束 |
| 改 | 新增**独立可信基线要求**：`K_pre` 不得仅从被恢复的损坏 credential 文件派生；不得假设枚举 social-v2 覆盖全部；可信来源 = credential manifest / 审计回放 / 人工核对；无法建立基线 → UNCONFIRMED；仅计数匹配不得判 PASS |
| 证据 | 本任务 Correction B 要求 + 23 号 Issue 2 |
| 类型 | 细化（正确性） |
| 遗留 | 独立基线机制（M14 manifest）为新建模块；凭据出 S 后是否孤儿需 V-8b 复核 |

### 细化 C · 账本与 reset 生命周期边界

| 项 | 内容 |
|---|---|
| 原 | D-8 只定义幂等保留，未定义账本与 reset 的关系 |
| 改 | 明确：账本记录是**独立会计操作、非 reset 必要 effect**（证据：账本写入只由 DSH 会话事件驱动 `bridge.js:11763/11769`，与 reset 解耦）；账本失败不逆转 reset、不触发再次轮换；账本结果不入 `overallResult`，作独立运维状态 |
| 证据 | `bridge.js:2457/2478`（recordSessionUsage/Snapshot）、`:11763/11769`（事件回调） |
| 类型 | 细化（正确性 + 运维） |
| 遗留 | 账本结果的具体呈现形态（独立运维状态字段）为实施期细节 |
