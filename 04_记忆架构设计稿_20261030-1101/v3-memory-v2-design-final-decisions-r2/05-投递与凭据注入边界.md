# 05 · R2 投递与凭据注入边界

> 合并 22 号 C-6 与 23 号 §七/E 的边界结论。本文件是"token 如何进入模型世界"的**权威设计**。

---

## 一、投递出口全景（`CONFIRMED`，23 号 §七）

`api.sessions.prompt` 共 4 个调用点：

| 调用点 | 归属 | 会话类型 | 令牌 |
|---|---|---|---|
| `:9543` | `deliverPromptNow`（`:9483`） | **reserved2 QQ 用户会话** | 是（当前构造期嵌入） |
| `:11527` | v1 消息直投 | QQ 用户会话（v1 无令牌机制） | 否 |
| `:2170` | `runSlangExtraction`（内部学习会话） | 内部辅助会话 | 否 |
| `:2233` | `runSlangResearch`（同上） | 内部辅助会话 | 否 |

notify-ai（`:4379`）、唤醒（`:10847`）、防永眠提醒（`:11932`）、摘要投喂（`:9773`）、离线重投（`:2845`）**全部**经 `deliverPrompt → deliverPromptNow → :9543`。

## 二、边界定义（C-6 + D-1）

> **凭据注入边界 = `deliverPromptNow`（reserved2 QQ 会话的唯一出口）+ 两条显式豁免路径**：
> - 豁免①：v1 直投 `:11527`（v1 模式无令牌机制，tokenLine 仅 `isV2` 注入 `:4361-4364`）。
> - 豁免②：内部学习会话 `:2170`/`:2233`（`ensureSlangLearnerSession`，非 QQ 会话）。
> 若未来 v1/内部会话引入凭据，必须收敛进边界。

## 三、注入规则五条（C-6，Correctness）

1. **基础 prompt 裸存**：队列/journal/dump 均不得含凭据材料。
2. **注入时机**：`api.sessions.prompt` 调用前一刻。
3. **取值**：发送时刻读当前 `credential.get(key).epoch` 的 token。
4. **共用实现**：所有 reserved2 QQ 投递共用同一注入实现（现状已天然满足：五条上游全汇入 `:9543`）。
5. **恰好一次**：每次发送注入恰好一次，重复投递不累积令牌行。

## 四、队列载荷语义（`CONFIRMED` 现状 vs 目标态）

| 项 | 现状（`CONFIRMED`） | 目标态 |
|---|---|---|
| 队列存什么 | **完整 promptText（含令牌行）** `:9504` | 无凭据裸 prompt |
| 重连/重投发什么 | 原样发送存储文本 → **旧 token** | 投递时注入当前 token |
| 重复投递是否累积令牌行 | 否（构造期嵌入一次） | 否（投递时注入恰好一次） |

**迁移动作**：队列载荷从"含令牌完整 prompt"改为"裸 prompt"；`deliverPromptNow` 在发送前按固定槽位注入当前令牌段（保持"角色/身份之后"的前缀次序，兼顾 09 号缓存稳定性）。

## 五、needsDelivery 语义

- `needsDelivery=true` 表示"这一 epoch 的 token 尚未被 DSH 确认接受"。
- **只有 `accepted.result.ok === true` 才清位**；`constructed`/`queued`/`failed` 均不清（04 §3.2 五态机）。
- 兜底：启动清扫（扫描 needsDelivery=true）+ 告警（`credential_delivery_stalled`：3 turns 或超 N 小时）。
- **默认不做合成 prompt 兜底**（每次合成=真实模型调用+可能的工具误发；"保持沉默"指令不保证沉默）。合成推送如需，属 **[Product]** 需主人批准。

## 六、凭据持久化限制（C-10）

凭据值**永不进入**：prompt ledger、持久队列、debug dump、普通日志、备份、导出。
- 日志只记 `tokenHash8` + epoch。
- 出站文本脱敏走 `redactKnownTokensOnly`（消费脱敏索引）。
