# 02 · R2 记忆架构（A/P/S 边界 + 快照 + 记忆职责）

> 基线：R1 `01`（架构）、`03`（权限）、`05/06/07`（写入/召回/reflect）。本文件做**架构级合并**，不重复逐字段矩阵（细节仍以 R1 对应文档为历史出处，活跃规范以本文件 + `01` 决策寄存器为准）。

---

## 一、A/P/S 边界（保持 R1，一处口径强化）

| 层 | 定义 | 权威来源 | 可重建性 |
|---|---|---|---|
| **A** | 权威长期记忆记录（向量 + 文本 + 权限/来源元数据） | `memory-store`（`commit()` 唯一写入口） | 不可重建，是真相 |
| **P** | 可重建派生投影 | 从 A（memoryView）+ 从 S（runtimeView）分别重建 | **可重建**；依赖 S 数据的投影不得声称"仅从 A 重建" |
| **S** | 非可重建运行时/会话状态（`social-v2.json` 会话态 + 快照） | `socialStateWriter` | 不可重建，会话级 |
| **B** | 业务级记忆概念（话题/想法/印象，`memberImpressions` 等） | 当前在 S 层，是唯一副本 | **B ≠ P**：B 是原始业务记忆，P 是派生投影，二者语义不同 |

**R2 强化（源自 19 号 §一）**：S 层快照器 `buildSocialV2Snapshot` 是**显式字段白名单序列化器**（`bridge.js:8935-8963`，每会话 21 字段 + 顶层 2 键）。含义：**任何未登记进白名单的字段，每次保存被静默丢弃**。因此：
- 任何新状态字段，要么登记进快照器白名单，要么归入独立文件（走 P/B 拆分），**二者必须显式二选一**；
- 这从机制上强化了"B/P 拆出 S 层"的论据（R2 与 R1 结论同向）。

## 二、social-v2 快照与写入（源自 19 号 §一 / 22 号 F-8 / 23 号 C-1/C-7/C-8）

| 项 | 规定 |
|---|---|
| 写入物理路径 | 3 条：普通保存（`saveSocialV2State`，吞错，38 处）、Strict（`saveSocialV2StateStrict`，抛错，5 处，仅 memory append/remove/clear）、直写（`:4624` 固定空对象，**必须消灭**） |
| 快照一致性 | 内存唯一真相 + 同步重建快照（`atomicWriteJson` 全同步，`:182-193`）→ 文件级过写在单进程内物理不可能；**不加全局快照锁** |
| 跨进程 | `acquireLock`（启动期防双实例）+ 载入期 mtime 守卫；运行期外部修改会被下一次保存覆盖（记入 `stateRev` 校验后变为可检测） |
| 逻辑并发 | 三级：同步变更靠事件循环原子；跨 await 变更靠 fencing（C-2）；多 phase 操作靠 per-key 锁（C-7） |

## 三、Retain / Recall / Reflect 职责（保持 R1，含安全约束）

| 模块 | 职责 | 关键约束 |
|---|---|---|
| **Retain** | 从对话提取候选观察，写入候选池 | 不直接进 A；候选需 reflect 审核 |
| **Recall** | 按 `canRead` 过滤 + 语义检索（复用 `embed/cosSim/searchVectorMemory`） | 注入前终检 `canRead`；token 预算约束；`proposed` 不进召回 |
| **Reflect** | 审核/合并/降级观察，产出 A 层记录 | **无删除权**（不能物理删 A 层原始记录）；证据可追溯；自动晋升不靠数量；合并不做不安全单链聚类；矛盾证据保留供人工审 |

## 四、记忆可见性与权限（源自 R1 `03` + `01` 决策 A-1～A-5）

- 四维正交：`origin`（来源）/ `scope.contentClass`（分级）/ `scope.read`（读取范围）/ `review.status`（审核）。
- 保护序与不变式：`contentClass !== 'public' ⇒ scope.read === 'owner_only'`。
- 权限函数：`canRead(record, ctx)`（agent/reflect，fail-closed 拒 admin）与 `canReview(record, ctx)`（admin）。
- 群聊死锁修法：来源+分级四维拆开，敏感内容即使同群也降 `owner_only`（A-1）。
- promote 关闭（A-2）：后端拒绝、UI 显示未开放、配置无入口。

## 五、删除 / 修正 / 审计 / 备份边界

| 项 | 规定 |
|---|---|
| 删除 | 仅软删（tombstone）；物理清除需独立授权（purge），reset 不清 A 层 |
| 修正 | 走 `commit({type:'edit'|'setReview'|'setLifecycle'})`，保留版本/审计 |
| 备份 | 现状 `dailyBackup`（`memory-vector.js:131-147`）仅备份 A 层向量库；扩展任何备份清单时 `agent-token.json` 显式排除 + 断言（B-4/FILE-01 依据） |
| 导出 | 排除凭据；过 `redactKnownTokensOnly`；禁止自动上传 |
| 审计 | 分级变更、人工降级、promote（不可达）、审核、purge 全部留审计 |

## 六、token 预算与召回约束

- 召回注入受字符预算约束；`estimateTokens` 只做预算决策，**不用于报告实际节省**。
- 实际用量只来自 `token-ledger.js`（`cacheMiss/cacheHit/cacheWrite` 桶 + `:709` 公式）。
- **cacheHitRate 数据源未确认前（V-8），该指标标 `N/A`，禁止引用 `:709` 的 0 值、禁止估算冒充实测**（C-10 相邻约束，详见 `06`）。
