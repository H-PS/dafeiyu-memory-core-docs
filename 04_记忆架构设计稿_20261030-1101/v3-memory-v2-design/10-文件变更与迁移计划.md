## 四、新增数据文件

见 `08` §2.1（12 个左右）。其中 A 层与索引体积：`memory-store.jsonl` 约 1KB/条（含 1024 维浮点，实际约 6KB/条 —— 注意：向量以 JSON 数组存会膨胀，见 §4.1）。

### 4.1 一个必须提前说的体积问题

现状 `memory-vectors.jsonl` 每条含 `vec: [1024 floats]` 的 **JSON 文本**（约 1024×9 ≈ 9KB/条）。102 条约 2MB（`【审计】项目全景` §九：102 条 2047KB）。

Rev3 把向量移到二进制 `vec.f32`（1024×4=4KB/条），A 层 JSON 里**不再存 vec**，只存 `vecRef: docId` 或 `vecPresent: true`。

| 方案 | 10k 条体积 |
|---|---|
| 现状（JSON 内嵌 vec） | ≈90MB |
| Rev3（vec 外置 f32） | A 层 ≈10MB + index 40MB = 50MB |
| 增益 | 约 -44%，且索引可独立重建 |

**迁移含义**：A 层记录形态改变（去 vec、加 vecRef），需要一次性转换 + 重建索引。**这是迁移里最实质的一步**。

## 五、迁移步骤

```
阶段 0（准备）
  · 产出 43 处 social-v2 写点清单（U-8）
  · 备份 state/（含 ACL 检查）
  · 记录基线：token-ledger 当前 summary（供后续对比）

阶段 1（结构）
  · 建 12 个新文件（空结构）
  · A 层转换：vec 外置 → vec.f32 + ids.json，A 行改写（一次性，幂等）
  · 重建索引（10k 条约 40-60s）

阶段 2（写路径）
  · memory-vector 旧函数转发 commit（兼容适配器）
  · socialStateWriter 收敛
  · 双读单写期：新文件优先，缺失回退 S 字段

阶段 3（能力）
  · Ledger 上线（只 4 块）
  · credential 模块上线（两条退役路径统一）
  · recall 三通道上线（先只用于新工具，不改自动注入）

阶段 4（自动注入）
  · buildWakePromptV2 接入 recall（这一步最影响体验，最后上）

阶段 5（Retain/Reflect）
  · Retain 异步旁路
  · Reflect 空闲调度
```

**当前记忆库 0 条**，所以阶段 1 实际是"建结构"而不是"转数据"，风险极低。**但如果从备份导入历史数据，必须走"最保守"映射**（`03` §8）。

## 六、回滚

| 阶段 | 回滚 |
|---|---|
| 1 | 删新文件；A 层转换保留 `.bak` 一份 |
| 2 | 旧函数仍需能直写（保留 fallback 开关 `memoryStore.legacyWrite=true`） |
| 3 | `blockLedger.enabled=false`；`credential.mode` 不变（本就是 prompt 每轮） |
| 4 | `recall.enabled=false`（注入块消失，退回现状） |
| 5 | `retain.enabled=false` / `reflect.enabled=false` |

**没有一步需要"恢复备份"** —— 加法式设计的收益。

## 七、兼容性矩阵

| 场景 | 结果 |
|---|---|
| 新代码 + 旧数据（A 层含内嵌 vec） | ✅ 读取时兼容；首次启动触发一次转换 |
| 旧代码 + 新数据（A 层去 vec） | ⚠️ 旧 `searchVectorMemory` 读不到 vec → 返回空（功能退化，不报错、不越权） |
| 索引缺失/损坏 | ✅ 重建或降级 |
| Ollama 不可用 | ✅ 写入成功（`embedding.status='pending'`） |
| 双实例 | ❌ 不支持（`bridge.lock`） |
