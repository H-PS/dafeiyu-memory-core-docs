# 12 · 启动前验收标准

> 原则：**测实际行为，不测设计假设。**
> 每条给：步骤、判据、失败样例、对应模块。凡涉及 token 的，一律取 `token-ledger` 实测。

---

## 一、十二项验收

### #1 保存与删除的正确性

| 项 | 内容 |
|---|---|
| 步骤 | 写 20 条（含 3 条 embedding 必失败）→ 读回 → 删 5 条 → 三路检索 → 查投影与索引 |
| 判据 | ① **文本写入 20/20**（向量成功率单独统计，`status ∈ {pending,failed}` 不算失败）② 读回逐字相同 ③ 删后三路均不命中 ④ 索引无残留 docId ⑤ 投影与 A 一致 |
| 失败样例 | embedding 失败 → 整条被丢弃（错）；删后关键词仍命中（错） |
| 关联 | M01/M03 |

### #2 并发与版本语义

| 项 | 内容 |
|---|---|
| 步骤 | 3 写者 × 50 条并发 + 2 deleter 交错 + 同 opId 提交 5 次 + 4 个并发 clear |
| 判据 | ① 最终条数 == 150 − 删除数 ② 无重复 id ③ **`rev` 严格单调且唯一，不要求连续** ④ 重复 opId 不改条数 ⑤ `interactionCount` 累计 == 操作次数（S-1 回归） |
| 修订 | 不要求 rev 连续（并发合并会留空洞，属合法） |
| 关联 | M01/`08` §3 |

### #3 同义改写召回

| 项 | 内容 |
|---|---|
| 数据 | `fixtures/seed-200.jsonl`（种子固定）、`queries.jsonl` 的 `paraphrase` 类 10 条，每条带 `expectedIds[]` |
| 判据 | `Recall@3 ≥ 0.80`、`MRR ≥ 0.65` |
| 统计 | `Recall@k = 命中查询数 / N`（expected 任一中即算命中）；`MRR = mean(1/rank_firstHit)` |
| 关联 | M04 |

### #4 专名精确召回

| 项 | 内容 |
|---|---|
| 数据 | `exact_term` 类 10 条（5 正例 + 5 干扰例：`STM32F103C8T6` vs `STM32F407`；`[OWNER_QQ]` vs `[TEST_QQ]`） |
| 判据 | 正例 `Recall@1 = 1.0`；干扰例"进入 top3 的比例 ≤ 1/5" |
| 关联 | M03（BM25） |

### #5 时间检索

| 项 | 内容 |
|---|---|
| 时间基准 | **固定** `--fake-now 2026-10-31T18:00:00+08:00`；时区固定 `Asia/Shanghai` |
| 数据 | 5 条：今天/昨天/上周/上个月/三个月前 |
| 判据 | 可解析查询：返回结果**全部**在窗口内（不允许"大概对上"）；不可解析（"那次"）→ 返回空 + `reason:'no_time_expression'` |
| 关联 | M03/M04 |

### #6 多路 vs 单路（对照，不做机械排序）

| 项 | 内容 |
|---|---|
| 组 | A 仅语义 / B 语义+关键词 / C 三路 |
| 判据 | ① C 独立达标：`Recall@8 ≥ 0.85`、`MRR ≥ 0.70`、`privacyViolations = 0` ② C 相对 A 的 `Recall@8` 提升 ≥ 0.08 ③ `exact_term` 类 C 的 `Recall@1 ≥ 0.90` ④ 若 C 比 A 低 **>0.02** → 判实现有 bug |
| 明确删除 | ❌ 不要求 `C ≥ B ≥ A` 的逐级单调（统计上不成立，会逼着凑参） |
| 关联 | M04 |

### #7 注入精度

| 项 | 内容 |
|---|---|
| 数据集 A（完全无关） | 200 条无关记忆 + 一句无关闲聊 → 注入 ≤3 条、`estTokens ≤ 200` |
| 数据集 B（混合相关） | 200 条中 20 相关 / 30 弱相关 / 150 无关 → 注入 ≤8 条，**人判精确率 ≥ 0.60** |
| 关联 | M04 |

### #8 重复治理（三档分开测）

| 档 | 造数据 | 期望 |
|---|---|---|
| 完全重复 | 同句 3 次（归一化后相同 + cosSim ≥0.99） | Retain 阶段即合并 → A 层 1 条 |
| 可能重复 | cosSim 0.92-0.99（"板子好贵"/"价格劝退"） | **2 条都保留**，各带 `possibleDuplicate`，**均不 supersede** |
| 主题相似 | cosSim 0.65-0.92 | 2 条都保留，字段不变 |
| 幂等 | 同批数据整理两次 | 第二次 0 新增 |
| 重点 | ② 档必须验证"没有被误合并"（S-15 回归） |
| 关联 | M07/M08 |

### #9 归纳安全（九项）

| 检查 | 判据 |
|---|---|
| ① 原文不变 | 5 条事实 `text` 逐字节不变，`rev` 不变 |
| ② 证据可溯 | 每个 `evidence[].quote` 是原文连续子串；`memId` 存在且 active |
| ③ 独立来源 | 3 条同一天同一段对话 → **不得**升级为 active |
| ④ 否定 | 造"我不打算买X" → 观察不得写成"打算买X"；建 `conflictWith` |
| ⑤ 时间 | "以前在学X，现在不学了" → 时间限定必须保留 |
| ⑥ 数字 | 观察里的数字必须能在 evidence 找到（"200"不得变"500"） |
| ⑦ 主体 | 多人对话中 `assertedBy` 必须是正确的人 |
| ⑧ 矛盾 | 矛盾对 → 不生成单一观察，标 `conflictWith` 进待办 |
| ⑨ 可删除性 | 删除全部 observation 后，事实问答仍正确（INo-12） |
| 关联 | M08 |

### #10 跨会话延续

| 项 | 内容 |
|---|---|
| 触发条件统一 | 轮次 ≥60 / 估算 ≥40k / 空闲 ≥12h 且轮次 ≥20；测试**必须显式触发其中一条**并在报告里写明 |
| A（触发轮转） | 20 轮后手动把 `sessionMeta.turns` 调到 60 → 轮转 → 用户只发"想好了吗" |
| B（不触发） | 阈值调高，仅靠召回延续 |
| C（群聊） | 同 A，在 group key 下（依赖权限模型） |
| 判据 | 回复提及话题核心词；**不含**"你指的是什么"类反问 |
| 关联 | `04` §4.4、M04 |

### #11 Token 与人格（实测）

| 项 | 内容 |
|---|---|
| 条件 | 同一 40 轮剧本；A 基线（全块每轮）/ B Rev3；同模型、同 preset hash、同人格卡 hash；固定 fake-now |
| 数据源 | **`token-ledger` 实测**（`conversation().turns[].buckets`），非估算 |
| 判据 | ① **B 的 cost ≤ A 的 cost** ② B 的 prompt tokens < A ③ **必须报 `cacheHitRate` 变化** ④ 第 40 轮人格一致性人工检查通过（不说错名字、语气符合）⑤ 盲评质量 B ≥ A − 0.3 |
| 明确删除 | ❌ 不设"下降 ≥35%/45%"的固定百分比（`09` §4.5） |
| 关联 | M05、`09` |

### #12 记忆越权（四类，阻断级）

| 测试 | 步骤 | 判据 |
|---|---|---|
| ① 私聊隔离 | 私聊写 5 条含标识文本 → 其参与的群用 20 角度查询 | 命中 **0/20** |
| ② 群间隔离 | 群 A 写 5 条 → 群 B 20 角度查询 | 命中 **0/20**，反向同 |
| ③ 同群共享（正向） | 群 A 写 5 条 public 内容 | 同群召回 **5/5**（这是死锁修复的正向证明） |
| ④ 投影/摘要/dump 继承 | 群 A 的 projection 不含非 public 文本；quarantine 项不进召回；dump 不含凭据；注入日志无跨 key 的 `memId` | 全部 **0 违规** |
| 失败判定 | 任一非 0 → **阻断上线**，不允许"附条件通过" |
| 关联 | M02、`03` §4 |

## 二、阶段门槛（不过不许进下一阶段）

| 阶段 | 必过 |
|---|---|
| M0（store/permission/index/credential） | #1 #2 + 崩溃场景 5 例 + 判决表 10 例 + `eval-privacy --stage M0` = 0 + **dump 不含凭据（单测）** |
| M1-a（ledger） | 失效矩阵 6 例 + `09` 的 A/B 报告（T-1~T-6） |
| M1-b（recall） | #3 #4 #5 #6 #7 + `eval-privacy --stage M1` = 0 |
| M2（retain/reflect） | #8 #9 #10 + `eval-privacy --stage M2` = 0 |
| 最终 | #12 全量回归（阻断级） |

### 2.1 隐私必须分三阶段重跑

| 阶段 | 新增的风险面 | 必跑 |
|---|---|---|
| M0 | 权限字段、quarantine、新写路径、凭据文件 | 隐私测试 ①②③ |
| M1 | 召回通道、digest、注入断言 | 隐私测试 ①②③④ |
| M2 | Retain 自动写、Reflect 归纳（可能串人） | ①②③④ + 归纳安全 |

任一次非 0 → 当阶段不通过。**理由**：越权一旦引入，后续都建在它上面，越晚发现越贵。

## 四、验收记录模板（强制）

```
批次：M1-b / 日期
版本：commit abc1234
数据集：fixtures @ commit def5678
fixed-now：2026-10-31T18:00:00+08:00
preset hash：xxxx  人格卡 sha256：yyyy  模型：deepseek-flash

指标                  基线     目标     实测     结论
recall@8 full         0.78     0.85     0.91     PASS
Δ vs semantic          —       +0.08    +0.14    PASS
mrr                   0.61     0.70     0.76     PASS
exact recall@1        0.60     0.90     1.00     PASS
privacyViolations     0        0        0        PASS
...

失败用例：3 条（明细见附录）
遗留：paraphrase recall@3=0.70（目标 0.80），记 T-03，截止 M2
结论：附条件通过（条件：T-03 在 M2 前清零）
```

"附条件通过"必须写条件 + 截止里程碑，否则视为不通过。

## 五、验收不通过的处置

| 情况 | 处置 |
|---|---|
| 阻断级（#12、R-6/R-7/R-8、R-11/R-15） | **立即回滚对应模块**，不得"下次修" |
| 质量阈值不达标 | 记入调参清单（T-xx），明确截止里程碑 |
| 数据不足（基线未测） | 该阶段视为未验收 |
| 实测与估算混用 | 报告作废，重出 |
