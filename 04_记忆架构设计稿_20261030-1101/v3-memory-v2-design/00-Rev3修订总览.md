## 三、十三条关键决策（一句话各一条）

1. **A 层权威写服务只有一个** `memory-store.commit(op)`；旧函数是适配器（`05` §2）。
2. **人格每轮全文注入**；Ledger 只动表情清单 / 黑话表 / 睡眠规则 / 首回复节奏（`04` §2）。
3. **凭据独立存储** `state/agent-token.json`，`retireSession` 后强制下一轮重发（`04` §4）。
4. **权限四字段正交**：`origin` / `contentClass` / `scope.read` / `review.status`（`03` §2）。
5. **`owner_only` = 仅 `private:<botOwner>` 可读**，不含"发送者私有"与"被描述者私有"（`03` §3）。
6. **群聊死锁的修法是"内容分级 + 来源限定"，不是把 `not_requested` 改成 `approved`**（`03` §5）。
7. **权限失败进独立隔离库**，与候选池物理分离，且**无任何自动晋升路径**（`05` §4）。
8. **P 层劈成两半**：`memoryView` 可从 A 重建；`runtimeView` 只能从 S 重建（`01` §4）。
9. **`social-v2.json` 只保留 B 层与纯运行态**；token / interactionCount / ledger / rotationTx / epoch / reviewQueue / pendingEmbed 全部外移（`08` §2）。
10. **`estimateTokens` 是预算员，`token-ledger` 是会计**；报告里不得混用（`09` §2）。
11. **`/reset` 保持不清 A 层**；删除与 purge 是独立授权动作（`05` §6）。
12. **记忆工具进 `mcp__snowluma__` 命名空间**，不新建 server、不改 `SAFE_PREFIXES`（`05` §7）。
13. **`proposed` 观察不进召回、不进注入**；Reflect 无删除权（`07` §3）。

### 4.1 为什么行数降了 26%，排期不变

省掉的是"重复实现"（token 计量、原子写、备份、脱敏、语义检索底座），但省下来的时间**转移到了三件更贵的事**：

| 转移项 | 为什么比从零写更贵 |
|---|---|
| `social-v2.json` 拆分（`08`） | 要处理 43 处整文件重写、B 层语义连续性、迁移期双读；写错了是静默丢数据 |
| 兼容适配器（`05` §2） | 旧函数不能 throw、不能改签名，还要让 5 条旧路径在迁移期都工作 |
| 人格频率与 prefix cache 的实测（`09` §4） | 需要 40 轮 ×2 组对照、盲评、cacheHitRate 观测；这不是写代码，是做实验 |

**明确拒绝**："行数少了所以 11 周够"。任何排期调整必须由依赖关系与测试工作量驱动，不由代码行数驱动。

## 五、A/P/S/B 一句话定义（详见 `01`）

| 代号 | 一句话 | 可重建性 |
|---|---|---|
| **A** | 断言级长期记忆记录（一句话一条） | ❌ 不可重建 |
| **P** | 派生视图，供注入与查询 | ⚠️ **半可重建**：`memoryView` 可（从 A），`runtimeView` 只能从 S |
| **S** | 运行时状态（会话、游标、唤醒配置、B 层业务记忆） | ❌ 不可重建 |
| **B** | 业务级记忆概念（activeTopics / pendingThoughts / memberImpressions），**当前住在 S 里** | ❌ 不可重建（不在 A 里，粒度不同） |

**Rev2 的错误**：把 B 当成 P 的一部分，于是声称"P 可从 A 重建"。实际上 B 的三个集合在 A 里没有对应粒度（A 是"一条记忆"，B 是"一个进行中的话题"），**删掉 S 就丢**。Rev3 明确：B 是 S 的一部分，P 的 `runtimeView` 是 B 的只读投影。
