# 二、主要架构变更（3 项）

## 2.1 数据层从 2 层变 3 层

```
原：A（事实源） + B（投影，实为混合）
现：A（事实源） + P（记忆投影，新文件） + S（运行状态）
```

**理由**：`social-v2.json` 的 21 个字段中 18 个无法从 A 重建（`11 §2.2`，`SOURCE_CONFIRMED`）。

## 2.2 版本从 1 个变 2 个

```
原：rev（内容 + 元数据 + 乐观锁混用）
现：rev（全量） + contentRev（内容） + vecContentRev（向量对应内容版本）
```

**理由**：单版本会让元数据变更打断内容操作（edit 409、多群审批互相失效、WAL 重放丢编辑）。

## 2.3 M0 从"半可用"变"可上线"

```
原 M0：修写入竞态，但留隐私（F-02）、丢正文（F-08）、恢复绕墓碑（F-11）
现 M0：三者全部纳入 + 关闭分享与 B 编辑入口
```

# 八、需与用户确认的 3 个"产品语义"

以下不是技术细节，是**用户体验/隐私语义**，必须用户明确：

## 8.1 clear 之后还有残留吗（D-21）

```
场景：用户发 clear，但之前有个 append 卡在 embed（最多 30s）
方案 A：append 被丢弃 → "清了就是清了"
方案 B：append 写入成功 → 用户看到"清空后还有一条"
```

## 8.2 点 reset 会丢记忆吗（D-23）

```
V1 现状：reset 清空整个 social-v2.json（含记忆三字段）
方案 A：只重置会话（消息/未读/唤醒），**记忆保留**
方案 B：连记忆一起清
```

## 8.3 删原件时群里的副本怎么办（D-15）

```
方案 A：默认级联删除（隐私优先）
方案 B：提供"保留副本"选项 + 严重警告（内容连续性优先）
本版默认：只实现级联（不提供选项）
```
