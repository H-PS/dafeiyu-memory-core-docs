# 09 · 实施路线图（修订版）

> M0 / M1 / M2 基础版都属于启动前目标；M3 属于启动后。
> 本版同步：新增 `memory-permission.js`（M0）、凭据过渡态（M0）、三池分离（M2）、模块编号统一为 M01~M14（见 01 §8）。
> **本路线图不构成实施授权。**

---

## 1. 依赖关系

```
        ┌─────────────────────────────────────────────────┐
        │ M0 可靠记忆基础                                   │
        │ A/P/S · WAL · 三版本 · 权限模型 · 索引写入钩子     │
        │ 凭据过渡态（token 每轮→首轮）                      │
        └───────────────┬─────────────────────────────────┘
                        │
        ┌───────────────┼───────────────┬─────────────────┐
        ▼               ▼               ▼                 ▼
 ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌──────────────────┐
 │ M1-b 上下文 │ │ M1-a 召回   │ │ 凭据目标态  │ │ M2 形成与整理      │
 │ Ledger+轮转 │ │ 3路+融合    │ │ 带外绑定    │ │ Retain/Reflect    │
 └─────┬──────┘ └─────┬──────┘ └─────┬──────┘ └────────┬─────────┘
       │              │              │                  │
       └──────────────┴──────┬───────┴──────────────────┘
                             ▼
                  ┌──────────────────────┐
                  │ 联调 + 12 项验收 + 对比│
                  └──────────┬───────────┘
                             ▼
                  ┌──────────────────────┐
                  │ M3 图与主动关联（启动后）│
                  └──────────────────────┘
```

关键路径：M0 → M1-b → M1-a → M2。

**M1-b 先于 M1-a**：Ledger 是纯减法、风险低、收益立刻显现，且不依赖任何记忆数据。先清干净上下文再加召回内容，否则"加了召回但上下文更脏"互相抵消，且无法归因。

**凭据目标态（S-13）单独成一个工作项**，因为它依赖 `12-RISKS-PERMISSIONS.md` §6 的 F-1 核查结论，可能与 M1 并行的任意时点插入。
