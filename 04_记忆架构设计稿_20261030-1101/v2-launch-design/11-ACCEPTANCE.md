# 11 · 启动前验收标准（修订版）

> 本版修复验收设计缺陷：#1 embedding 失败误判、#2 rev 连续性误判、#3/#4/#5 判据不明确、#6 机械排序要求、#7 数据集混用、#8 重复定义粗糙、#9 检查项不全、#10 时间条件不统一、#11 轮数不统一、#12 隔离测试不完整。
> 性能指标一律三列：**基线 / 目标 / 实测**。实测列为空 → 视为未验收。

---

## 0. 验收总原则

1. **每条验收必须有可执行命令 + 数据集版本 + 通过阈值**。写不出命令的，不算验收项。
2. **隐私类验收在 M0 / M1 / M2 三阶段各自重跑**，不得只在最后全量跑一次（见 §5）。
3. **任何"实测"列留空的记录视为未验收**，不得以"应该没问题"代替。
4. **阻断级失败（#12、INo-13）命中 1 条即整体不通过**，不允许附条件通过。

## 1. 十二项验收

### #1 能否正确保存和删除记忆

| 项 | 内容 |
|---|---|
| 目的 | 基础 CRUD 正确性 + **embedding 失败不得导致记忆被判为"无法保存"** |
| 步骤 | ① 写 20 条（含 3 条 embedding 必然失败的构造：超长文本触发 Ollama 拒绝）② 逐条读出 ③ 删 5 条 ④ 再读 ⑤ 检查 P 层与索引 |
| 判据 | ① **20/20 落盘**，其中 3 条 `embedding.status ∈ {pending, failed}` 但记录存在 ② 读回文本与写入逐字相同 ③ 删除后三路检索均不命中 ④ P 层与 A 层一致 ⑤ 索引无残留 id |
| **修订点** | 上一版要求"20/20 成功"，未区分"记录写入"与"向量生成"。断言应为：**文本写入成功率 100%，向量成功率单独统计**。embedding 失败是允许的降级，不是保存失败 |
| 修复后验证 | 关掉 Ollama 后写 5 条 → A 层 5 条，`embedding.status='pending'`；恢复 Ollama 后 5 分钟内全部变 `ready`（M2-R12） |
| 关联 | M0-01/03/04 |

### #2 并发操作是否会丢失更新

| 项 | 内容 |
|---|---|
| 目的 | 并发下的写不丢、**rev 语义正确** |
| 步骤 | ① 3 个并发写入者 × 50 条（同 key，不同文本）② 2 个并发 deleter 交错删 10 条 ③ 同一 `opId` 重复提交 5 次 ④ 4 个并发 `clear` |
| 判据 | ① 最终条数 == 150 − 实际删除数 ② 无重复 `id` ③ **每个 id 的 `rev` 严格单调递增；全局无重复 (id, rev) 对；不要求 rev 连续** ④ 重复 opId 提交后条数不变 ⑤ `interactionCount` 累计 == 操作次数（防 S-1 丢更新） |
| **修订点** | 上一版要求"rev 无重复无跳号"。**跳号是合法的**（并发合并、失败回滚都会产生空洞）。只断言 `单调 + 唯一`，不断言连续 |
| 反例 | 若实现用"全局自增计数器"保证连续，反而会在崩溃恢复后产生重复值 → 那是缺陷 |
| 关联 | M0-06、INo-4/5 |

### #3 能否找到关键词不同但语义相同的历史记忆

| 项 | 内容 |
|---|---|
| 数据集 | `tests/fixtures/memory-seed.jsonl` v1（200 条，随机种子固定 42） |
| 查询集 | `queries.jsonl` 的 `paraphrase` 类，**10 条**，每条含 `{id, q, expectedIds[], note}` |
| 固定查询（举例，全部列出见数据集） | `q_para_01`: "啃单片机" → expected: `[mem_stm32_01]`<br>`q_para_02`: "价格有点劝退" → `[mem_price_02]`<br>`q_para_03`: "周末那个展" → `[mem_expo_01]` |
| 判据 | `Recall@3 ≥ 0.80`（10 条中 ≥8 条把 expected 放进 top3）<br>`MRR ≥ 0.65` |
| 统计方式 | `Recall@k = #{expected ∩ topK ≠ ∅} / N`（expected 可多条，命中任一即算命中该查询）；`MRR = mean(1/rank_firstHit)`；未命中记 0 |
| **修订点** | 上一版写"6 组同义对 ≥5 组命中"，既没有固定查询串，也没有说明 expected 是单条还是多条、命中算在哪一位 |
| 关联 | M1-R1 |

### #4 能否准确找到特定项目名称

| 项 | 内容 |
|---|---|
| 数据集 | 同 seed v1，含 5 条专名记录 + 20 条"近似干扰"（同前缀不同型号/不同尾号） |
| 查询集 | `queries.jsonl` 的 `exact_term` 类，**10 条**（5 条正例 + 5 条干扰例） |
| 固定查询 | `q_term_01`: "STM32F103C8T6" → `[mem_mcu_01]`，干扰 `mem_mcu_02`(F407) 必须不在 top3<br>`q_term_02`: "RoboMaster" → `[mem_rm_01]`<br>`q_term_03`: "[OWNER_QQ]" → `[mem_qq_01]`，干扰 `[TEST_QQ]` 不在 top3 |
| 判据 | 正例 `Recall@1 = 1.0`（5/5 排第一）<br>干扰例：`干扰项进入 top3 的比例 ≤ 1/5` |
| **修订点** | 上一版只写"5/5 命中且干扰不进 top3"，未区分正例/干扰例两类查询，也未给阈值 |
| 关联 | M1-R2、§2.3 |

### #5 能否根据时间找到过去的经历

| 项 | 内容 |
|---|---|
| **时间基准（必须固定）** | 数据集里所有记录的时间戳以 `2026-10-31T18:00:00+08:00` 为"现在"构建。验收时把系统时钟 fake 到该时刻（`--fake-now` 参数），**不得依赖真实运行日期** |
| 时区 | 固定 `Asia/Shanghai`，不随机器 |
| 数据集 | 5 条记录：今天 / 昨天 / 上周（本周一之前）/ 上个月 / 三个月前 |
| 查询集 | `queries.jsonl` 的 `temporal` 类，10 条 |
| 固定查询 | `q_time_01`: "昨天聊了什么" → 期望 top1 ∈ 昨天集合<br>`q_time_02`: "上个月那个事" → top1 ∈ 上月集合<br>`q_time_03`: "最近有什么" → 返回集合 ⊆ 过去 7 天<br>`q_time_04`: "那次" → **返回空**（不可解析） |
| 判据 | 可解析查询：`窗口内命中率 = 1.0`（返回的每条都必须在窗口内，不允许"大概对上"）<br>不可解析查询：返回 `[]` 且 `meta.reason='no_time_expression'` |
| **修订点** | 上一版没定义"现在"是哪天、哪个时区、窗口边界含不含端点 |
| 关联 | M1-R3、04 §6.1 |

### #6 多路检索是否比单纯向量检索更有效

| 项 | 内容 |
|---|---|
| **修订点（重要）** | 上一版要求 `C ≥ B ≥ A` 的机械排序。这在统计上不成立：B（加关键词）可能因为把专名 queries 排好而略微降低 paraphrase 类表现，导致 B < A 但总体更好。**机械单调要求会逼着实现去调参凑数** |
| 修订后方法 | **质量阈值 + 对照评测**，不做单调断言 |
| 对照组 | A = 仅 semantic；B = semantic + keyword；C = 三路（full） |
| 判据（三组各自独立判） | ① C 组必须达到：`Recall@8 ≥ 0.85`、`MRR ≥ 0.70`、`privacyViolations = 0`<br>② C 组相对 A 组：`Recall@8` 提升 **≥ 0.08**（单侧）<br>③ 分类型看：C 组在 `exact_term` 类上 `Recall@1 ≥ 0.90`，A 组该指标若也 ≥0.90 则允许 C ≈ A（说明语义模型对专名已够强，属正常）<br>④ 若 C 的 `Recall@8` 比 A 低 **超过 0.02** → 判为融合实现有 bug，必须查 |
| 报告要求 | 三个模式各出一份 `reports/recall-<mode>.json`，并在 `CROSS-DOC-CONSISTENCY.md` 附对比表（基线/目标/实测） |
| 关联 | M1-R5 |

### #7 是否会注入大量无关记忆

| 项 | 内容 |
|---|---|
| **修订点** | 上一版只用一个"200 条无关记忆"的数据集，测不出"部分相关"时的精度问题 |
| 数据集 A（完全无关） | 200 条与当前话题无任何语义关联的记忆（不同主题、不同人物）。查询：一句与这些记忆无关的闲聊 |
| 数据集 B（混合相关） | 200 条中 20 条相关、30 条弱相关、150 条无关。查询：该相关话题 |
| 判据 A | 注入条目 ≤ 3；`avgInjectTokens ≤ 200`（应该几乎检不到东西） |
| 判据 B | 注入条目 ≤ 8；精确率 ≥ 0.60（人判：8 条中 ≥5 条与话题相关）；`avgInjectTokens ≤ 600` |
| 反向判据 | 若 A 场景注入了 ≥5 条，说明阈值/融合有问题，属不通过 |
| 关联 | M1-R7、K6 |

### #8 是否存在重复记忆

| 项 | 内容 |
|---|---|
| **修订点** | 上一版把"重复"当成一个概念，实际有三种，处置完全不同 |
| 三档数据集 | ① **完全重复**：归一化文本相同（同句话 3 次）<br>② **可能重复**：cosSim 0.92-0.99（"板子好贵"/"价格劝退"）<br>③ **仅主题相似**：cosSim 0.65-0.92（"在学 STM32"/"下周三去电子城"） |
| 判据 | ① 完全重复：Retain 阶段即合并（A 层 1 条），Reflect 后仍有 1 条 active<br>② 可能重复：A 层 **2 条都保留**，各自带 `extra.possibleDuplicate`，**均不 supersede**<br>③ 主题相似：2 条都保留，任何字段不变<br>复现性：同批数据整理两次，第二次 0 新增 |
| 关键 | ② 档必须验证"没有被误合并"。这是 S-15 的直接回归 |
| 关联 | M2-R4、M2-F1、M2-F2 |

### #9 自动归纳是否会错误改变原始事实

| 项 | 内容 |
|---|---|
| **修订点** | 上一版只查"原文是否逐字不变"，不够。归纳的错误有五种形态，要分别测 |
| 数据集 | 5 条事实：`f1` 我在学 STM32 / `f2` 板子还没买 / `f3` 预算 200 以内 / `f4` 老师推荐最小系统板 / `f5` 下周去电子城 |
| 检查一（原文不变） | 5 条 `text` 逐字节不变；`rev` 不变（若变，必须 `contentRev` 也不变） |
| 检查二（证据可溯） | 每条 `evidence[].quote` 是原文连续子串；`memId` 全部存在且 `lifecycle='active'` |
| 检查三（独立来源） | 3 条证据来自同一天同一段对话 → **不得升级为 active** |
| **检查四（否定）** | 造一条 "我不打算买最小系统板" → 观察不得写成"他打算买最小系统板"；与 `f4` 建立 `conflictWith` |
| **检查五（时间）** | 造 "以前在学 STM32，现在不学了" → 观察的时间限定必须保留（`validUntil` 或文本中体现"曾经"），不得写成现在时 |
| **检查六（数字）** | 观察中出现的任何数字必须能在 evidence 原文找到（"预算 200" 不得写成 "预算 500"） |
| **检查七（主体）** | 多人对话中，观察必须挂在正确 `assertedBy` 上（A 说的事不得记到 B 名下） |
| **检查八（矛盾）** | 造一对矛盾事实 → 不生成单一观察，标 `conflictWith` 并进审核 |
| 检查九（INo-12） | 删除全部 observation 后，问"我在学什么"仍能正确回答 |
| 判据 | 一到八全部满足；九必须通过 |
| 关联 | M2-F5~F8、M2-F13、INo-12 |

### #10 是否能够跨会话延续未完成的话题

| 项 | 内容 |
|---|---|
| **修订点** | 上一版用"中断 30 分钟（模拟）"，与 05 文档的 `rotateAfterIdleMs: 12h` 不一致，导致测试根本没触发轮转 |
| 统一条件 | 轮转触发三条件（轮次 ≥60 / 估算 ≥40k token / 空闲 ≥12h 且轮次 ≥20），测试**必须显式触发其中一条**，并在报告里写明触发的是哪一条 |
| 测试 A（轮转触发） | 20 轮对话后，手动把 `sessionMeta.turns` 调到 60 触发轮转；下一轮用户只发"想好了吗" |
| 测试 B（无轮转） | 同场景但把阈值调高不触发；验证"仅靠 A 层召回"也能延续 |
| 测试 C（群聊） | 同 A，但在群 key 下；依赖权限模型（S-11 修复） |
| 判据 | 回复中提及话题核心词（"开发板"/"STM32"）；**不含**"你指的是什么"类反问 |
| 判定方式 | 关键词匹配（客观）+ 人工核对（3 条抽样） |
| 关联 | M2-R6、05 §5.2 |

### #11 是否能在减少 Token 的同时维持回答质量

| 项 | 内容 |
|---|---|
| **修订点** | 上一版"20 轮测试 token、40 轮测人格"，两套条件不可比；且 token 用估算值 |
| 统一条件 | **同一份 40 轮剧本**，A 组（现状注入）/ B 组（Ledger + 预算）。在第 20 轮与第 40 轮各取一次快照 |
| Token 统计（**必须实测**） | 优先用模型 API 返回的 `usage.prompt_tokens` 累加；若无 usage，用 `estimateTokens` 并在报告中标注"估算"及 `calibrationFactor` |
| 判据 | ① **第 1-20 轮累计** input token：B 相对 A 下降 ≥ 35%<br>② **第 1-40 轮累计**：下降 ≥ 45%（Ledger 收益随轮数增长）<br>③ 第 40 轮时模型仍自称人格卡中的名字、且符合人格卡语气（人工 1-5 分 ≥4）<br>④ 盲评质量：B 组均值 ≥ A 组 − 0.3 分 |
| **关于基线** | 上一版没给基线数值。基线必须在 M1-b 开工前用现状代码实测一次并写入报告，否则"下降 35%"无从计算 |
| 质量评分维度 | 人格一致性 / 相关性 / 不重复 / 记忆使用 / 自然度，各 1-5 分，两名评分者独立打分（一致性差 > 1 分时第三人裁决） |
| 关联 | M1-C1~C8、05 §2.3 |

### #12 群聊和私聊之间是否存在记忆越权

| 项 | 内容 |
|---|---|
| **修订点** | 上一版只测"私聊→群"一个方向。实际有四类隔离，且有第四类容易被漏：投影/摘要 |
| 测试一（私聊隔离） | 私聊写 5 条含标识文本（"我家的猫叫豆豆"）→ 在**主人参与的所有群**里用 20 个角度查询（"豆豆"/"我家的猫"/"宠物"/"养了什么"）→ 群聊命中 **0/20** |
| 测试二（群间隔离） | 群 A 写 5 条 → 在群 B 用 20 个角度查询 → 命中 **0/20**；反向同样 |
| 测试三（同群共享） | 群 A 写 5 条 public 内容 → 群 A 内立即可召回 **5/5**（这是 S-11 的修复验证，也是唯一允许的"共享"） |
| 测试四（投影/摘要权限继承） | ① 群 A 的 P 层 digest 中不得出现 `contentClass != 'public'` 的文本<br>② 群 A 的回忆结果中不得出现 quarantine 项<br>③ 私聊的 digest 不含群聊专属标识文本<br>④ 任何注入日志里不得出现 `key !== 当前 key` 的 `memId` |
| 判据 | 全部 **0 违规**（任何一条非 0 即阻断） |
| 附加 | 检查 `audit` 日志中 `recall_permission_violation` 事件数 = 0 |
| 关联 | INo-13、01 §3、SCHEMA §9 |

## 3. 隐私验收的分阶段重跑（重要修订）

隐私不是"最后测一次"，而是**每加一层能力就重测**：

| 阶段 | 新增了什么可能泄露的东西 | 必跑 |
|---|---|---|
| M0 结束 | 权限字段、quarantine 文件、新的写路径 | `eval-privacy --stage M0`（#12 测试一/二/三） |
| M1 结束 | 召回通道、digest、注入断言 | `eval-privacy --stage M1`（#12 全部四项） |
| M2 结束 | Retain 自动写、Reflect 归纳（可能把 A 的事实串到 B） | `eval-privacy --stage M2`（#12 全部 + `reflect-cases`） |

任一次非 0 → **当阶段不通过，不得进入下一阶段**。理由：越权一旦引入，后续所有阶段都在它之上叠加，越晚发现修复成本越高。
