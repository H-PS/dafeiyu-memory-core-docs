### 1.2 写入机制（先说清"写"是什么样）

1. **单一序列化器**：所有保存共用 `buildSocialV2Snapshot()`（注释自述"序列化结构单一来源"，`:8933-8934`）。
2. **快照器是显式字段白名单**：`:8938-8960` 只输出列出的 19 类字段（wakeConfig / recentMessages / unread / lastWakeReason / lastAiReplyAt / lastActionAt / **agentToken** / bootstrapSent / wakeTimes / sendTimes / stickerCollectTimes / lastIncomingAt / preSleep 三字段 / lastUnreadSeq / lastReadThroughSeq / activeTopics / pendingThoughts / memberImpressions / seenForwardIds）。**st 上任何未列入白名单的字段，每次保存都被静默丢弃——不是被旧快照覆盖，而是根本不落盘。**
3. **普通版吞错、严格版抛错**：普通版 try/catch 后仅记日志（供 40+ 个调用方，注释 `:8965`）；Strict 版失败向上抛（注释 `:8974-8975`：仅 memory 的 append/remove/clear 使用，"失败可发现 + 字段回滚"）。
4. **载入侧防覆盖**：`loadSocialV2State()` 载入期间 stat 两次比对 mtime（`:8820`、`:8916`），若文件在载入期间被其它进程改写则**跳过回写**（`:8925` 不执行）。守卫只在载入窗口有效，运行期保存不再检查 mtime。
5. **载入修复也是写点**：`:8834-8851` 对缺失/重复的 `agentToken` 就地补生成（16 字节）并去重——这是审计未单列的**第 5 类 token 写点**。

### 1.4 三个判定

1. **与审计一致性**：审计"约 43 处整文件重写"= 上表 #1–#43（save 函数调用点），逐项核对**一致**；新增 #44 直写点与"第 5 类 token 写点"（§1.2-5，`:8834-8851`）。计数口径：43 = save 调用点；真实写文件路径 = 3 条（普通版 / Strict 版 / 直写），全部汇于 `atomicWriteJson`。
2. **新增字段是否被旧快照覆盖**：不存在"旧快照覆盖新字段"——因为快照器是**白名单输出**，未登记的新字段每次保存直接丢失；反之，任何外部进程在 bridge 运行期对文件的修改，都会被 bridge 下一次保存（43+1 中任意一处）整文件覆盖（载入期 mtime 守卫不覆盖运行期）。
3. **哪些必须纳入统一写机制**：#1–#43 全部（单进程内存真相 + 单一序列化器的前提不变）；#44 直写点必须改走统一路径（它当前绕过快照器，是未来加字段时最容易被遗忘的一处）；memory 四端点已具备"失败可发现"语义（Strict），是 `commit()` 设计的现成衔接点。

### 4.2 三条 reset 路径的完整调用链

**路径 A：控制台"重置二代状态" POST `/api/socialV2/reset`（:4587）**
```
sessionEpoch++ → 清定时器 → drainAllPromptQueues
→ 逐 key：delete state.sessions[key] → stopRetiredSessionWork(sid,key)
  （注释 :4596-4598：先停 DSH 侧在途 turn，否则输出被静默丢弃、MCP 发送全 403）
  → 清 7 个会话级 Map → api.events.forget(sid)
→ delete state.sessionPolicies[key]
→ forgetAgentToken(key)          :4613
→ socialV2.conversations.delete(key)  :4614   ← 紧邻，同一循环内
→ seenForwardIds.delete(key)
→ saveState()                    :4617
→ 清唤醒相关 5 个 Map → socialV2.paused=false
→ atomicWriteJson(SOCIAL_V2_FILE, {conversations:{}})  :4624 ← 整文件写空（U-8 #44）
```
失败分支：循环内**无 try/catch**——中途抛错则该请求 500，内存 Map 已部分删除但 `saveState()`/写空均未执行，磁盘仍是旧状态，重启后载入旧文件（半恢复）。成功路径则 S 层被整体清空（含 token，随对象删除消失）。

**路径 B：控制台"清除会话上下文" POST `/api/session/reset`（:7389）**
```
… 清 collectors/pending/queued/social.* → cancelSocialTimers/clearSocialV2Timers
→ forgetAgentToken(key)          :7432
→ socialV2.conversations.delete(key)  :7433   ← 紧邻
→ seenForwardIds.delete(key)
→ saveSocialV2State()            :7435   ← 此处之后 token 才真正从磁盘消失
→ saveState()                    :7436
→ stopSessionWork（try/catch，失败仅告警）:7438-7439
→ archiveSession（try/catch 吞错）     :7440
```
失败分支：保存发生在 stop/archive **之前**——若进程在 :7436 与 :7438 之间崩溃，磁盘已是"会话已删"，DSH 侧旧会话仍在跑（输出丢弃、MCP 403，与 :4597 注释语义一致）；stop/archive 失败不回滚已保存状态。

```
→ saveState() :11312 → stopSessionWork（try/catch）:11314 → archiveSession（try/catch）:11316
→ sendToQQ('已重置会话…') :11317
```
失败分支语义与路径 B 相同。**A 层长期记忆三条路径均不触碰（R11 保持）**。

## 五、U-1 · acquireLock 语义

### 5.1 核查卡

| 字段 | 内容 |
|---|---|
| 核查编号 | U-1 |
| 结论 | **CONFIRMED** |
| 证据位置 | 定义 `bridge.js:1080-1142`；`releaseLock()` `:1143-1149`；唯一调用点 `main()` `:1390`；端口探测 `consolePortInUse()` `:1064-1078`（netstat/ss） |
| 实际行为 | 启动期**单实例互斥锁**：① `state/bridge.lock` 以 `flag:'wx'` 原子创建并写入 PID（0600，避免"先建空文件再写 PID"窗口，`:1082-1091`）；② EEXIST 时读 PID 判活——空文件/非法 PID = 过期锁；`kill(pid,0)` 成功还要**再探测控制台端口**才认定"活着"（防 PID 回收误判，`:1104-1108`）；ESRCH = 过期；**EPERM = 疑似过期但需端口空闲**（`:1112-1123`，修复了"PID 被系统回收给受保护进程导致桥接永久起不来"的旧 bug）；③ 过期则删锁重试一次；活实例则 `exit(2)`。`releaseLock` 仅当锁内 PID 等于自身才删除 |
| 影响范围 | 08 §4（并发前提）、16 §一 U-1 处置（"维护脚本默认要求 bridge 停止"）**维持不变** |
| 实施门禁 | V-5 关闭。结论：acquireLock 是**进程生命周期级**的单实例锁，**不是**通用并发锁——无超时、无重入、无共享模式、不给脚本用；它防"第二个 bridge"，不防"脚本趁 bridge 运行改 social-v2.json"（该风险由 U-8 §1.4-2 回答：运行期任何外部修改都会被下一次保存覆盖） |
| 遗留问题 | 无（未做破坏性并发实测，按要求不做；语义从代码完整可读） |

## 八、汇总

### 8.1 已确认事实（全部有 文件:行号）

1. social-v2.json 写入 = 3 条物理路径（普通保存 38 处 / Strict 5 处 / 直写 1 处），调用点共 44 处；快照器为**显式字段白名单**，未登记字段每次保存丢失。
2. token 写点实为 **5 类**（init `:8782` / rotate `:2795` / 载入修复 `:8834-8851` / 快照 `:8945` / 脱敏索引维护）；读取方共 **8 处代码位置**（§2.2-①②③④）+ 7 个 harness 测试脚本；**无任何一方从 social-v2.json 文件读 token**。
3. token 进入模型的通道是 **3 个 prompt 构造器**（`:4363` notify-ai、`:10674` 唤醒、`:10751` 防永眠提醒）；`qq_get_prompt` 响应**不含** token。
4. 三条 reset 路径均为 `forgetAgentToken → conversations.delete` 紧邻执行；`/api/socialV2/reset` 另整文件写空。
5. acquireLock = 启动期单实例文件锁（'wx'+PID+端口探测+EPERM 处置），非通用锁。
6. MCP：DSH spawn 3 个 stdio server；bridge 不 spawn；工具经 bridge HTTP 三重鉴权 → 方案 A 无障碍。
7. DSH compaction + 工具结果修剪**启用中**（50k/45k/2k）；会话存储 zstd。
8. 控制台（前端+插件+状态端点）不展示会话 token。
9. `dailyBackup()`、`rotation-journal/rotationTx/resetTx/digest/withKeyLock` 在代码中**不存在**（grep 零命中）；唯一既有备份是 memory-vector 自身的 `backups/`（7 份，仅 memory-vectors.jsonl，`memory-vector.js:124-135`）。
