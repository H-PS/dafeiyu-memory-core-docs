## 二、本轮新确认（CONFIRMED）

### C-1 · `v2SessionAllowed` 就是 `isSessionAllowedInCurrentMode`（原 U-9 结案）

```js
// bridge.js:3167
const v2SessionAllowed = isSessionAllowedInCurrentMode;
```

`isSessionAllowedInCurrentMode`（`:2713`）→ `modeAllowed`（`:2666`）→ `allowed(kind,id,cfg)`（`:1358`）。

**结论**：记忆端点（如 `:6868`）的 `v2SessionAllowed(key)` **确实包含白名单校验**。
**原审计 U-9 从 `【UNCONFIRMED】` 升级为 `【已确认】`。**
**对设计的影响**：`canRead` 仍不引入白名单（两层正交），但"白名单移除后旧会话读不到记忆"这一行为**已在端点层成立**，不需要 `canRead` 再做。

### C-2 · token 的全部赋值与拷贝点

| 位置 | 行为 | 备注 |
|---|---|---|
| `bridge.js:8782` | 会话初始化 `crypto.randomBytes(16)` | 16 字节 |
| `bridge.js:2795` | `retireSession` 轮换 `crypto.randomBytes(24)` | 24 字节 |
| `bridge.js:8945` | `buildSocialV2Snapshot()` 拷贝 token | ⇒ 随 S 层保存落盘 |
| `bridge.js:11308` / `:4613` | `forgetAgentToken(key)` | 只清脱敏集合；配合 `conversations.delete` 使 token 消失 |

**读取点**：`agentTokenOk :3149`、`isLiveAgentToken :3162`、prompt 注入 `:4363` 与 `:10674`。

### C-3 · 凭据脱敏集合的保留代际

```js
// bridge.js:540-566
rememberAgentToken(key, token)  // 保留 [当前代, 上一代]，丢弃两代前
forgetAgentToken(key)           // 整体摘除
```

**结论**：上一代 token **只留在脱敏集合里用于日志/出站脱敏**；`agentTokenOk` 只比 `st.agentToken`（当前代），因此**旧 token 立即不可认证**。这支持 `04` §5.2 "立即失效、无宽限"的结论。

### C-4 · DSH 接受/拒绝的两条失败路径都存在

```js
// bridge.js:9542-9554
try { accepted = await api.sessions.prompt({...}); } catch (error) { ... }   // 抛错
if (!accepted.result.ok) { ... 失败分支 ... }                                 // 返回 ok:false
```

**结论**：`04` §8.2 的四态（constructed / queued / accepted / failed）覆盖完整——抛错与 `ok:false` 都归 `failed`。
