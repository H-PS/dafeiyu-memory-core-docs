## 一、系统是什么（四层，一句话各一层）

```
QQ 客户端
   │  (QQ 协议)
SnowLuma  OneBot v11 实现   ws://127.0.0.1:3001 / http 3000
   │  (OneBot 事件 / API)
qq-bridge  Node 主程序      127.0.0.1:3100（控制台 + 内部 HTTP API）
   │  (DSH RPC)
DSH web    Agent 底座       127.0.0.1:3080，preset = qq-chat-v2
   │
DeepSeek   模型          deepseek-account / deepseek-flash（可切）
```

| 层 | 证据 |
|---|---|
| 端口与 URL | `config.json:2-23`（`dsh.baseUrl=…:3080`、`snowluma.wsUrl=…:3001`、`snowluma.httpUrl=…:3000`）、`config.json:45`（`consolePort: 3100`） |
| SnowLuma 是 OneBot v11 | `SECURITY_BASELINE.md` §2.3 提到 `onebotSend()`；`FOLDER_MAP.md` 提"连 SnowLuma 的 OneBot WS" |
| DSH 是 agent 底座 | `src/dsh-client.js`、`bridge.js` 里 `api.sessions.*` / `api.workspace.*` |
| preset 是 qq-chat-v2 | `config.json:116` `socialV2.agentPreset: "qq-chat-v2"`；`dsh/agent-presets/qq-chat-v2/agent.cordis.yml` |

**核心设计意图**（来自项目全景 §一）：不是助手，是一只猫；不干活、不解释、短句、会拒绝。人格稳定性靠三层：人格卡 + preset（行为协议）+ 记忆（连续性）。

**结论**：这个项目的**安全与工程底座比 Memory V2 设计文档假设的要强得多**（尤其令牌、工具面、出站审计、原子写、token 实测）；而 **智能能力（多路召回、归纳、压缩、任务队列）几乎为零**。

这正好与 Memory V2 的方向互补——但也意味着 Memory V2 里有若干模块是**重复建设**，见 `05-Memory-V2能力映射.md`。
