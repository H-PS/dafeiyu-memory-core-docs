# 一、这是什么

**一只住在电脑里的猫，通过 QQ 群/私聊跟你聊天。**

| 层 | 组件 | 端口 | 职责 |
|---|---|---|---|
| 接入 | SnowLuma（OneBot v11） | 3001 / 3000 | 登录机器人账号，收发 QQ 消息 |
| 桥接 | qq-bridge | 3100 | 会话管理、社交仿真、主动搭话、记忆存取、控制台 |
| 大脑 | DSH web | 3080 | Agent 底座，preset `qq-chat-v2` |
| 模型 | DeepSeek | — | `deepseek-account / deepseek-flash` |
| 人格 | `roles/大肥鱼.md` | — | 5.2 KB / 6 节 |
| 记忆 | A 层向量（102 条）+ B 层社交状态 | — | `state/memory-vectors.jsonl` / `social-v2.json` |

**核心设计意图**：她不是助手，是一只猫。不干活、不解释、短句、会拒绝。人格的稳定性靠三层保证：人格卡（人设）+ preset（行为协议）+ 记忆（连续性）。

# 七、经验与方案（可复用的决策）

## 7.1 架构经验

```
1. 三层分工要清晰：人格（她是谁）/ 记忆（她记得什么）/ 仿真协议（她怎么做）
   混在一起就会出现"人格被协议压过"——这也是 preset 里 3 处身份锚点必须删的原因

2. 能力必须写进 description，否则模型不会用
   qq_memory_query 带 topic 才查 A 层，但说明书没写 → 她永远只看到 B 层那几条
   → 加参数就同步改 description，还要检查 preset 协议有没有复述旧用法

3. 身份锚点是人格的头号杀手
   "You are a coding agent""你是 DeepSeek 鲸鱼""Q 版小鲸鱼"——任何一处都能覆盖掉人格卡
   → 新建人格时先全局搜一遍身份声明

4. 注入顺序决定权重：仿真提示词 → 人格提示词 → 本轮消息
   人格层保存即生效，仿真层需重启 DSH —— 这个差异要记牢
```

## 7.2 数据经验

```
5. 同步数据永远不做"润色"
   差三个字（是/，、她/让我、定了/我定了）就让逐字匹配全废

6. 用户复述天然会丢数字、括号、标点
   归一化必须把这些一起剥掉，只留语义骨架（第 4 级匹配就是这么来的）

7. 两套存储之间要有桥，否则"她说的"和"库里存的"永远对不上
   B 层印象 ≠ A 层向量，没有同步机制时必然脱节

8. 时间字段要分两种：occurredAt（真实发生）和 time（写入时刻）
   混用会让所有按时间排序/衰减的逻辑失真
```

## 7.3 工程经验

```
9. 本地调试必须绕过代理（HTTP_PROXY 会把 127.0.0.1 转走，502 是代理给的）
   判断服务死活要用裸 socket connect，别信 HTTP 状态码

10. 重启类操作必须先确认有守护
    run-bridge.bat 无自愈循环 → process.exit 之后就真没了
    start.bat 有 5 秒 :loop → 才是"重启"该有的样子

11. 改代码前备份 + node --check，改完立刻验证
    40 个备份救过很多次

12. 鉴权只做一层就够，但一层都不能少
    /api/memory/admin 曾同时用 Bearer 和 x-console-token 两套写法，
    结果控制台按钮一律 403 —— 全局中间件校验过的端点别再验第二种头
```

## 7.4 协作经验（给 AI 的）

```
13. 报告里要区分【已确认】【推断】【无法确认】
    这次审计有 3 处无法确认，如实标出来比假装确定更有用

14. 结论要能追溯到文件:行号
    "A 层无鉴权"必须能指到 mcp-snowluma-safe.js:996，否则无法复核

15. 发现自己上一份报告错了，要显式纠正
    比如"群聊只有 #101 可查"→ 实际是"一条都查不到"，这种修正必须写明
```

# 八、挫折与坑

## 8.1 环境类（换机器还会遇到）

| 坑 | 现象 | 解法 |
|---|---|---|
| VBScript 含中文 | 报"未结束的字符串常量" | 全文纯 ASCII |
| ws.Exec 轮询 | 闪黑框 | `Run "cmd /c ... > 临时文件", 0, True` 再读文件 |
| 停止脚本误杀 | 把用户自己的 QQ.exe 杀了 | 只杀 node，不碰 QQ 进程 |
| 工具起的进程随命令结束被杀 | 服务起来 3 分钟就没了 | 必须用户双击 vbs / 或用 start.bat |
| Bash PATH 为空 | ls/mkdir 全 command not found | 一律用 Python 绝对路径 |
| 本地请求走代理 | 502 Bad Gateway | `ProxyHandler({})` 绕过 |

## 8.2 架构类（设计层面的教训）

| 坑 | 本质 | 教训 |
|---|---|---|
| private_companion 主动联系修不通 | 五重校验 + 写死 role hash，防篡改设计 | **别绕过界面改配置文件**；这类插件要么全新装、要么别碰 |
| 人格不生效 | preset 3 处身份锚点压过人格卡 | 新建人格先清身份声明 |
| 错误被审计层隐藏 | "含敏感信息，已隐藏" | 看 bridge.log / prompt-dump.log 原始日志 |
| 群记忆失效 | key 与 approved 双闸门同时收紧 | 权限设计要想清楚"群内产生的记忆归谁" |

## 8.3 认知类（这次记忆系统踩的 8 个坑）

```
坑1  她只翻到"当天那一页"      → 能力在，说明书没写（带 topic 才查 A 层）
坑2  分享永远"找不到那条"      → 没先查、凭印象编句子
```
