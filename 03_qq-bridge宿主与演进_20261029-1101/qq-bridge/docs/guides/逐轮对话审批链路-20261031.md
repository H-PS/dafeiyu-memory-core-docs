# 第一幕｜选型与调研（10-25 ~ 10-26）

## 轮次 0｜起点：怎么把 DSH 接进 QQ
- **目标**：让 DeepSeek Harness（DSH）里的 agent 能收发 QQ 消息
- **结果**：✅ 摸清三件事 —— DSH 桌面版被 Electron 独占、官方插件 `@tencent-connect/dsh-qqbot` 只能扫码、克隆了 `Derpyu520/qq-bridge`（走 SnowLuma OneBot → 桥接 → DSH web API）
- **关键发现**：本机只有 `deepseek-account` OAuth，没有 `sk-` API Key，任何默认写 `deepseek-official` 的都要改
- **审批**：✅ 信息调研完成，无决策阻塞

## 轮次 1｜算账：这样玩多少钱
- **目标**：搞清楚 token 成本和电费
- **结果**：✅ 单次调用 ¥0.008~0.016；一天 ¥0.3~¥5；**电费 ¥1.5~3/天，比 token 还贵**
- **审批**：✅ 成本可接受，继续

## 轮次 2｜调研 AstrBot（用户说的 "artbot"）
- **目标**：评估另一条路 —— AstrBot 独立 IM 框架
- **结果**：✅ 结论是 AstrBot「既有官方通道合规性、又能主动消息」，是当时最均衡的方案
- **审批**：✅ 决定转 AstrBot

## 轮次 3｜实际部署 AstrBot
- **目标**：把 AstrBot 装起来跑通
- **结果**：⚠ `uv` 安装失败（jieba 构建被 safe-delete 门禁拦）→ 改用官方 Windows 便携包（177.7MB）装成功
- **审批**：✅ 部署完成

## 轮次 4｜自建"WorkBuddy 当群友大脑"读取通道
- **目标**：绕开 AstrBot 只有发、没有读的缺陷，让 WorkBuddy 定时读消息、判断接话、再发回
- **结果**：❌ **失败**。automation 的 rrule 不支持分钟级（最小 1 小时），做不到"秒回"
- **审批**：🔒 此路放弃

## 轮次 5｜WorkBuddy CLI 自我唤醒（大转弯）
- **目标**：用 WorkBuddy 自带的非交互 CLI `codebuddy -p` 做大脑，写守护进程 8 秒轮询
- **结果**：❌ **失败**。三条认证路径全堵死 —— 中国版个人账号拿不到 API Key、`~/.codebuddy` 无凭据、TUI 未登录状态下不渲染登录界面
- **审批**：🔒 此路放弃

## 轮次 6｜正解：WorkBuddy 桌面端内置「QQ 机器人」远程通道
- **目标**：找官方能力，不再外部折腾
- **结果**：✅ **接通**。左下角 → 设置 → 远程通道 → QQ 机器人 → 扫码。`QQBot-018135`，backendMode=local
- **关键教训**：「先看产品自己的设置页，再外部折腾」。前面 AstrBot / qq-bridge / CLI 两小时全是可以跳过的
- **审批**：✅ 接通，但发现两个限制（见轮次 7）

## 轮次 7｜发现 QQ 通道的致命限制
- **目标**：验证这条通道的实际能力
- **结果**：⚠ 两个问题 —— ① QQ 通道复用同一个长期会话（session `1fb4bd39`，10-09 创建），**改记忆不生效**（会话启动时注入 MEMORY.md，老会话读不到新内容）② 该通道本质依赖本机 WorkBuddy 在线，不接就是空壳
- **审批**：❓ **这条通道最终没走通"主动联系"，为第二幕的大迁移埋下伏笔**

# 第二幕｜大迁移：AstrBot → DSH + qq-bridge（10-29 ~ 10-30）

## 轮次 8｜private_companion 插件时代
- **目标**：在 AstrBot 上装 private_companion v7.0.20，做「主动联系」
- **结果**：⚠ 私聊/群聊 @ 能回、安全拦截有效，但**主动联系修不通**
- **审批**：❓ 卡在第 5 步向导

## 轮次 9｜主动联系彻底修不通（8 种改法全失败）
- **目标**：绕过界面直接改配置，让主动联系生效
- **结果**：❌ **失败**。private_companion 的主动联系依赖**五重校验**，且 role hash 写死在 `conversation_id` 里（防篡改设计）。试了 8 种改法全撞墙
- **关键结论**：这个插件设计前提是「所有配置通过界面完成」，绕过界面改文件必失败
- **审批**：🔒 放弃 AstrBot 路线

## 轮次 10｜大迁移：DSH + qq-bridge 全链路打通
- **目标**：换到可控的底座
- **结果**：✅ **全链路通**：SnowLuma → qq-bridge → DSH → DeepSeek
- **关键突破**（都进了部署记录）：
  1. provider 必须是 `deepseek-account`（写错报错被审计层隐藏）
  2. 人格**全文注入**（原来只给一句"调工具查看"）
  3. preset 里 3 处身份锚点压过人格，全删
  4. 人格卡标题不能带名字
  5. VBScript 必须纯 ASCII
- **审批**：✅ **这是项目真正的转折点，从"能不能"进入"怎么做好"**
