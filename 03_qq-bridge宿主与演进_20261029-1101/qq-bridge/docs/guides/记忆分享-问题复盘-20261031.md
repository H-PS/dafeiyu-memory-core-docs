# 记忆分享功能 —— 问题复盘（2026-10-31 凌晨）

> 从「她查不到历史」到「群里能共享一条记忆」，整条链路踩了 8 个坑。
> 每个坑都记：**现象 → 根因 → 修复 → 教训**。下次改记忆相关的东西先读这份。

---

## 链路全景（先搞清有几套存储）

```
┌─ B 层：SocialV2 轻量记忆（state/social-v2.json，按会话 key 存）
│    activeTopics / pendingThoughts / memberImpressions
│    ← qq_memory_append 写入，随唤醒提示注入
│    ← 她嘴里的「小本子」「本子上那一行」就是这里
│
└─ A 层：向量记忆库（state/memory-vectors.jsonl，102+ 条）
     ← 历史对话切块向量化后写入，语义检索
     ← qq_memory_query 带 topic 才查这里（不带 topic 只返回 B 层）
     ← 分享申请的审批状态字段也挂在这一层
```

**两套存储、两套检索路径，混着用就会「她说的和库里对不上」。**

## 坑 1：她查不到历史对话 ——「只能翻到当天那一页」

| | |
|---|---|
| **现象** | 她说「小本子摸到了，就是只能翻到当天那一页」「就你那几条印象」，永远不会回忆更早的对话 |
| **根因** | `qq_memory_query` 的**语义检索要靠 `topic` 参数触发**（查 A 层）；但工具 description 和 preset 协议里**从没写过这一点**，她调用时自然不带 topic，只拿到 B 层那几条印象。**能力一直在，说明书缺两行** |
| **修复** | ① `src/mcp-snowluma-safe.js` 里 `qq_memory_query` 的 description 补明「带 topic 会检索长期记忆库」② `dsh/agent-presets/qq-chat-v2/agent.cordis.yml` 第 8 条补「回忆更早的对话必须带 topic」，并重建 patch |
| **教训** | **工具能力没写进 description = 模型不会用。** 加参数就要同步改说明书，还要检查 preset 协议是否复述了旧用法 |

---

## 坑 2：申请分享永远「找不到那条」

| | |
|---|---|
| **现象** | 她 `qq_memory_share_request` 一直返回「找不到那条」 |
| **根因（第一层）** | 她**没先查**就凭印象编了一句「之前在群里的那次谈话」，库里没有这句 → 三级匹配再强也兜不住凭空编造 |
| **修复** | 引导语：**先 `qq_memory_query` 查原文，再拿原文去申请，别凭印象编** |
| **根因（第二层）** | key 可能错位：在私聊（`private:xxx`）申请，想分享的却是群里的记忆（`group:xxx`）→ key 过滤后必然找不到 |
| **教训** | 「找不到」有两种：**内容不存在** 和 **key 不对**。排查时先确认是哪一种，别急着改匹配算法 |

---

## 坑 3：B 层有、A 层没有

| | |
|---|---|
| **现象** | 她说「本子上就一行」，但拿那行去申请，向量库里查无此条 |
| **根因** | 那条印象是**只存在于 B 层**（social-v2.json 的 memberImpression），从未被向量化进 A 层。B→A 没有桥 |
| **修复** | 手工把该条同步进 A 层；正常链路 `qq_memory_append` 记印象时本来就会同时写 A 层，只有历史遗留条目缺 |
| **教训** | 任何「跨存储」的功能，先问一句：**这个对象在另一层有对应记录吗？** 没有就得补桥，否则所有匹配逻辑都是白费 |

---

## 坑 4：我同步时「润色」了原文 —— 差三个字全废

| | |
|---|---|
| **现象** | 同步进 A 层后，用她的原话申请仍然失败 |
| **根因** | 我写的是「…**是**电脑的主人…**她**给他起了个称呼…**定了**叫网管」，她记的是「…**，**电脑的主人…**让我**给他起个称呼…**我定了**叫网管」。双向包含要求逐字一致，**差一个字就废** |
| **修复** | 删掉我加的前缀、改回**逐字原文** |
| **教训** | **同步数据永远不做「润色」。** 哪怕是补个前缀、把「，」改成「是」，都会让逐字匹配失效。要加工就另存，别覆盖原句 |

---

## 坑 5：复述时漏 QQ 号 / 标点 → 归一化后不连续

| | |
|---|---|
| **现象** | 她复述「[真实姓名]，电脑的主人，嫌叫全名伤人…」能问到痛点，但匹配不上 |
| **根因** | 原文含 `（[OWNER_QQ]）`，她复述时省了 → 去标点后字符串中间多出一段原文没有、复述也没有的区域，包含关系断裂 |
| **修复** | `src/memory-vector.js` 的 `findMemoryRow` 加**第 4 级匹配**：先剥掉 `activeTopic:/pendingThought:/memberImpression:` 前缀，再删掉标点、空格、括号、引号**和数字**，最后做双向包含 |
| **教训** | 用户复述天然会丢**数字、括号、标点**。归一化必须把这些一起剥掉，只留语义骨架 |

**现在的匹配等级（`findMemoryRow`）：**

```
1 逐字全等
2 双向包含（原文含复述 / 复述含原文）
3 剥前缀后双向包含
4 归一化（去前缀+标点+空格+括号+引号+数字）后包含
```

## 坑 6：控制台根本没有「同意」的按钮

| | |
|---|---|
| **现象** | 用户问「我在哪里同意」，翻遍控制台找不到入口 |
| **根因** | 后端 `approve_share` / `reject_share` 早写好了，**`public/console.html` 里从来没做对应 UI**（全文件搜 share 只命中一个无关的 `usageBar(share)`） |
| **修复** | 在 `section-social-v2` 后面新增 `#section-memory-share` 卡片：列出 pending 条目（key / 分类 / 申请时间 / 原文），带「批准并共享到群」「拒绝」按钮；`setConsolePage` 进二代仿真页时自动 `msLoad()` |
| **教训** | **后端接口做完 ≠ 功能可用。** 交付前要问：这个操作的入口在哪个界面、点了会发生什么 |

## 坑 7：控制台点了也 403 —— 鉴权头对不上

| | |
|---|---|
| **现象** | 补了 UI 后，页面请求 `/api/memory/admin` 全部 403 |
| **根因** | 该端点自己又校验了一遍 `req.headers.authorization === 'Bearer <token>'`，而**控制台页面从来只发 `x-console-token`**（全局中间件认这个头，端点里却认另一个）→ 双重鉴权用了两套写法 |
| **修复** | `src/bridge.js`：`viaBearer` 与 `viaConsoleHeader` 二者其一即可；同时**显式拒绝带 `x-agent-token` 的请求**，防止智能体借会话令牌升级成管理端全权（confused deputy） |
| **教训** | 全局中间件已经鉴权过的端点，**不要再用另一种头重复校验**。要兼容就给两条路径，别二选一 |

## 坑 8：重启之后服务起不来

| | |
|---|---|
| **现象** | `/api/restart` 返回 200，但 3100 端口一直不通，`urllib` 还报 502 |
| **根因（两层）** | ① 这个环境里 **`HTTP_PROXY` 指向 127.0.0.1:9889**，本地请求被代理转发 → 502 是代理给的，不是桥给的（用 `ProxyHandler({})` 绕过）② 用 `启动大肥鱼.vbs` 拉起时 **`run-bridge.bat` 里的 `npm start` 没有重启循环**，`process.exit` 后就真没了 |
| **修复** | 判断「服务死了没」要用**裸 socket connect**，别信 HTTP 状态码；恢复服务用 `start.bat`（内含 5 秒自动重启 `:loop`）而不是 `run-bridge.bat` |
| **教训** | **本地调试永远绕过代理**；**重启类操作必须确认有守护**，否则「重启」等于「关机」 |

不是桥的 bug —— 模型侧生成工具参数时 JSON 转义崩了，触发条件是**记忆原文里有英文双引号**（`我定了叫"网管"`）。
