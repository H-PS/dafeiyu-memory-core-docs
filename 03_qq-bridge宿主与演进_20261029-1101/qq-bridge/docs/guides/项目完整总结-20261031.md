# 一、项目是什么（一句话 + 一图）

**一只住在电脑里的猫（大肥鱼），通过 QQ 群/私聊跟你聊天。不是助手，是"像活着"的陪伴。**

```
SnowLuma(OneBot v11, 3001)  ← 登录机器人号，收发 QQ
        ↓
qq-bridge(3100)              ← 会话管理 / 社交仿真 / 主动搭话 / 记忆 / 控制台
        ↓
DSH web(3080)                ← Agent 底座，preset qq-chat-v2
        ↓
DeepSeek(deepseek-account/flash)  ← 大脑
```

**人格稳定性靠三层**：人格卡（她是谁）+ preset（行为协议）+ 记忆（连续性）。

# 三、成功案例（✅ 做得对，值得复用）

## 3.1 选型：最后靠"看产品内置能力"省了两小时

**场景**：折腾 AstrBot / qq-bridge / CLI 两小时，最后发现 WorkBuddy 桌面端自带「QQ 机器人」远程通道。

**成功点**：
- 没有继续死磕外部方案，而是回头查了产品自己的设置页
- 从 app.asar 里实证了 QQBot 能力存在（97 处），才去操作

**可复用**：**先看产品自带能力，再外部折腾。** 任何"接入"类需求，第一件事是搜一遍目标产品有没有现成通道。

## 3.2 大迁移：provider 一改就通，靠"查真实数据源"

**场景**：写 `deepseek-official` 报 `session/model-unavailable`，错误还被审计层隐藏成"含敏感信息"。

**成功点**：
- 没有凭经验猜，而是去 `~/.dsh/storages/session_projcache/sessions/*.json` 里查 `lastUsed` 字段
- 拿到真实 provider 值 `deepseek-account`，一次改对

**可复用**：**报错被吞/隐藏时，去查数据源的真实值，别猜。** 错误信息不可信时，原始数据最可信。

## 3.3 人格生效：全文注入 + 删身份锚点

**场景**：人格怎么改都不生效，模型还是"AI 助手"味。

**成功点**（三个连环动作）：
1. 人格**全文注入**（原来只给一句"调工具查看"，模型不调就看不到）
2. 删掉 preset 里 3 处身份锚点（"coding agent""DeepSeek 鲸鱼""Q 版小鲸鱼"）
3. 人格卡标题去掉名字（"# 角色卡：大肥鱼"会让她联想成"鱼"）

**可复用**：**人格不生效，先查三处**——注入是否全文、有没有身份锚点压过、标题有没有暗示。

## 3.4 记忆检索"通"起来：说明书补两行

**场景**：她永远只记得"当天那一页"，怎么都回忆不起更早的对话。

**成功点**：根因不是代码没接上，而是 **`qq_memory_query` 带 topic 才查 A 层，但工具的 description 和 preset 协议里从没写过**。补了两处文案，检索就通了。

**可复用**：**能力没写进 description = 模型不会用。** 加参数就同步改说明书，还要检查 preset 有没有复述旧用法。

## 3.5 匹配抗改写：第 4 级归一化

**场景**：她复述记忆时漏了 QQ 号/标点，就"找不到那条"。

**成功点**：匹配从 3 级加到 4 级，最后一级把标点、空格、括号、引号、**数字**全剥掉只比语义骨架。

**可复用**：**用户复述天然丢数字/括号/标点，归一化必须把这些一起剥掉。**

# 四、挫折与失败（❌ 明确不该再踩）

## 4.1 完全失败的路线（🔒 已封存）

| 路线 | 为什么失败 | 教训 |
|---|---|---|
| WorkBuddy 定时读消息当大脑 | automation rrule 不支持分钟级（最小 1 小时），做不到秒回 | **先确认调度粒度，再设计轮询方案** |
| WorkBuddy CLI 自我唤醒 | 三条认证路径全堵死（中国版拿不到 API Key / 无凭据 / TUI 不渲染登录） | **认证是硬门槛，先验证再投入** |
| AstrBot private_companion 主动联系 | 五重校验 + role hash 写死，绕过界面改配置必失败 | **别绕过界面改防篡改设计**；要么全新装，要么别碰 |

## 4.2 环境类坑（换机器还会遇到，务必记牢）

| 坑 | 现象 | 解法 |
|---|---|---|
| VBScript 含中文 | 报"未结束的字符串常量" | 全文纯 ASCII |
| ws.Exec 轮询 | 闪黑框 | `Run "cmd /c ... > 文件", 0, True` 再读 |
| 停止脚本误杀 | 杀掉用户自己的 QQ.exe | 只杀 node，不碰 QQ 进程 |
| 工具起的进程随命令结束被杀 | 服务起来 3 分钟就没了 | 必须用户双击 vbs / 用 start.bat |
| Bash PATH 为空 | ls/mkdir 全 command not found | 一律用 Python 绝对路径 |
| 本地请求走代理 | 502 Bad Gateway | `ProxyHandler({})` 绕过 |
| 错误被审计层隐藏 | "含敏感信息，已隐藏" | 看 bridge.log / prompt-dump.log 原始日志 |

## 4.3 架构类教训（设计层面的反思）

| 教训 | 本质 |
|---|---|
| 权限语义没想清楚就上线 | visibility + approved 双闸门同时收紧，群记忆一条查不到 |
| 双写路径没对齐 | 逐句切块 + 归纳成印象，同一句话存两遍 |
| 时间字段混用 | time 记写入时刻，真实时间写进文本前缀，时间线不可信 |
| needs_review 造了却没接 | 字段加进去，但从不参与检索，成了噪声 |

## 4.4 记忆系统 8 个坑（本次最密集的踩坑区）

```
坑1  她只翻到"当天那一页"      → 能力在，说明书没写（带 topic 才查 A 层）
坑2  分享永远"找不到那条"      → 没先查、凭印象编句子
坑3  "本子上就一行"            → B 层 ≠ A 层，没有桥
坑4  同步时润色原文            → 差三个字，逐字匹配全废
坑5  复述漏 QQ 号              → 归一化后不连续 → 需要第 4 级匹配
坑6  控制台没有"同意"按钮      → 后端做了，前端没做
坑7  补了按钮还是 403          → 两套鉴权写法打架
坑8  重启后服务起不来          → 无守护 + 代理误导判断
```

# 五、可复用的经验原则（抽象成规则）

## 5.1 给架构设计的

```
1. 三层分工要清晰：人格（她是谁）/ 记忆（她记得什么）/ 仿真协议（她怎么做）
   混在一起就会出现"人格被协议压过"

2. 鉴权只做一层就够，但一层都不能少
   /api/memory/admin 曾用两套鉴权写法，结果控制台按钮全 403

3. 时间字段要分两种：occurredAt（真实发生）和 time（写入时刻）
   混用让所有按时间排序/衰减的逻辑失真

4. 权限设计要先想清楚"数据归谁"，再想"怎么存"
   群记忆失效的根因是"群内产生的记忆归谁"这个前置问题没定
```

## 5.2 给数据处理的

```
5. 同步数据永远不做"润色"
   差三个字（是/，、她/让我、定了/我定了）就让逐字匹配全废

6. 两套存储之间要有桥
   B 层印象 ≠ A 层向量，没有同步机制时必然脱节

7. 去重要在写入时做，不要事后清理
   三条写入路径（运行/手工/回填）各行其是，就是因为写入时没查重
```

## 5.3 给工程实践的

```
8. 改代码前备份 + node --check，改完立刻验证
   40 个备份救过很多次

9. 本地调试必须绕过代理
   HTTP_PROXY 会把 127.0.0.1 转走，502 是代理给的，不是桥死的

10. 重启类操作必须先确认有守护
    run-bridge.bat 无自愈循环 → process.exit 之后就真没了
```

## 5.4 给 AI 协作的（写报告/审计用）

```
11. 报告里区分【已确认】【推断】【无法确认】
    这次审计有 3 处无法确认，如实标出来比假装确定更有用

12. 结论要能追溯到文件:行号
    "A 层无鉴权"必须能指到 mcp-snowluma-safe.js:996

13. 发现自己上一份报告错了，要显式纠正
    "群聊只有 #101 可查" → 实际是"一条都查不到"，这种修正必须写明
```
