# 五、A/B 同步能力及明确限制

## 已实现

```
append：B 改内存 → A 写 → B strict 落盘 → 失败回滚 B 快照
        部分成功如实报告（partial:true + aSynced/bSynced 三态）
remove（activeTopic/pendingThought）：
        先算 bRemoved → A 删 ≤ bRemoved → B 删 → strict → 回滚
        数量对齐，A 删不超 B 删
clear（全量）：A 清整 key → B 清三字段 → strict → 回滚
```

## 明确限制（诚实声明）

```
1. 非原子：A/B 是两个独立文件，无法单次系统调用同时写。
   只保证「尽力同步 + 失败可发现」，不保证最终一致。
2. remove memberImpression：A 层无法通过 target 精确定位（text=memberImpression:<content>，
   content≠target），只删 B 层，A 层残留，返回 aSynced:'n/a' + partial:true。
3. clear 分类清理：A 层只支持按 key 整体清理，分类清理跳过 A 层，返回 aSynced:'n/a'。
4. append A 失败：无自动重试，再次调用会重复写 B 层（B 层无查重）。
5. edit 同步：本轮不实现（B 层 memory-update 与 A 层 admin edit 互相独立）。
```

# 六、鉴权边界和分享申请行为

```
鉴权边界：
  A 层所有 HTTP 入口（memory-vector / memory-share-request）都执行三重校验：
  agentTokenOk(key, token) → v2SessionAllowed(key) → v2ToolEnabled('memory')
  私聊 key 无法被其他 session 查询（agentTokenOk 校验 key↔token 绑定）

分享申请：
  private key → 明确拒绝（400「私聊记忆不支持共享到群」）
  group key → 只提交 pending，审批仍在 /api/memory/admin（管理员手动 approve）
  不支持 private → group 共享（本轮明确语义）
```
