## 二、值得搬的点（按价值排序）

### ⭐1 语言风格量化

他的统计输出：
```
一句话中位数 7 个字、超短句 7.4%、指令动作 6.3%
句尾高频：了/吧/到/的/吧
高频词：不是×22、要求×18、一个×18、这样×16
按群分类：每个群单独统计风格
```

我们的人格卡只有「一句话尽量不超过 40 字」—— 模糊。
他的方案给了模型可执行的数字。**flash 吃精确数字，不吃模糊形容词。**

做法：把量化数据写进人格卡，或定期从聊天记录统计后自动更新。

### ⭐2 聊天记录 SQLite 全量入库

```
聊天记录 → SQLite（qq-history.db）
群语学   → 从 2826 条里学说话方式（qq_style_learn）
黑话库   → 多次出现才提交核选（抗噪声设计）
```

qq-bridge 现状：recentMessages 滚动 100 条（会丢）、token-usage.jsonl。
**长期记忆的地基就是全量入库 + 可检索。**

### ⭐3 本地多模态（Qwen2.5-VL 7B 走 Ollama）

```
Ollama 11434 跑 Qwen2.5-VL 7B → 看图走本地
faster-whisper → 语音转写本地
嗓音克隆 → 说话
```

修正之前的判断：本地识图是跑得通的（他跑通了）。
价值：看图不花 API 钱、语音能力白得。
前提：有独显或接受 CPU 慢速。

### 4 权限分级 + 一键熔断

```
*锁死遥控   一键熔断（解释只能在电脑前手动解除）
*开文件权限 临时开 PC 文件挂载权限
*跑 <命令>  在本机执行 PowerShell
```

比我们的"停止 vbs"粒度细。可以给控制台加"紧急静默"按钮。

### 5 memory 分层

```
memory = SOUL / 规则 / 项目 / 经验
```

人格复杂了之后照这个分层，比单文件好维护。

### 6 任务收尾自动清理

"临时脚本和中间文件都清了，工作区只剩 README.md 和 划过的.md"
—— agent 跑完任务自己清理，写进人格或 preset 即可。

### 7 风格按群分

不同群不同说话方式（他有按群统计）。
qq-bridge 的 slang 机制是雏形，但没做到按群切换风格。

## 三、记忆向量化调研

**「把记忆变成向量」的出处：AstrBot 4.29.3 自带，路径：**

```
D:\[ASTRBOT]\app\...\astrbot\core\db\vec_db\faiss_impl\vec_db.py
  class FaissVecDB            FAISS 向量库
  embedding_provider          文字 → 向量
  rerank_provider             检索重排
astrbot/core/knowledge_base/  知识库管理（kb_mgr.py）
```

这是 AstrBot webui 里"知识库/长期记忆"的底层。**qq-bridge 没有**（搜过，
只有 dsh-skill 的 MCP 协议文档里提了 vector 一词，与记忆无关）。

### 向量记忆原理（30 秒版）

```
存：每条记忆 → embedding 模型 → 一串数字（向量）→ 入库
查：当前话题 → 也转成向量 → 找"距离最近"的 K 条记忆 → 注入 prompt
```

比"最近 100 条滚动"强在：**按语义相关性找，不按时间先后**。
三个月前一句"我讨厌香菜"，在你提到吃饭时也能被捞出来。

### 给大肥鱼做的三条路

```
A. 搬 AstrBot 的 faiss 模块   不可行（那是 Python，qq-bridge 是 Node）
B. DeepSeek/硅基流动 embedding API + Node 端简易向量库
   可行，中等工作量：memory_append 时顺手算 embedding 存 JSON/SQLite，
   qq_memory_query 改成向量检索。embedding 很便宜（百万 token 几毛钱）
C. 现成的 MCP memory server（带向量检索的开源实现）接进 DSH
   最省事，但要挑一个质量靠谱的
```

建议：先跑稳当前版本，向量记忆做成 qq-memory 的升级版，一次到位。
